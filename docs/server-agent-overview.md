# Краткие проблемы агентов на главной странице

Пакет рабочей ветки `feature/local-backup-agent`, исходник `dffb31f`.
Доработка опубликована в [Server preview.11](server-preview11-publication.md);
preview.10 её не содержит.

## Поведение

В строке агента рядом со связью показаны число причин, две приоритетные
категории и время последнего полученного отчёта. Ссылка открывает существующий
раздел «Проблемы» с фильтром по ID агента. Фильтр сохраняется при поиске,
смене категории и переходе между страницами; его можно снять явно.
Из строки проблемы задания можно перейти к нему в карточке агента.

Число означает причины, а не задания: одно задание может давать несколько
причин. Счётчик включает результаты за пределами первой страницы проблем.
Общий SQL-запрос используется списком и сводкой; сводка ограничена агентами
текущей страницы (до 50), а не запрашивает все проблемы по одному агенту.
Фильтр папки и подпапок продолжает работать.

Отсутствие связи, ошибка и частичная доставка показаны раздельно. Восстановление
связи не очищает прежнюю частичную доставку; нужен новый успешный результат
копирования. Отозванный агент не отслеживается, отсутствие первого отчёта явно
обозначено. «По отчёту проблем не найдено» не доказывает восстановимость копии.
Время отображается в установленном серверном часовом поясе.

На ширине до 1100 дерево папок располагается над таблицей. При 900×580 все
колонки помещаются без горизонтальной прокрутки; на телефоне широкая таблица
имеет собственную прокрутку. Весь документ не выходит за ширину окна.

## Проверки

Три новых интеграционных теста используют отдельную схему настоящей PostgreSQL
и HTTPS: более 50 причин, изоляция агента, отозванные/неотчитавшиеся агенты,
перезапуск, недопустимые ID/доступ и восстановление связи без ложного успеха.

Браузерный сценарий `tests/server/agent_overview_browser.py` запускается из
`AgentProblemSummaryTests` при заданной `ONECBACKUP_OVERVIEW_BROWSER_OUTPUT`.
Работает только с loopback-стендом; пароль передаётся закрытым файлом. Настоящие
вход/формы/маршруты, PostgreSQL и сервер; данные тестовые. Пройдены 8 браузерных
проверок: одновременные Offline/Partial/время отчёта, обе темы при 1366, 900×580
и 360, клавиатурный переход, пагинация и якорь задания. Просмотрены снимки
светлой и тёмной тем, тесная компоновка 900 исправлена и перепроверена.
Артефакты: `artifacts/agent-overview-browser/` (6 PNG и `result.json`).

Windows и Linux проверяются отдельно режимом workflow `scope=integration`:
интеграции и собранный пакет. Этот режим не повторяет неизменённые установку,
снимок и возврат, принятые при публикации preview.10; теговый выпуск по-прежнему
требует полный профиль. Новый релиз и приёмка на пользовательском CT не заявляются.

Первый Windows-прогон [43678441576](https://github.com/sanekman/1C-Backup/actions/runs/43678441576)
нашёл четыре устаревших ожидания тестов: прежнюю общую категорию Failed для
PartiallySucceeded и три точных HTML-шаблона `<tr><td>` без нового атрибута-якоря.
На `688a791` ожидание заменено на Partial, шаблоны разрешают атрибуты строки;
проверки содержимого, принадлежности отчёта агенту/заданию и истории сохранены.
Производственный код после `dffb31f` не менялся.

Повторный [Windows-прогон 43678709503](https://github.com/sanekman/1C-Backup/actions/runs/43678709503)
на `688a791` завершён успешно: 178/181, ровно три предусмотренных Linux-only
пропуска Unix-сокета; пакет 1/1, Python 57 тестов с платформенными пропусками.
Строгий валидатор проверил именно 181 результат и имена трёх пропусков.

После Windows [Linux-прогон 43678946861](https://github.com/sanekman/1C-Backup/actions/runs/43678946861)
на том же `688a791` завершён успешно: 181/181 без пропусков, пакет 1/1,
Python 57/57, Compose-проверка успешна. Проверки выполнены 15 ноября 2026 года.
Оба workflow завершились успешно; профильные логи и результаты строгого
валидатора прочитаны. Браузерный результат локальный и не подменяет CI.

Итог: реализация и стендовая приёмка завершены. Схема БД и агентский протокол
не менялись; последующая публикация preview.11 принята в отдельном отчёте. Проверка новой
главной страницы на CT 107 остаётся отдельной. Установка кнопкой принята
в [отчёте CT 107](server-update-umask-fix.md).
