# Проверка настоящей платформы 1С на Windows

Сценарий tools/test_windows_onec.ps1 предназначен для пунктов 4.1–4.2 дорожной карты. Он использует установленную платформу и установленный SP Backup, не требует SDK и не меняет задания или службу программы. Версия агента записывается в отчёт: результат относится именно к ней.

## Перед запуском

1. Выберите тестовую файловую базу. Закройте её у всех пользователей. Исходный 1Cv8.1CD читается с эксклюзивным доступом только для создания отдельной рабочей копии.
2. Убедитесь, что платформа установлена и доступна её лицензия. Для ZIP-проверок вход в открываемую тестовую базу выполняется в локальном окне 1С. Для автоматической DT-выгрузки базы с пользователями используйте -AskOneCLogin, как описано ниже. Пароли и ключи в чат не передаются.
3. Выберите диск для тестовых копий. Сценарий оставляет архивы и восстановленные базы: резервирует место примерно на 22 размера исходного файла плюс 2 ГиБ. Другой диск задаётся через параметр -WorkParent.
4. Сохраните скрипт. Откройте Windows PowerShell от администратора под тем же пользователем, у которого работает 1С. Это нужно для отдельной временной SMB-папки; существующие сетевые папки и брандмауэр не меняются. Папка разрешена только текущему пользователю и удаляется по завершении проверки.

Пример для тестовой базы:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\test_windows_onec.ps1" -SourcePath 'C:\Bases\Demo' -PlatformVersion '8.5.1.1150'

Если программы находятся в другом каталоге, добавьте параметры -PlatformExecutable и/или -AgentExecutable с полными путями к 1cv8.exe и SPBackup.Agent.exe. Проверяется точная версия платформы.

Если на диске с профилем Windows не хватает места, выберите другой локальный диск и добавьте в конец команды, например:

    -WorkParent 'D:\SPBackup-Tests'

Исходная база остаётся на прежнем месте. На выбранном диске появится отдельный каталог onec-<GUID> для тестов. Скрипт показывает требуемое и доступное место до чтения базы. При отказе в отчёте будут этап disk-space, код InsufficientDiskSpace и размеры в байтах; копирование ещё не начиналось. Не нужно удалять рабочие резервные копии ради этого теста.

## Во время проверки

Все запуски 1С и восстановления используют новые каталоги внутри %LOCALAPPDATA%\SPBackup-Tests\onec-<GUID> или выбранного -WorkParent. Исходная база не открывается платформой и не перезаписывается. Для агента создаются отдельные профили с ручными заданиями.

Сценарий проверяет:

- ZIP закрытой базы с выключенным и включённым разрешением открытой базы: восстановленные байты должны совпасть; предупреждения об открытом сеансе быть не должно.
- Настоящий открытый сеанс: без разрешения копия отклоняется; с разрешением создаётся с предупреждением. ZIP не объявляется проверкой согласованности открытой базы.
- Повторное копирование после закрытия сеанса: предупреждение исчезает.
- Те же сценарии через собственную временную UNC-папку. Это проверка SMB текущего компьютера, не доменного сервера или физического NAS.
- Настоящую выгрузку DT агентом и восстановление платформой в ещё одну отдельную тестовую базу. Документы и справочники подтверждает пользователь; этот результат отделён от автоматического сравнения ZIP.
- Отмену выгрузки, когда обнаружен настоящий процесс платформы, созданный тестовым агентом. Проверяются итог отмены, отсутствие зарегистрированной копии, завершение процесса и освобождение базы.

Окна 1С открываются последовательно. Читайте подсказку в PowerShell, дождитесь загрузки тестовой базы и нажмите Enter. Закрывайте только окно тестовой копии. В восстановленной DT проверьте данные и введите ДА, если они верны.

Если вместо данных появился список информационных баз, выберите тестовую базу с путём, который напечатал скрипт, и нажмите «1С:Предприятие». Дождитесь появления данных, завершив локальный вход при необходимости. Сам список баз не удерживает файл и не подтверждает открытый сеанс. Для UNC-проверки путь должен начинаться с двух обратных косых черт и имени компьютера, а не с буквы диска.

Если выгрузка завершилась до отправки отмены или UNC не проверен без прав администратора, соответствующий пункт остаётся not-exercised. Общий успех тогда не объявляется. Ошибка одного этапа также не превращается в успешную приёмку.

Если после открытия тестовой базы платформа не удерживает её файл, сценарий записывает open-session со статусом not-exercised. Закройте её окно или сообщение и нажмите Enter: после проверки освобождения файла сценарий продолжит независимую выгрузку DT. Такой пропуск не считается подтверждением работы с открытой базой и не даёт общего успеха.

## Продолжить только проверки выгрузки DT

Если ZIP-проверки уже выполнены, добавьте к исходной команде параметр -PlatformOnly. Будет создана новая отдельная копия исходной базы, затем выполнены выгрузка DT, восстановление, проверка данных пользователем и отмена. ZIP и временная UNC-папка повторно не создаются. Исходная база перед запуском должна быть закрыта.

В этом режиме в JSON указано scope: platform-only. Поле selectedChecksPassed показывает результат выбранных проверок; success остаётся false, поскольку режим не выполняет весь набор приёмки. Предыдущий отчёт сохраняет силу для записанных в нём проверок своей версии агента. Неподтверждённый открытый сеанс UNC остаётся отдельным незакрытым пунктом.

## Если база требует пользователя 1С и пароль

Для DT используется только пользователь информационной базы 1С, с отключённым входом Windows. Добавьте **-AskOneCLogin**: сценарий запросит данные прямо в PowerShell. Введите имя пользователя из списка входа 1С и нажмите Enter, затем введите пароль и снова нажмите Enter. Пароль вводится скрыто; отдельное окно учётных данных не открывается. Пользователю требуется право выгрузки. Имя учётной записи Windows, пароль службы или PIN-код здесь не подходят.

Нужна новая тестовая сборка агента с поддержкой входа ИБ. Опубликованная **alpha.34** её ещё не содержит. Задайте путь к SPBackup.Agent.exe из новой сборки через **-AgentExecutable**. До запроса пароля и чтения исходной базы сценарий проверяет поддержку: старый агент даст код **AgentInfobaseCredentialsUnsupported**. Не заменяйте исполняемый файл работающей службы отдельным файлом из другой сборки; распакуйте тестовую сборку целиком в отдельную папку.

Пример одной полной команды после получения новой сборки и сохранения нового скрипта:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\test_windows_onec.ps1" -SourcePath 'C:\Bases\Demo' -PlatformVersion '8.5.1.1150' -WorkParent 'E:\SPBackup-Tests' -AgentExecutable 'E:\SPBackup-Candidate\SPBackup.Agent.exe' -PlatformOnly -AskOneCLogin

Замените два примерных пути: к своей базе и к агенту новой сборки. Скопируйте команду целиком одной строкой. Если база не содержит пользователей, не добавляйте -AskOneCLogin.

Сценарий создаёт собственную временную запись Windows Vault, передаёт пароль помощнику агента через стандартный ввод и удаляет свою запись при завершении. Пароль не включается в JSON-отчёт, профиль задания или командную строку процесса. Для запуска 1С используется закрытый файл параметров, доступный текущему пользователю, SYSTEM и администраторам. Агент создаёт его вне папки архива и удаляет после завершения процесса, ошибки или отмены. Принудительное завершение всего процесса или выключение компьютера может оставить временный файл; не передавайте такие файлы и тестовые папки другим людям.

Параметры 1С записываются в UTF-8 с BOM: эта метка позволяет платформе правильно прочитать кириллицу и другие символы независимо от кодовой страницы Windows или процесса агента. Выгрузка, восстановление и запуск восстановленной базы используют один формат. Сохранение пароля и автоматические проверки передачи ещё не подтверждают настоящий вход в вашу платформу: для этого нужен новый результат DT, восстановления и проверки данных.

## Результат

В конце выводится путь к one-c-acceptance-result.json. Для разбора нужен только этот JSON. Базы, ZIP, DT, профили и платформенные журналы остаются в закрытой тестовой папке и могут содержать ваши данные; автоматически они никуда не отправляются.

Общий успех означает, что все записанные проверки прошли, включая подтверждение данных пользователем. Это проверка указанной версии агента от текущего пользователя Windows. Она не подтверждает права другой учётной записи службы, удалённый MS SQL или всю матрицу ОС.

После разбора результата тестовую папку можно удалить целиком. Рабочую базу, её регистрацию в списке 1С и обычный профиль SP Backup сценарий не изменяет.
