# Оповещения в Telegram и MAX

Откройте «Настройки → Оповещения: Telegram и MAX → Настроить оповещения». Каналы независимы: можно включить один или оба. По умолчанию выбраны ошибки и предупреждения. Успешные копии и отмену можно включить отдельно. Нажмите «Отправить тест», затем «Сохранить». Тест использует введённые данные и не включает оповещения автоматически.

## Telegram

1. Откройте официального бота **@BotFather**, выполните `/newbot` и сохраните выданный токен в поле «Токен бота».
2. Откройте созданного бота и нажмите **Start** или отправьте `/start`. Бот не может первым начать личную переписку.
3. Для группы добавьте бота в группу и отправьте в ней команду, например `/start@имя_вашего_бота`. Для канала назначьте боту право публиковать сообщения.
4. Получите числовой `chat_id` из `message.chat.id` или `channel_post.chat.id` ответа официального метода `getUpdates`: `https://api.telegram.org/bot<ТОКЕН>/getUpdates`. Подставьте свой токен локально. Не отправляйте эту ссылку другим людям: она содержит секрет. У группы ID обычно отрицательный. Если бот уже используется другой программой с webhook или получением обновлений, не меняйте её настройки; используйте отдельного бота для резервного копирования.
5. Вставьте ID в программу и отправьте тест. Здесь поддерживаются числовые ID, включая группы и каналы; `@username` вместо ID не используется.

Официальная документация: https://core.telegram.org/bots/tutorial и https://core.telegram.org/bots/api#getupdates.

## MAX

1. Создайте бота через платформу MAX для партнёров и получите токен согласно правилам платформы. Доступ к созданию ботов может требовать регистрации и проверки организации; программа не создаёт бота вместо владельца.
2. Для личного сообщения пользователь должен начать взаимодействие с ботом. Для чата или канала добавьте бота и предоставьте необходимые права.
3. Получите ID по официальной инструкции https://dev.max.ru/docs-api/use-cases/getting-chat-id или из обновлений вашего бота. Не указывайте телефон вместо ID.
4. Выберите «Пользователь (user_id)» для личного сообщения либо «Чат или канал (chat_id)», вставьте ID и токен, отправьте тест и сохраните настройки.

Используется официальный `POST https://platform-api2.max.ru/messages`. MAX указывает этот домен вместо `platform-api.max.ru` и рекомендует проверить доверие к сертификатам Минцифры. При ошибке TLS следуйте официальной документации MAX и требованиям администратора компьютера. Программа не отключает проверку сертификата.

Документация отправки: https://dev.max.ru/docs-api/methods/POST/messages.

## Работа оповещений

- Отправка выполняется отдельно от резервного копирования в открытом приложении, приложении в трее и фоновом агенте/службе. Для доставки должен работать хотя бы один из них. Результаты хранятся в истории; сообщения повторяются после восстановления связи.
- В сообщении: имя компьютера и задания, результат, начало и окончание по локальному времени, число предупреждений. Текст ошибок, источники, пути хранилищ и секреты не передаются. Подробности смотрите в истории программы.
- Настройки применяются без перезапуска. Включение канала, смена получателя или набора событий начинает отправку с новых результатов. Старые результаты до этого момента не рассылаются.
- После ошибки доставка в этот канал откладывается на минуту; другой канал продолжает работать. Ошибка оповещения не изменяет результат резервного копирования и не останавливает агент.
- Успешная доставка отмечается на диске. После обычного перезапуска повторной отправки нет. Если сервис принял сообщение, но соединение оборвалось до подтверждения, либо отметка доставки не записалась, при повторе возможно дублирование. Гарантия ровно одного сообщения без поддержки сервиса невозможна.
- Токены сохраняются отдельно от JSON в диспетчере учётных данных Windows. При работе службы используется существующий защищённый механизм передачи секретов службе. Пароли в поле не показываются: пустое поле сохраняет прежний токен. Токены не нужно присылать для анализа логов.
- Диагностика содержит события доставки и ошибок без текста сообщений, токенов и получателей. Очередь использует историю запусков: удаление записей истории до доставки отменит соответствующие оповещения.

Реальные сообщения с вашим ботом проверяются кнопкой «Отправить тест». Автоматические тесты разработчика используют модели ответов API и не отправляют сообщений в чужие аккаунты.
