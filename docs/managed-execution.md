# Серверные задания в Windows-агенте: состояние разработки

Публичные alpha.29 и server preview.4 предоставляют автономное копирование, мониторинг, API публикации файловых конфигураций и подтверждение их проверки/сохранения. Описанный ниже исполнитель добавлен после этих выпусков и ещё не опубликован.

## Что подключено

LocalAgentHost поддерживает отдельный Managed-режим с тем же единственным владельцем исполнителя, контролем остановки и отмены, ручной очередью, проверкой хранилищ, каталогом и историей. Сохранённые agent.json и server-monitoring.json должны относиться к одному enrollment: HTTPS-адрес с префиксом API, ID агента и ссылка на учётные данные. Отсутствующее или несовпадающее подключение запрещает запуск; локальные задания не подставляются.

Подготовленный AgentApiClient использует тот же Windows Vault или делегированный кэш службы, что и мониторинг. Секрет читается заново перед запросом и не записывается в JSON. HTTPS использует системное доверие либо точный SHA-256 сертификата, сохраняя проверку имени и дат; перенаправления запрещены. Ошибки адаптера секретов не переносят его сообщения или вложенные исключения в диагностику.

Готовый Managed-хост объявляет managed-execution-v1 только для своего привязанного API и мониторинга. Автономный клиент, обычная библиотека и окно, просматривающее кэш, этого не заявляют. Синхронизация и heartbeat работают отдельно от планировщика, поэтому недоступность сервера не останавливает принятые задания. При остановке хост пытается передать отрицательную готовность с бюджетом в одну секунду; при недоступном сервере остаётся обычный срок устаревания последнего сигнала.

## Первый запуск и офлайн

Без принятого кэша расписание пусто: агент ждёт сервер, а ручная команда для неизвестного задания отклоняется. После успешной проверки и атомарного сохранения конфигурации расписание использует серверные задания. При недоступном сервере или ошибочной новой ревизии сохраняется прежний принятый план. Ручной запуск доступен независимо от расписания и признака Enabled; удалённое задание больше не находится в текущем источнике.

Режим и подключение фиксируются на время жизни хоста. Изменение или отключение Managed-подключения в окне требует свободного исполнителя. Если настройки были недоступны при запуске и затем восстановились как Managed, требуется перезапуск: переход через локальные задания запрещён.

## Изоляция данных

Для каждого канонического HTTPS-адреса, ID агента и ссылки на учётные данные вычисляется ConnectionId. В managed/<ConnectionId> находятся отдельные принятая конфигурация, очередь её подтверждений, отметки запуска при загрузке, каталог копий, рабочая папка и файловые снимки. Идентификатор не содержит токен. Перевыпуск подключения с новым ключом создаёт новый профиль; прежние файлы остаются.

Глобальные jobs.json, защищённые локальные задания, каталог автономных копий и их архивы не перезаписываются. Старый общий server-jobs.json автоматически не переносится в новый профиль. Первая файловая копия нового профиля полная даже при совпадающем ID автономного задания: чужая цепочка не становится её родителем и не попадает под её очистку.

## Ревизия конкретной копии

AgentExecutionJobSource передаёт исполнителю неизменный снимок задания с внутренней привязкой к подключению и ревизии. Она не входит в JSON задания. BackupRun сохраняет эту привязку до начала копирования; завершение, ошибка, отмена и восстановление после аварии её сохраняют. Новая ревизия не изменяет уже выбранный снимок.

В отчёт сервера передаётся только положительный номер ревизии этого запуска. Хэш подключения, ссылки на секреты и локальные пути туда не добавляются. История другого enrollment исключается из результатов и текущего прогресса для нового подключения. Прежняя автономная история без такой привязки сохраняет обычное поведение мониторинга.

Карточка агента отдельно показывает режим, принятую ревизию и готовность исполнителя. В подробностях результата видна ревизия самой копии: принятие ревизии 2 во время работы копии по ревизии 1 не превращает её в результат ревизии 2. Подтверждение конфигурации означает проверку и сохранение, а не создание копии.

## Проверки и оставшаяся работа

Набор проверок включает настоящий LocalAgentHost с HTTPS/PostgreSQL, принятие новой ревизии во время создания архива и доставку прежнего номера ревизии; офлайн-ручной запуск, изоляцию цепочек и каталогов, восстановление прерванной истории. Native Windows-проверка запускает опубликованный агент как настоящую SCM-службу под другой учётной записью и проверяет делегированный токен, HTTPS, отсутствие локального fallback без кэша, создание и чтение ZIP, подтверждения, офлайн-перезапуск, ручную очередь и новый enrollment.

Интерфейс простого включения Managed и полноценный веб-мастер ещё не завершены. Технический режим не предлагается как готовый сценарий для новичка: окно показывает серверные задания только для чтения. Новая версия не публикуется автоматически после разработки. Настоящий Hyper-V-прогон с выключением ВМ, доменным SMB и реальной платформой 1С остаётся отдельной проверкой; CI и тестовый файл 1CD его не заменяют.
