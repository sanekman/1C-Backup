# Служба Windows

Установщик размещает программу в `C:\Program Files\1C-Backup` с запросом UAC.
Задания, история и пароли остаются в пользовательском профиле. После установки
откройте программу обычным запуском ярлыка, чтобы использовать свои задания.

Откройте **Настройки → Служба Windows → Установка службы**. Остановите автоматическое
копирование и дождитесь завершения операций. В поле **Пользователь службы** можно:

- выбрать текущую учётную запись или одного из включённых локальных пользователей;
- ввести `КОМПЬЮТЕР\пользователь`, `.\пользователь`, `ДОМЕН\пользователь` или UPN
  (`пользователь@домен`); короткое имя считается локальным пользователем.

Список не перечисляет весь домен: доменного пользователя введите вручную. Windows
проверяет имя и SID; группы, LocalSystem, LocalService и NetworkService не принимаются.
Введите пароль **выбранного пользователя** (не PIN) и нажмите **Установить службу**.
Windows запросит права администратора. При смене пользователя или пароля остановите,
удалите и установите службу заново. Доменная политика может запрещать вход в качестве службы.

`OneCBackupAgent` автоматически запускается при включении компьютера, до входа пользователя,
и использует существующие задания, расписания, историю, каталог и учёт попыток копирования
при запуске системы. В состоянии службы отображаются статус и установленная учётная запись.

## Доступ к данным

Владелец рабочего профиля и пользователь службы могут отличаться. В `windows-service.json`
сохраняются их SID и папки владельца, **без пароля Windows**. Старый формат без SID службы
продолжает использовать владельца. Интерфейс работает под владельцем; служба проверяет
свою фактическую учётную запись перед запуском.

При установке другой пользователь получает права изменения стандартного рабочего профиля
`%LOCALAPPDATA%\OneCBackup` владельца. Папка должна принадлежать владельцу заданий и не
проходить через junction/ссылки. Пользовательские переносные/нестандартные профили для такого
делегирования не поддерживаются. Права на исходные файлы, базы, временную папку и хранилища
нужно настроить в Windows отдельно. SQL Server с Windows-аутентификацией видит выбранного
пользователя службы: ему нужны разрешения на SQL Server. Платформа 1С должна работать
под выбранной учётной записью. Сетевые папки задавайте UNC-путями (`\\сервер\папка`),
поскольку буквы подключённых дисков недоступны в отдельном сеансе службы.

Пароли FTP, WebDAV и архивов, включая пароли старых архивов из каталога, экспортируются
в `service-secrets`: машинное DPAPI-шифрование и защищённые ACL. Владелец, SYSTEM и
администраторы имеют полный доступ; другой пользователь службы — только чтение.
Служба под другим пользователем читает этот экспорт вместо личного Windows Vault своего
пользователя. Интерфейс владельца обновляет экспорт при сохранении паролей.

Для PostgreSQL используется `%APPDATA%\postgresql\pgpass.conf` владельца. Если файл
существует и принадлежит владельцу, выбранному пользователю предоставляется чтение
**этого файла**, а не всего roaming-профиля. После замены файла редактором права могут
потребовать повторной настройки. Файл другого владельца автоматически не делегируется.

Пароль Windows передаётся повышенному помощнику только по ограниченному локальному каналу,
после проверки SID процесса интерфейса. В аргументах, JSON и диагностических логах пароль
не сохраняется. Помощник передаёт его SCM. Настройки и файлы секретов не входят в диагностику.

## Управление

**Запустить**, **Остановить** и **Удалить службу** находятся в том же разделе. Обычная
кнопка запуска фонового агента при установленной службе запускает службу. Остановка через
`services.msc`, настройки или полный выход из трея отменяет текущую операцию и дожидается
записи результата и освобождения профиля. Один профиль использует один исполнитель.
При установке удаляется принадлежащий этой программе автозапуск при входе пользователя.

Обновление сохраняет регистрацию службы. Ручное обновление с перезапуском фоновой работы
снова запускает службу. Автообновление при полном выходе оставляет службу остановленной
до следующего запуска или включения компьютера. **Перед удалением программы удалите службу
в настройках**. Удаление службы сохраняет задания, копии и пароли. Выданные права Windows
на профиль / pgpass и вход в качестве службы автоматически не отзываются: они могут
использоваться другими службами. Если учётная запись больше не нужна, администратор
может отозвать эти права в Windows; при повторной установке другой пользователь получает
свои права отдельно. Экспорт паролей перезаписывает ACL каталога для текущего выбора.

## Проверки

В Linux выполняются сборка агента/WPF, тесты имён, SID профиля и протокола. WindowsIntegration
проверяет разрешение текущего имени, отказ для групп, DPAPI и чтение секретов по ACL.
Выбор пользователей, доступ другого пользователя к файлам, UAC, регистрацию SCM, запуск
до входа и права на реальные SQL/1С необходимо проверить на Windows. В этой Linux-среде
эти нативные операции не выполнялись.
