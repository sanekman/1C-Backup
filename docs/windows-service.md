# Служба Windows

Установщик по умолчанию размещает программу в `C:\Program Files\1C-Backup` с запросом UAC.
Задания, история и пароли остаются в пользовательском профиле. После установки откройте
программу обычным запуском ярлыка, чтобы использовать свой профиль.

В установленном приложении откройте **Настройки → Служба Windows → Установка службы**.
Остановите автоматическое копирование, дождитесь завершения операций, введите пароль своей
учётной записи Windows (не PIN) и нажмите **Установить службу**. Windows запросит права
администратора. Служба `OneCBackupAgent` запускается автоматически при включении компьютера,
до входа пользователя, и использует текущие задания, расписания, историю и каталог копий.
Программа должна оставаться в установленной папке. Переносной дистрибутив не регистрирует службу.

Служба работает под владельцем рабочего профиля, а не LocalSystem. Это сохраняет права
доступа пользователя к исходным базам, SQL Server с Windows-аутентификацией и сетевым папкам.
Для сетевых дисков указывайте UNC-пути (`\\сервер\папка`): подключённые буквы дисков
недоступны в отдельном сеансе службы. Пользователь должен иметь доступ к источникам,
временной папке и хранилищам. При смене пароля Windows остановите, удалите и установите
службу заново с новым паролем. Доменная политика может запрещать вход в качестве службы.

Сохранённые пароли FTP, WebDAV и архивов экспортируются для сеанса службы в `service-secrets`
рабочего профиля: машинное DPAPI-шифрование и отдельные права только владельцу, SYSTEM
и администраторам. Экспортируются также пароли старых архивов из каталога копий.
Последующие изменения паролей в приложении обновляют защищённые файлы. Пароль Windows
передаётся повышенному помощнику по локальному каналу с ограниченными правами и передаётся
в SCM; в аргументах, JSON-профиле и логах он не сохраняется. Настройки окружения владельца
хранятся в `windows-service.json` без паролей. Данные диагностики эти файлы не включают.
Для PostgreSQL используется файл владельца `%APPDATA%\postgresql\pgpass.conf`.

**Запустить**, **Остановить** и **Удалить службу** находятся в том же разделе. Запуск
обычного фонового агента при установленной службе запускает службу. Остановка через
`services.msc`, настройки или полный выход из трея отменяет текущую операцию, дожидается
записи результата и освобождения профиля. Один профиль одновременно выполняет только
один исполнитель. При установке удаляется принадлежащий этому приложению автозапуск
обычного агента при входе; ярлык другого расположения не изменяется.

Обновление сохраняет регистрацию службы. Ручное обновление с перезапуском фоновой работы
снова запускает её через интерфейс. Автообновление при полном выходе оставляет службу
остановленной до следующего запуска или включения компьютера. **Перед удалением программы
сначала удалите службу в настройках**: установщик блокирует удаление зарегистрированного
агента даже при остановленной службе. Удаление службы сохраняет задания, копии и пароли.

## Проверки

Сборка агента и WPF проверяется в Linux с Windows targeting. Тесты протокола проверяют
ограничение размера, усечённые сообщения, Unicode и разделение профилей. Проверка DPAPI
и прав доступа выполняется в Windows при включённых WindowsIntegration-тестах.
Регистрацию SCM, запрос UAC, запуск до входа пользователя, остановку при активной архивации
и обновление установленной службы необходимо проверить на Windows: Linux эти механизмы
не выполняет. Не используйте тестовый профиль для управления существующей службой.
