# Сначала завершаем Windows

Приоритет разработки: Windows-агент и Windows-сервер как законченный рабочий комплект. Новые возможности Linux, нативный systemd и дополнительные архитектуры идут после этого. Уже опубликованные Linux-пакеты остаются доступными; проверки общих библиотек на Linux продолжаются, чтобы не вносить регрессии.

Изменения накапливаются в `feature/local-backup-agent`, PR №2. Последние опубликованные версии — клиент alpha.27 и отдельный сервер preview.3; новые изменения накапливаются после них. Отдельная доработка не означает новый выпуск; существующие теги и файлы выпусков не заменяются.

## Что уже работает

- Установка Windows-клиента с собственным runtime; интерфейс, фоновый агент, автозапуск и служба под выбранным пользователем.
- Файлы и папки, WebDAV, файловая 1С, MS SQL и PostgreSQL; ручной запуск при включённом расписании, последовательная очередь, история, проверка и восстановление файлов.
- Полные и инкрементные файловые копии, полная по дню недели, перенос пропущенного дня, сохранение доступных файлов при ошибках и предупреждения о неполной копии.
- Несколько хранилищ, проверка доставки, хранение зависимостей инкрементной цепочки, ZIP/AES-256, экспорт секретов службе.
- Проверка и установка обновления; сохранение профиля; диагностика и локальные инструкции. Новые разделы настроек, первый экран и помощь по шагу мастера доступны начиная с alpha.25.
- Установка Windows-сервера с PostgreSQL, HTTPS и службами; понятное имя отдельно от адреса; приглашения, мониторинг агентов, прогресс, история, неполные копии и результаты хранилищ.

Это перечень реализованных функций. Он не означает проверку на всех целевых версиях Windows или на рабочей платформе 1С.

## Текущий пакет Windows

| Работа | Что считается проверкой |
| --- | --- |
| Переход с 1C-Backup alpha.25 на SP Backup | Настоящий опубликованный установщик с закреплённым SHA-256; прежняя папка установки; чтение старых Vault/DPAPI-секретов; восстановление прежней и новой копии; перенос своего автозапуска; сохранение профиля и копий после удаления. Сценарий выполняется только в изолированном Windows CI. |
| SQL-логин MS SQL вместо обязательного входа через Windows | Выбор и повторное открытие в мастере; пароль только в Windows Vault / DPAPI; одинаковый способ входа для проверки источника и копирования; импорт с другим SQL-сервером или без доступного секрета требует нового ввода; старые задания сохраняют Windows-вход. Реальное подключение SQL-логином к серверу со смешанным режимом требует отдельного стенда; LocalDB его не заменяет. |
| Поиск клиентских утилит PostgreSQL | Реестр и обычные папки установки; выбор версии; pg_dump/pg_restore из одной папки; отсутствие EXE не стирает ручные пути; поиск ничего не запускает и не обещает доступ к базе. |
| Настоящая служба агента в Windows CI | Отдельный временный пользователь без интерактивного входа, SCM и автоматический старт, задание при запуске, ручная очередь владельца, DPAPI-пароль и восстановление копии, остановка и освобождение профиля, перезапуск без повторения задания за ту же загрузку, удаление без удаления копий. |
| Чтение истории во время копирования | Завершённое задание сохраняет итог, даже когда интерфейс читает прежнюю запись «Выполняется»; читатель получает целый старый снимок, новые читатели — целый новый. Такой же способ замены используется для заданий, каталога, прогресса и индекса файловых копий. Отмена записи сохраняет прежний файл. |
| Нехватка места в файловом хранилище | Размер готового архива сверяется с доступным объёмом до его хеширования и переноса; Windows учитывает пользователя, UNC и квоту. Неудачное хранилище не блокирует остальные и не запускает очистку старых копий. Проверка доступа показывает объём временной папки и локальных/сетевых хранилищ. Неизвестный объём не запрещает обычную запись; это проверка, а не резервирование места. |
| Кратковременный обрыв доставки в сетевую папку | После известных сетевых кодов Windows повторяется только доставка готового архива: две попытки после пауз 2 и 5 секунд, без нового чтения источника. Отмена прерывает ожидание. Потерянное подтверждение переименования требует проверки файла до регистрации; прежний чужой файл не принимается и не заменяется. Очистка только собственных временных файлов не маскирует основную ошибку. Ошибки прав/паролей/места и SHA-256 не повторяются; выводятся действия для пользователя службы. |
| Длинные пути с русскими именами | Автоматический сценарий создаёт источник, хранилище, временную папку и папку восстановления с путями длиннее 260 символов. Проверяются повтор доставки, полная и неполная инкрементная копии с занятым файлом, восстановление потерянного индекса и точных байтов всей цепочки. Результат Windows CI фиксируется вместе с остальными проверками пакета. |
| Проверка хранилищ от имени исполнителя | Сохранённое задание проверяется через работающий агент/службу без остановки расписания. В результате указана действующая учётная запись Windows; нативный SCM-сценарий сверяет SID отдельного пользователя службы и неизменность истории/каталога. Команда отделена от резервного копирования, привязана к сеансу и настройкам задания. Старые агенты её не принимают; отмена, смена сеанса, повреждённая команда и ошибка подтверждения проверяются отдельно. |
| Сетевая папка от пользователя службы | Добавлен нативный SCM-сценарий под отдельным временным пользователем без интерактивного входа. У двух собственных UNC-шар одинаковый разрешающий доступ к папкам NTFS, но одна разрешает доступ через SMB, а другая явно запрещает его этому пользователю. Проверки через службу сверяют действующий SID, отказ и успех без изменения истории/каталога и остановки расписания. Настоящая зашифрованная копия в разрешённой шаре проверяется по владельцу файла, SHA-256 и восстановленным данным; архив входит в проверки сохранности после перезапуска и аварии службы. Результат нового сценария фиксируется в CI; это локальный SMB-сервер стенда, а не доменная сеть. |
| Настоящий обрыв SMB во время доставки | Изолированный Windows-стенд создаёт собственную временную сетевую папку и записывает в неё первый блок через UNC. После подтверждения серверного SMB-дескриптора тест удаляет только свою шару и продолжает запись: ошибку возвращает Windows, а не подставной исполнитель. Восстановление шары перед повтором позволяет проверить доставку тех же байтов, SHA-256, однократную регистрацию, сохранность прежней копии и очистку временных файлов. Обрыв проверяется от пользователя стенда; доступ отдельного пользователя службы проверяется самостоятельным SCM-сценарием. Доменный сервер требует отдельного стенда. |
| Аварийное завершение службы в ожидании | Нативный Windows CI действительно завершает процесс после проверки пути EXE, дожидается освобождения профиля и запускает службу снова. Проверяются новый сеанс, полный цикл расписания без повтора стартового задания, неизменность заданий, истории, каталога и SHA-256 всех доставленных архивов. Это не проверка отключения питания или остановки во время записи. |
| Аварийное завершение службы во время PostgreSQL-копии | После alpha.27 добавлен нативный сценарий: настоящий `pg_dump` ожидает блокировку таблицы отдельной тестовой БД, затем завершается только проверенный родительский процесс службы. Проверяется выход дочернего `pg_dump` до снятия блокировки, новый сеанс, итог «Прервано», отсутствие повторного исполнения старых команд и стартового задания, сохранность прежних архивов по SHA-256 и восстановление данных из следующей явно запущенной копии. Результат сценария фиксируется в CI; перезагрузка Windows, отключение питания и настоящая платформа 1С требуют отдельных проверок. |

После alpha.27 уточнена обработка повторно доставленных ручных команд: уже завершённое подтверждение сохраняется и после смены сеанса. Нативный SCM-сценарий возвращает настоящую завершённую команду в очередь при остановленной службе, затем сверяет неизменность подтверждения и истории после её запуска. Несовпадающие задание или сеанс не перепривязывают старый результат и не запускают копирование; агент показывает предупреждение. Отдельный сценарий повторно доставляет команду, пока запись её итогового подтверждения недоступна, и проверяет отсутствие второй копии и работу следующего задания.

Результаты каждого пакета и ссылки CI фиксируются в PR. Тест службы требует изолированный Windows-runner и явный флаг; существующие службу и профиль он не использует.

В пакете после alpha.27 Windows-агент при фоновом запуске и работе службой включает защиту дочерних процессов до запуска утилит. При аварийном завершении агента Windows завершает и его утилиты; новый исполнитель не должен работать одновременно с оставшимся `pg_dump`. Прямое копирование в окне программы и выполняемый на сервере `BACKUP DATABASE` MS SQL имеют другой жизненный цикл и этой защитой не охватываются.

При сбое тест службы сохраняет состояние планировщика, историю и журнал до удаления временного профиля. Эта диагностика выявила отказ Windows при замене читаемого файла истории: архив уже был доставлен, но итоговая запись оставалась «Выполняется». Для существующих файлов профиля используется атомарная замена с сохранением прав доступа; форматы заданий и архивов не меняются.

## Следующие Windows-этапы

Для оставшихся эксплуатационных проверок пункта 1 подготовлен [изолированный Hyper-V-стенд](windows-lab.md): отдельный доменный SMB-сервер, служба под доменным пользователем и принудительное выключение ВМ во время настоящего `pg_dump`. До получения результатов этого стенда сценарии остаются непроверенными. В текущем пакете восстановление после аварии также завершает подтверждения уже принятых ручных команд прежнего сеанса, не повторяя их исполнение.

1. **Повседневная работа агента.** Защита несохранённого задания реализована в текущем пакете; Windows CI проверяет сохранение, отказ, возврат, ошибки записи и сворачивание в трей. В текущем пакете добавлено различение службы, фонового агента, планировщика программы и разовой копии; ближайший запуск, состояние автозапуска и защита чужой записи. Добавлено восстановление потерянного или отставшего индекса инкрементной цепочки по проверенным локальным/UNC-архивам после прерванного запуска; порядок регистрации не зависит от коррекции часов. После alpha.26 реализованы ограниченные повторы доставки готового архива при известных сетевых ошибках и проверка хранилищ через действующего пользователя службы без остановки расписания. Нехватка места и длинные пути проверены автоматическими сценариями из таблицы выше. После alpha.27 добавлены защита дочерних процессов агента и сценарий принудительного завершения службы во время настоящего `pg_dump`. Также добавлены проверка настоящего обрыва собственной SMB-шары во время записи готового архива и отдельный SCM-сценарий доступа/отказа к UNC от пользователя службы; приостановка записи управляет только моментом обрыва. Повторно доставленная ручная команда сохраняет уже записанный итог и не создаёт вторую копию. После перезапуска агента окно и трей очищают прогресс прежнего процесса, сохраняя отображение долгой SQL-копии действующего исполнителя. Далее — перезагрузка Windows во время копирования, обрыв подключения к отдельному SMB-серверу и доменный UNC-сервер с правами пользователя службы. Локальный SMB-стенд и PostgreSQL не подтверждают эти оставшиеся эксплуатационные сценарии.
2. **Подключения к базам без ручных файлов.** Сохранение пароля PostgreSQL из интерфейса и передача службе реализованы в текущем пакете с реальной SCRAM-проверкой копирования и восстановления. В следующем пакете после alpha.25 добавлены подсказки по известным кодам MS SQL и действия при неудаче psql. Добавлена настройка TLS PostgreSQL с проверкой имени и сертификата и выбором корневого PEM. Защищённые задания хранятся отдельно, обычные доступны прежнему агенту; изменение защищённых заданий требует остановки исполнителя. Проверки используют TLS/SCRAM, неверные CA/имя, службу и опубликованный старый клиент. Реальный MS SQL со смешанным режимом и сертификатами требует отдельного стенда. В следующем пакете после alpha.25 добавлен SQL-логин для мониторинга внешних MS SQL-копий: Windows Vault, экспорт службе до сохранения источника и сброс привязки при смене сервера. Для каждого способа — реальная проверка входа, копирования и восстановления на тестовой базе.
3. **Управление заданиями с Windows-сервера.** Веб-мастер, сохранённая и принятая ревизии, отклонение некорректной конфигурации целиком, исполнение Managed в настоящем хосте, работа офлайн, аудит. Секреты остаются на агенте. Затем — удалённый ручной запуск с подтверждением и защитой от повторов. Пока сервер обеспечивает мониторинг, автономное копирование не зависит от его доступности.
4. **Эксплуатация Windows-сервера.** Копия и проверенное восстановление БД, настроек и сертификатов; обновление и возврат после ошибки миграции; срок сертификата, свободное место и понятные действия администратора. В следующем пакете после preview.3 реализованы смена пароля панели с завершением прежних сеансов, журнал действий и выгрузка диагностики; копия и восстановление сервера ещё не реализованы. Копирование самого сервера не подменять копиями агентских заданий.
5. **Проверка целевых систем и общий билд.** Windows 11 и Windows Server 2016/2019/2022/2025 с Desktop Experience; реальные сеансы 1С; установка под обычным пользователем с UAC, смена пользователя службы, обновление и удаление. CI `windows-latest` не подтверждает всю матрицу ОС. Подпись установщиков требует сертификата издателя; текущие сборки не подписаны.

Оповещения Telegram/MAX остаются отдельной задачей по ранее принятому решению. VSS, образ системы, дифференциальные SQL-копии и журнал транзакций не входят в уже заявленные возможности первой версии. Их нельзя считать готовыми на основании файлового копирования.

К Linux возвращаемся после завершения согласованного Windows-комплекта и его эксплуатационных проверок. Общие форматы, API и существующие Linux-дистрибутивы при этом сохраняем совместимыми.
