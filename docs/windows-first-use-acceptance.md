# Первое использование: протокол приёмки

Обновлено 15 ноября 2026 года. Пункт 7.3 основной дорожной карты остаётся
открытым до независимого прохождения человеком без устных подсказок разработчика.
Ниже разделены проверенный браузерный путь и ещё не выполненная ручная приёмка.

## Что проверено автоматически

Продолжен существующий браузерный сценарий `tests/server/agent_overview_browser.py`;
новые переходы находятся в `tests/server/first_use_flow.py`. Использован текущий
сервер рабочей ветки после `af5c881`, Chromium и отдельная PostgreSQL/HTTPS-схема.
Производственный код и пакеты приложения этим изменением не меняются.

Пройдено в браузере:

1. Создание организации, филиала и отдела; приглашение в выбранный отдел.
2. Регистрация тестового агента по одноразовому коду; появление в папке.
3. Мастер задания: отказ относительного пути без изменения ревизии, исправление,
   переход назад с сохранением пути, ручной режим, два хранилища и публикация.
4. Получение ревизии и подтверждение принятия через настоящий агентский API.
5. Удалённая команда: ожидание агента, принятие и выполнение; постановка команды
   не выглядит созданной копией.
6. Отчёт частичной доставки: раскрытие истории и отдельные результаты двух
   хранилищ. Новый успешный отчёт очищает текущую сводку, прежняя ошибка остаётся
   в истории.

Регистрация, подтверждение плана, мониторинг и результаты подаются
**протокольным стендом агента**. Настоящие браузер, сервер, API и БД;
архивы не создаются, Windows-служба не запускается, восстановление не выполняется.
Скрипт работает только с loopback. Код приглашения и токен не сохраняются в
отчёт/снимки, пароль берётся из закрытого файла фикстуры.
Это проверка панели, не независимое прохождение новичком и не новая приёмка
действительного копирования. Прежние Windows/Linux-проверки неизменённого
приложения сохраняются в [отчёте сводки](server-agent-overview.md).

Запуск из корня репозитория с подготовленной отдельной PostgreSQL:

```sh
ONECBACKUP_SERVER_TEST_CONNECTION_FILE=<закрытый-файл-подключения> \
ONECBACKUP_OVERVIEW_BROWSER_OUTPUT=<каталог-отчёта> \
dotnet test tests/SPBackup.Server.Tests --no-build --no-restore \
  --filter 'FullyQualifiedName~AgentProblemSummaryTests'
```

Нужны собранные актуальные тесты, Python Playwright и `/usr/bin/chromium`.
Локальные результаты: `artifacts/server-first-use-browser/result.json` и PNG.
15 ноября пройдены **11 браузерных проверок** (8 прежних и 3 группы полного
пути), профильные интеграции **3/3**. Просмотрен снимок результата двух
хранилищ; секреты приглашения на снимки не попадали. Повторные запуски
исправляли только селекторы сценария и полноту тестовых heartbeat/отчётов;
изменений приложения и повторной установки не потребовалось.

## Независимое прохождение: пока не выполнено

Исполнитель получает только опубликованные пакеты и письменные инструкции:
[Windows-агент](user-guide.md), [первый запуск сервера](server-first-start.md),
[серверное задание](server-job-wizard.md), [совместимость](windows-compatibility.md).
Для рабочей ветки отдельно фиксируется кандидат: её интерфейс может отличаться
от опубликованного preview.10. Новая сводка ещё не выпущена.

Использовать отдельный Windows-компьютер/VM для чистой установки и тестовые
данные. Не удалять действующую установку ради теста и не переключать режим
рабочего агента. Базу `C:\Базы 1С\УНФ` не затрагивать. Для файлового сценария
подготовить отдельные подпапки `E:\SPBackup-Tests\FirstUse` с небольшими файлами,
каталогами двух доставок и отдельной папкой восстановления.

| Шаг | Ожидаемый результат |
| --- | --- |
| Установка и вход | Без пояснений найдены нужный пакет, имя/адрес сервера, вход и подключение; записаны ОС/версии/SHA-256. |
| Первое локальное задание | Источник и две папки копий заданы без изменения рабочих данных. Проверка доступа выполнена фактическим агентом/службой; пароль не попадает в отчёт. |
| Копия и восстановление | Получены файлы копий, выполнено восстановление в отдельную пустую папку; сверены имена и содержимое. Восстановление не перезаписывает источник. |
| Работа службы | Закрытие окна и перезагрузка тестовой Windows не теряют задание и расписание; реальный исполнитель и его права записаны. |
| Ошибка и исправление | На отдельном тестовом назначении воспроизведён отказ; другая доставка сохранена. Причина понятна, следующий успешный запуск и история различаются. |
| Подключение к панели | Агент помещён во вложенную папку; связь и успешная копия различаются. |
| Серверное задание | На изолированном агенте принят режим «Задания с сервера», создан файловый план, видны сохранённая и принятая ревизии. Локальные задания сохранены отдельно. |
| Команда и отсутствие связи | Команда не считается успехом до результата; при отключении связи данные обозначены устаревшими. После восстановления отчёты приходят без дублей; автономное принятое расписание продолжает работу. |
| Обновление и удаление | Пройдены документированные подготовка возврата и поддерживаемое обновление тестовой установки. Перед удалением сохранены нужные данные; результат удаления сверяется с инструкцией. |

Запись для каждого шага: пакет/коммит, окружение, время и пояс, действие,
ожидание, фактический результат, непонятная формулировка/место остановки,
ссылка на обезличенный снимок или отчёт. Секреты, коды приглашений, токены,
ключи сертификатов и содержимое рабочих баз не прикладывать.

Шаг без исполнения отмечается «не проверено» с причиной. Разработчик может
исправить найденную проблему и назначить профильную перепроверку; это не
заменяет исходный протокол самостоятельного прохождения.
