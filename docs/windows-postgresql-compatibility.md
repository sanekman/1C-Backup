# Совместимость утилит PostgreSQL на Windows

10 ноября 2026 года. Workflow **Verify Windows PostgreSQL tool compatibility** проверяет блок 4.4.2. Наличие сценария не означает приёмку: нужен успешный JSON с точным исходником и фактическими версиями.

## Проверки

На одноразовый GitHub-hosted Windows runner загружаются комплекты PostgreSQL 15–18 по фиксированным HTTPS-адресам официального поставщика EDB. Из архивов извлекаются только bin/lib/share в отдельную новую папку. Существующие установки, службы, реестр и брандмауэр не меняются. Сохраняются SHA-256 архивов, фактические pg_dump/pg_restore --version и версии серверов. Фиксированная ссылка не подменяет проверку содержимого.

Все 16 сочетаний сервер/pg_dump проверяются настоящим исполнителем SP Backup с Windows Vault, SCRAM и TLS verify-full. Для каждого сервера создаются отдельный кластер, база с двумя строками (включая Unicode), каталог и история. Успешная копия проходит доставку, SHA-256 и реальное восстановление с точным числом и содержимым строк.

- Четыре одноимённых комплекта восстанавливаются на исходную основную версию сервера.
- Шесть сочетаний нового pg_dump со старым сервером восстанавливаются на PostgreSQL 18 с `--no-owner --no-privileges`: у отдельного целевого кластера свой тестовый пользователь, роли кластера не содержатся в pg_dump. Это проверка переноса данных, а не переноса владельцев/прав или восстановления нового дампа на старом сервере. Четыре восстановления одноимённым комплектом сохраняют штатное поведение без этих флагов.
- Шесть старых pg_dump против нового сервера должны завершиться именно несовпадением версий. Ошибка пароля или TLS не засчитывается вместо ожидаемого отказа.
- Отдельно проверяется дамп pg_dump 18 с pg_restore 15: настоящий отказ неподдерживаемой версии формата, отсутствие доставки и записи в каталоге.
- Следующий запуск правильным комплектом должен завершиться успешно и восстановить данные. После каждого запуска существующие копии сверяются по SHA-256; ошибочная операция не должна их менять.

Всего требуются **18 завершённых проверок**: 10 восстановлений основной матрицы, 6 отказов старого pg_dump, отказ старого pg_restore и успешное восстановление после ошибки. В артефакт попадает только JSON результата/подготовки. Пароли, Vault, дампы, базы, закрытые ключи, утилиты и их журналы не загружаются.

## Границы

Матрица выполняется под текущим пользователем Windows и явно сообщает serviceIdentityVerified=false. Настоящая служба с делегированным паролем, TLS и восстановлением принята отдельно в 4.4.1; эта матрица не выдаётся за проверку каждого сочетания под SCM. Другие основные версии, расширения, роли кластера и WAL/PITR не охватываются.

Результат пока не принят: требуется фактический прогон Windows. Неудачный сценарий нужно исправить и повторить; недостающие проверки не заменяются моделированием утилит или ослаблением ожиданий.
