# Этап 5: центральное управление Windows

Пакет принят 11 ноября 2026 года: **5.1–5.5 завершены в границах поддерживаемых файловых серверных планов.** Новый публичный выпуск не создаётся. PR №2 остаётся черновиком.

## Границы пакета

Сервер управляет поддерживаемыми файловыми заданиями: файлы/папки и ZIP файловой 1С, локальные и UNC-хранилища (до восьми), расписание и полные/инкрементные файловые цепочки. Сохранение, история, возврат новой ревизией, конфликт редакторов и подтверждения применяются ко всему плану. Неверная ревизия не заменяет принятый локальный кэш. SQL, WebDAV, FTP/Google Drive и DT остаются локальными типами заданий: новый пакет не добавляет их в серверный мастер и не выдаёт за проверенные удалённые механизмы.

## 5.1. Сводка проблем

Страница «Проблемы» показывает агента, конкретное задание, причину и действие. Есть папка с подпапками, раздел «Без папки», тип проблемы, буквальный поиск по имени агента/задания и страницы по 50 причин. Отозванные агенты исключены. Старый результат удалённого из текущего списка задания не попадает в сводку.

Отсутствие связи определяется серверным временем получения сигнала. Дата отчёта показана отдельно. Можно увидеть ошибки, неполные копии, предупреждения, ошибки SQL-опроса, неприменённый/отклонённый план, недоступного исполнителя и незаданный локальный доступ.

Для файлового задания можно задать допустимый возраст копии в часах (1–87600); пустое поле отключает контроль. Полная или инкрементная успешная копия без пропусков удовлетворяет сроку. Порог не меняет расписание. Для новых управляемых запусков передаётся контрольная сумма области источника/назначений без путей и ключей: старая копия другого источника или набора хранилищ не подтверждает свежесть нового. Смена названия/расписания не обнуляет этот результат. История прежних копий сохраняется. Для наблюдения SQL используется заданный на агенте срок и состояние выбранного источника; прежняя ошибка другого источника не становится текущей. При отсутствии связи показанные сведения считаются состоянием последнего отчёта, а не проверкой текущего доступа.

## 5.2. План и ревизия

Действующий протокол подтверждений сохраняется: желаемая ревизия, проверенная/сохранённая агентом ревизия и ревизия конкретной копии различаются. При первом подключении без кэша локальные задания не подставляются. После принятия плана агент исполняет его и без связи; ошибка новой конфигурации сохраняет прежний план. Веб-мастер сохраняет новые требования доступа и срок свежести при редактировании, возврате и создании на основе.

## 5.3. Защищённый доступ

В мастере можно потребовать AES-256 и отдельный сетевой вход для каждого UNC-назначения. В панели нет полей логина, пароля или ключа Windows Vault. Учётные данные задаются в Windows-программе: остановить агента/службу, выбрать серверное задание, открыть **«Файл → Доступ серверного задания…»**, проверить показанные источник и назначения и ввести доступ.

Пароли хранятся в Windows Vault и существующем делегированном кэше службы. В `managed/<ConnectionId>/bindings` сохраняются только локальные ссылки и контрольная сумма области применения. Серверные конфигурации, история и экспорт API этих ссылок не получают. Изменение источника, путей/типов назначений или требований доступа требует новой локальной привязки. Смена названия/расписания привязку не отменяет. Новый enrollment не наследует доступ старого. Старые архивы сохраняют собственные ключи.

До настройки требуемого доступа копия завершается ошибкой до подготовки хранилища и чтения источника; незашифрованная копия вместо защищённой не создаётся. Наличие ссылки не является проверкой доступа — после настройки нужно выполнить проверку хранилищ через нужного исполнителя. UNC-источник читается под учётной записью пользователя агента/службы; отдельный NAS-логин назначения не подменяет её.

## 5.4. Удалённый запуск

В списке серверных заданий есть **«Запустить…»**. Форма подтверждает задание и ревизию, срок запуска — 1–1440 минут, по умолчанию 10 минут. Сохранённая команда получает уникальный ID, привязку к текущему enrollment и статус «Ожидает агента». Повтор отправки той же формы возвращает ту же команду.

Состояния: ожидание → принята → выполняется → завершена/ошибка; отдельно отказ, истечение и прерывание. Время и ID результата показаны в истории команд. Команда может выполнить ручное задание или задание с выключенным расписанием. Неподдерживающий агент не выдаётся за принявший запуск. В серверной очереди допускается до 100 ожидающих активных команд на агента.

Агент сохраняет журнал до исполнения, повторно проверяет ревизию/задание/срок после получения общего исполнительского шлюза и получает серверное разрешение на начало. При недоступном сервере новая удалённая команда не начинает копирование; локальное расписание и локальная ручная очередь работают независимо. Уже начатое копирование может завершиться без связи, результат сохраняется для повторной доставки.

Серверное разрешение на начало одноразовое: уже выданный старт не подтверждается заново даже после потери локального журнала. Потерянный ответ, повтор получения и перезапуск не запускают команду заново. Запись о начале без надёжного итога становится «Прервана, проверьте историю». Это намеренно консервативный результат: даже потерянное разрешение на начало не считается основанием для автоматического повтора. Перед новым ID после прерывания нужно проверить историю копий.

## 5.5. Работа без связи

Принятый план, локальная очередь результатов, подтверждения конфигурации и журнал команд разделены. Принятие плана не подменяет результат копии. Серверные результаты неизменяемы: одинаковый повтор подтверждается без дубля, изменённый — отклоняется. Ревизия запуска остаётся исходной при последующем изменении плана.

Журнал команд находится в профиле enrollment, хранит результаты до успешной передачи и сохраняет завершённые записи для защиты от повтора. Повреждённая запись не воспроизводится и не блокирует другие команды; предупреждение остаётся на агенте. Предел — 10000 записей: при заполнении новые удалённые команды не принимаются, локальное расписание работает. Журнал нельзя удалять ради повторного исполнения прежней команды. Для переноса/восстановления профиля нужно сохранять его вместе с историей; восстановление устаревшего состояния требует сверки истории перед удалёнными запусками.

## Схема и совместимость

Схема сервера **6** добавляет только `server_remote_runs` и индекс. Миграция выполняется общей транзакцией и advisory-lock; отказ откатывает таблицу и номер. Перед обновлением нужен штатный проверенный снимок PostgreSQL/настроек/ключей. Старое приложение не запускается поверх схемы 6: для возврата восстанавливаются соответствующие данные и бинарные файлы. Старые теги и установщики не меняются.

Возможности: `managed-secrets-v1`, `backup-age-v1`, `remote-runs-v1`; их заявляет инициализированный Managed-хост. Старый агент не получает неподдерживаемый защищённый план или план с новым контролем возраста. Базовые подтверждения ревизий и идемпотентная доставка отчётов сохранены.
