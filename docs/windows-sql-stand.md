# Стенд полноценного MS SQL на Windows

Workflow **Verify full Windows SQL engine** устанавливает отдельный SQL Server Express на одноразовый GitHub-hosted Windows runner. Локальный запуск установщика на пользовательском компьютере запрещён самим сценарием. Существующие экземпляры SQL не заменяются.

Установочные файлы загружаются с официального адреса Microsoft. Проверяется подпись Microsoft, в отчёте сохраняются SHA-256 загрузчика и полного дистрибутива. Версия установленного движка берётся из SERVERPROPERTY; изменяемая ссылка на установщик не считается закреплённой версией SQL. LocalDB явно отклоняется.

Проверяется следующий набор:

- Полный движок в смешанном режиме входа, TCP на loopback-интерфейсе, TLS с проверкой выданного для стенда сертификата. Публичный порт и правило брандмауэра не открываются.
- Локальный Windows-вход временного пользователя через Shared Memory и SQL-вход по TCP из его Windows Vault. Проверка запускается задачей Windows с парольным входом; исходная учётная запись runner не подменяет исполнителя. Windows/TCP на текущем runner возвращает ошибку недоверенного домена и не считается проверенным. Неверный SQL-пароль и несовпадение имени сертификата должны отклоняться. Отдельно проверяется явная настройка разрешения недоверенного сертификата и последующее корректное подключение.
- Создание агентом двух реальных BACKUP COPY_ONLY с CHECKSUM, доставка в каталог копий, SHA-256, RESTORE VERIFYONLY и восстановление в другие базы с проверкой строк Unicode.
- Независимые внешние полная, дифференциальная и журнальная копии. Коллектор должен прочитать реальные типы D/I/L из msdb, вернуть пустую историю для другой базы и ошибку при явном запрете чтения журнала. Следующий корректный опрос должен пройти; каталог копий агента не меняется.

SQL-логин стенда получает db_backupoperator в тестовой базе и dbcreator для VERIFYONLY. Проверка не является рекомендацией минимальных прав для рабочей установки.

Основное подключение использует 127.0.0.1 с этим IP в SAN сертификата. Отдельное случайное имя в зоне .invalid временно сопоставляется тому же IPv4-порту, но отсутствует в сертификате: SQL-вход должен отклонить его по умолчанию и подключиться только при явном разрешении недоверенного сертификата. Удаляется только собственная добавленная строка hosts. Перед созданием баз проверяется имя установленного экземпляра; при несовпадении запись и очистка баз не выполняются.

В артефакт попадают sql-engine-result.json и sql-media-provenance.json. При ошибке подготовки добавляется sql-setup-result.json с этапом, причиной и отфильтрованными сообщениями запуска SQL при отказе TLS. Пароли, базы, архивы, закрытые ключи, установочные файлы и журналы установки не загружаются. Созданные базы, логин и доверие тестовому сертификату удаляются; одноразовый runner затем уничтожается GitHub.

## Границы результата

Успешный отчёт имеет scope **full-engine-local-selected-task-user**, remoteHostVerified **false**, serviceIdentityVerified **false**, windowsTcpVerified **false**. SID исполнителя сверяется с созданным пользователем и записывается в отчёт. Windows-вход использует Shared Memory, SQL-вход — TCP с TLS. Это полноценный SQL Server на Windows, но клиент и сервер находятся на одном компьютере. Задача Windows не выдаётся за службу SP Backup; локальный Windows-вход не выдаётся за сетевой. Этот прогон не закрывает пункт 4.3: отдельно нужны другой сервер, сетевое сопоставление серверного и агентского путей, Windows/SQL-вход по TCP под учётной записью службы и доставка через SMB.

Результат принимается только по фактическому успешному JSON для конкретного source. Наличие workflow, успешная сборка или чтение msdb сами по себе не являются подтверждением восстановления копии.

## Подтверждённый прогон 9 ноября 2026 года

На исходнике **d280033b32a541398ae6ae5c6d29e02b20e96cc3** [прогон полного SQL](https://github.com/sanekman/1C-Backup/actions/runs/42615713087) завершился успешно. Фактический движок: **17.0.1000.7 Express Edition (64-bit)**. Это SQL Server Express, не LocalDB.

Подтверждены локальный Windows-вход через Shared Memory, SQL-вход по TCP/TLS с Windows Vault, отказ неверного пароля и неверного имени сертификата, явное разрешение недоверенного сертификата и восстановление корректного подключения. Обе реальные копии прошли SHA-256, VERIFYONLY/CHECKSUM и восстановление в другие базы с точным числом строк и проверкой Unicode.

Прочитаны реальные Full/Diff/Log из msdb. Штатный опрос сохранил историю, зафиксировал запрет чтения, затем восстановился без дубликатов. Проверены типы/время последних копий, просрочка при оценке будущего времени и смена базы на источник без копий. Каталог резервных копий агента не изменён.

Артефакт **13672687741**, SHA-256 ZIP **af89b3325cf502333e59ec80d48dc28fe5942e30558355cb3ed6c9e9f2610add**, сверены источник, успех всех пяти групп и ограничения scope. SHA-256 полного подписанного дистрибутива Microsoft: **74AA90C11202A5524E769B9BC22531BAEF22D91E9B2D2E8C3CB99E89A65C5297**. Базы, архивы и пароли в артефакт не входят.

Windows/TCP, другой компьютер и служба SP Backup этим результатом не подтверждены. Ошибка Windows/TCP «недоверенный домен» на runner остаётся ограничением стенда, а не успешной проверкой. Пункт 4.3 целиком остаётся открытым.
