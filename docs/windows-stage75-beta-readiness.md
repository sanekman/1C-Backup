# Пункт 7.5. Готовность SP Backup к beta

По состоянию на 18 ноября 2026 года (Владивосток) технические результаты
по выпускам **Windows alpha.39** и **Server preview.14** сведены.
Пользователь подтвердил успешное обновление до preview.14 и проверку панели на CT 107.
Широкая beta ожидает приёмки целевых Windows-стендов и подписи установщиков.

### Каталог автообновления агента

В `176bba118a456d765d203514d08e2d62c839a6a9` агент читает каталог GitHub
страницами по 10 релизов и выбирает максимальную подходящую версию после
чтения всех страниц. Лимит 1 МиБ применяется к каждому ответу. 33 теста на
.NET 10.0.13 подтверждают выбор версии при суммарном каталоге свыше 1 МиБ,
сохранение фильтра каналов и отказ при слишком большой отдельной странице.
Прошёл полный CI кода ветки с Windows- и Linux-тестами и установкой
собранного пакета. [Прогон ветки](https://github.com/sanekman/1C-Backup/actions/runs/44319266683).

Штатный клиент с этим исправлением выбрал alpha.39 для alpha.16, скачал
65 734 201 байт с SHA-256 из таблицы, повторно использовал проверенный файл
и завершил проверку установленной версии без повторного предложения alpha.39.
Прогон выполнен в GitHub Actions на Linux с runtime 10.0.15. Исправление входит
в рабочую ветку и ожидает следующего выпуска агента. [Проверка каталога и скачивания](https://github.com/sanekman/1C-Backup/actions/runs/44318624707).

При следующей публикации отдельно проверить переход со штатного alpha.39:
установленный alpha.39 запрашивает список одним ответом с лимитом 1 МиБ.

## Приёмка CT 107 и NAS

### CT 107

**Принято со слов пользователя.** После публикации preview.14 пользователь
сообщил, что обновление и проверка панели прошли успешно. Подробный журнал,
исходная версия и сведения о переносе тестового агента не приложены.

1. До обновления запишите текущую версию и выберите одного знакомого агента,
   его задание и исторический запуск для сравнения.
2. Откройте **Настройки → Обновление сервера → Проверить обновления**.
   Выберите **0.1.0-preview.14**, дождитесь подтверждения установки и запишите
   путь к комплекту возврата. Если панель временно недоступна, дождитесь
   запуска системной задачи и повторно откройте страницу.
3. Откройте Dashboard, проверьте цвета связи и результатов, кнопку
   «солнце / луна», раскрытие и сворачивание папок. Для тестового агента
   подтвердите перенос между тестовыми папками и верните его в исходную.
   При отсутствии тестового агента проверьте вывод исходной и целевой папок
   и нажмите «Отмена» в диалоге переноса.
4. Проверьте, что прежние агент, задание и исторический запуск видны.
   Повторно нажмите **Проверить обновления** и убедитесь, что сохранены
   итог установки и путь к комплекту возврата.

В результате достаточно указать версию до и после, итог обновления, результат
переноса и сохранность агента, задания, истории и комплекта возврата.
[Инструкция обновления LXC](server-proxmox.md#подключить-обновление-из-настроек).

### Внешний NAS

Пользователь подтвердил успешное прохождение сценария в своём окружении.
[Результат приёмки](windows-stage7-acceptance.md#внешний-nas).

1. В Windows-агенте откройте **Резервные копии**, выберите задание **Файлы
   и папки** и запись с расположением именно на внешнем NAS. Сравнивайте
   с файлами, содержимое которых известно на дату этой копии. Если таких
   файлов нет, создайте небольшое ручное задание для тестовых файлов и
   отдельной папки на NAS.
2. Нажмите **Восстановить файлы…**, проверьте в диалоге выбранную копию
   и укажите новую пустую локальную папку. Агент создаст внутри новый
   подкаталог. Если кнопка недоступна при работающем исполнителе, дождитесь
   завершения задач и приостановите фоновую работу в согласованное окно.
3. Сверьте имена, число и содержимое восстановленных файлов. Для точной
   сверки двух файлов можно сравнить хеши `Get-FileHash -Algorithm SHA256`.
   Если исполнитель был остановлен, верните прежний режим работы.

Для записи результата укажите версию агента, тип доступа к NAS, полная ли
копия, число сверенных файлов и итог восстановления. Для инкрементной копии
зафиксируйте число архивов в цепочке. Рабочую базу 1С в этой проверке не открывают.
[Руководство восстановления файлов](user-guide.md#3-убедиться-что-копия-действительно-восстанавливается).

## Решение о выпуске

По действующим условиям широкую beta стоит отложить до появления стендов и
сертификата. Если нужен ограниченный выпуск раньше, для отдельного решения
можно рассмотреть файловые сценарии на Server 2022 и Server 2025 x64 после
проверки сохранности цепочек и достоверности доставки из пакета 1.
LXC можно описать в границах штатного Debian 13 x64 с исправленным
системным обновлятором. Создание и восстановление копий на внешнем NAS
подтверждены для окружения пользователя. Доменная работа с NAS, удалённый MS SQL
и пропущенные сценарии 1С остаются за пределами подтверждённой приёмки. Для выпуска без
подписи потребуется явное решение об изменении 7.4.

После согласования объёма стоит зафиксировать версию и состав beta, а затем
связать заметки выпуска с [установкой агента](user-guide.md),
[первым запуском Windows-сервера](server-first-start.md),
[подготовкой возврата Windows-сервера](server-upgrade-backup.md) и
[обслуживанием LXC](server-proxmox.md). Перепроверять нужно изменившиеся пакеты,
способы установки и новые условия. Пункт 7.5 в части итогового отчёта выполнен.
Решение о beta остаётся открытым.
