# Подпись Windows-дистрибутива и SmartScreen

Предупреждение «Неизвестный издатель» у preview.42 связано с отсутствием Authenticode-подписи.
ZIP, переименование EXE или собственный самоподписанный сертификат не создают доверия
Windows к публичному установщику. Отключение SmartScreen не является решением для выпуска.

Нужен сертификат **Code Signing** доверенного центра сертификации либо сервис подписи
с проверкой личности издателя, например Microsoft Artifact Signing. Это отдельная
платная услуга; доступность зависит от страны и типа заявителя. Сертификат TLS для сайта
не подходит. Закрытый ключ обычно хранится в аппаратном токене или сервисе подписи;
его и пароль нельзя передавать в чат, коммитить в репозиторий или добавлять в аргументы CI.

Доверенная подпись позволяет показать имя издателя и проверить целостность файла.
SmartScreen отдельно оценивает репутацию приложения и издателя: у нового подписанного
приложения предупреждение всё ещё возможно. Даже EV-сертификат не гарантирует его
немедленное исчезновение. Подписанный выпуск можно отправить Microsoft на анализ,
если он ошибочно блокируется. На управляемых компьютерах администратор может разрешить
доверенного издателя корпоративной политикой; это не меняет репутацию публичного выпуска.

Официальные сведения:
- [Microsoft Defender SmartScreen](https://learn.microsoft.com/windows/security/operating-system-security/virus-and-threat-protection/microsoft-defender-smartscreen/)
- [SignTool](https://learn.microsoft.com/windows/win32/seccrypto/signtool)
- [Microsoft Artifact Signing](https://learn.microsoft.com/azure/artifact-signing/overview)
- [Отправка файла Microsoft на анализ](https://www.microsoft.com/wdsi/filesubmission)

## Поддержка в сборке

`tools/windows_signing.py` использует сертификат из Windows Certificate Store и SignTool
из Windows SDK. Закрытый ключ остаётся у своего провайдера; пароль PFX в аргументах не нужен.
Это путь для Windows-машины с уже установленным сертификатом / аппаратным провайдером.
Для облачного сервиса потребуется отдельная интеграция после выбора услуги. Обычный
одноразовый GitHub runner не содержит вашего сертификата: его наличие нельзя считать
автоматическим. Текущий CI и опубликованный preview.42 остаются неподписанными.

Настройки в PowerShell на машине подписи (отпечаток сертификата не является секретом):

```powershell
$env:ONECBACKUP_SIGNING_THUMBPRINT = '<40 шестнадцатеричных символов>'
$env:ONECBACKUP_REQUIRE_SIGNING = 'true'
$env:ONECBACKUP_SIGNTOOL = 'C:\Program Files (x86)\Windows Kits\10\bin\<версия SDK>\x64\signtool.exe'
# По умолчанию CurrentUser\My; при необходимости:
# $env:ONECBACKUP_SIGNING_STORE = 'LocalMachine'
python tools/build_windows_distribution.py
python tools/build_windows_installer.py
```

По умолчанию используется HTTPS RFC 3161 timestamp `https://timestamp.digicert.com`.
Другой HTTPS endpoint можно задать `ONECBACKUP_SIGNING_TIMESTAMP`.
Сначала подписываются EXE интерфейса и агента и три DLL приложения, затем формируется ZIP
и его SHA-256. Установщик подписывается после компиляции, до формирования SHA-256
и `update-manifest.json`. Каждая подпись проверяется SignTool по Authenticode-политике,
а PowerShell дополнительно проверяет статус доверия, точный отпечаток издателя и timestamp.
Ошибка подписи или проверки останавливает сборку. При `ONECBACKUP_REQUIRE_SIGNING=true`
отсутствие сертификата также останавливает сборку; подмена неподписанным выпуском запрещена.

Без настроек подписи остаются разрешены неподписанные сборки разработки. Не следует
выдавать их за подписанные или обещать отсутствие SmartScreen. После подключения
сертификата нужно выпустить новую версию с новыми хешами и проверить установку,
службу и обновление на Windows. Старые опубликованные артефакты не перезаписываются.

В Linux проверяются блокировка обязательной подписи без сертификата, отказ от
неподдерживаемой платформы и расчёт хешей после имитации подписи. Реальная подпись,
доверие сертификату, timestamp и отображение SmartScreen здесь не проверены:
нужны Windows и действующий сертификат издателя.

## Проверка диалога NSIS

После изменения проверки каталога запустите на изолированной Windows-машине с NSIS:
`python tests/distribution/nsis_directory_smoke.py --compiler "<путь к makensis.exe>"`.
Тест компилирует минимальный диалог с настоящей функцией проверки из установщика,
проверяет активность кнопки для трёх корректных путей и отказ для корней / рабочего
профиля в silent-режиме. Файлы приложения не устанавливаются. Это проверка диалога,
а не замена полной проверки установки и службы. В Linux/Wine запуск этого GUI-теста
не подтверждён; результат не следует считать проверенным на настоящей Windows.
