# SP Backup Server 0.1.0-preview.9

Накопленный серверный пакет после preview.8. SDK **10.0.402**, встроенный runtime **10.0.13**, PostgreSQL **17**. Предварительный выпуск; Windows-установщик **не подписан**. Для новых функций агента рекомендуется **alpha.35**; минимальная версия обычного мониторинга остаётся alpha.20.

- **Центральное управление файловыми заданиями.** Сводка проблем по папкам, подтверждённые ревизии с историей и возвратом, несколько локальных/UNC-назначений, контроль возраста копии и локальные защищённые привязки. Прежний принятый план сохраняется при ошибке новой ревизии и работает без связи. Пароли задаются в Windows и в серверный план не передаются. Серверный мастер не управляет SQL, DT, FTP, WebDAV и Google Drive.
- **Удалённый запуск.** Команды с ограниченным сроком, отдельные состояния очереди/принятия/исполнения и защита от повтора после потери ответа или перезапуска. Принятая команда и успешная доставка — разные события; состояние каждого хранилища показано отдельно.
- **Обслуживание Windows-сервера.** Итог установки, проверка полного состава снимка, комплект возврата программы вместе с данными и локальная диагностика служб, места и HTTPS при недоступной панели. Ошибка настройки или миграции даёт ненулевой результат установщика. Возврат штатной установки ограничен тем же компьютером, путями и локальными NTFS-дисками; DPAPI и внешняя БД не переносятся.
- **Docker Compose одной командой.** Из checkout с новой командой: `./deploy/server/update.sh`. Получение серверного тега, изолированная сборка образа, комплект прежнего образа/БД/данных/секретов, миграция и доверенная HTTPS-проверка. При обычной ошибке миграции или готовности выполняется автоматический возврат с ненулевым результатом обновления. PostgreSQL не пересоздаётся и не обновляет major-версию. Повтор установленного тега ничего не меняет. [Требования, параметры и границы](docs/server-container-update.md).

**Схема БД: 5 → 6.** Перед обновлением сохраните БД, данные, настройки, сертификаты и прежний комплект программы. Старый сервер нельзя запускать поверх новой схемы; для возврата нужны соответствующие бинарные файлы и БД. Для preview.8 новый инструмент подготовки Windows-снимка берётся из ZIP preview.9 **до** запуска нового установщика. [Инструкция Windows](docs/server-upgrade-backup.md), [снимки](docs/server-snapshots.md).

**Обновление контейнера:** после получения команды в checkout выполните `./deploy/server/update.sh --version server-v0.1.0-preview.9`. Для нестандартных имени проекта и `.env` передайте прежние параметры. Нужны Linux, Git, Python 3.11+, OpenSSL и Docker Compose v2. Каталог данных и файлы секретов должны соответствовать штатному стеку. Комплекты содержат секреты и остаются на хосте с закрытым доступом. Жёсткое выключение хоста/`kill -9`, внешняя БД и другая топология требуют отдельного восстановления; автоматическое возобновление после перезагрузки не заявляется.

**Проверки:** исходный пакет этапов 5–6 принят на Windows/Linux; команда обновления прошла 28 Python-проверок и 14 Compose-сценариев, включая настоящий CLI, повтор без изменений и возврат после контролируемых ошибок с настоящим изменением БД/тома. Новые Windows/Linux-пакеты preview.9 публикуются штатным pipeline после проверки версий, установки, обновления и восстановления. [Этап 5](docs/windows-stage5-acceptance.md), [этап 6](docs/windows-stage6-acceptance.md), [проверка команды](docs/server-container-update.md).

Полная Windows-матрица, домен/внешний NAS, независимый сценарий новичка и сертификат подписи остаются открытыми условиями beta. Пропуски настоящей 1С и отсутствие удалённого MS SQL-стенда сохраняются. Telegram/MAX — отдельная задача. Прежние выпуски, теги и дистрибутивы не заменяются; PR №2 остаётся черновиком, слияние не выполняется.

# SP Backup Server 0.1.0-preview.8

Расширенные результаты SQL-наблюдений для Windows-агента alpha.34. SDK **10.0.402**, встроенный runtime **10.0.13**, PostgreSQL **17**.

- **Контроль свежести.** Панель показывает допустимый возраст успешной копии и предупреждение об отсутствии свежей копии. Проверка выполняется агентом; состояние относится к моменту его передачи. При потере связи проверяйте также связь с агентом.
- **Последние копии по типам.** В карточке задания раскрывается время последней успешной полной, дифференциальной копии и копии журнала транзакций MS SQL. Отсутствие типа не считается самостоятельной ошибкой и не подтверждает неполную цепочку.
- **Расшифровки опроса.** Для сертификата, входа, прав, тайм-аута, соединения и чтения журнала выводятся понятная причина и рекомендация. Исходный текст исключения агента в серверный снимок не передаётся.
- **Согласованное состояние выбранной базы.** После смены базы сервер использует текущий результат агента, а не копию прежней базы из общей истории. Исторические отчёты сохраняются; старые агенты продолжают отображаться прежним способом.
- Скрипт создания Proxmox LXC по умолчанию выбирает preview.8. Существующие контейнеры сам скрипт не обновляет.

Схема PostgreSQL остаётся **5**: при переходе с preview.6/preview.7 новой миграции нет. Перед обновлением сохраните согласованную копию БД, настроек и ключей. Установите соответствующий новый пакет и проверьте подключение агентов. Новые сведения требуют alpha.34; параметры наблюдения задаются в Windows-агенте.

Проверяются Windows/Linux, PostgreSQL/HTTPS, установщики, Compose и создание LXC. Прежние теги, дистрибутивы и файлы выпусков сохраняются.

# SP Backup Server 0.1.0-preview.7

Задания наблюдения SQL и резервная копия Windows-сервера. SDK **10.0.402**, встроенный runtime **10.0.13**, PostgreSQL **17** в Windows-установщике.

**Перед обновлением сохраните согласованную копию БД, настроек, сертификатов и ключей.** С preview.6 схема PostgreSQL остаётся **5**. Для более ранних выпусков применяются прежние последовательные миграции; подготовка описана в [инструкции перед обновлением](docs/server-upgrade-backup.md).

- **Наблюдение SQL как задание.** В карточке агента наблюдения отображаются рядом с заданиями копирования: название, интервал, включение опроса, его состояние и последний результат. Они также видны на странице заданий. Настройки наблюдения меняются в Windows-агенте **alpha.33**; сервер показывает состояние и историю. Сохраняется отображение источников от старых агентов.
- **Отчёт внешней копии отделён от доставки.** В истории указаны источник подтверждения и размер по внешнему отчёту; наблюдение не показывается как доставка агентом в «Хранилище 1». Ошибка чтения журнала не уничтожает прежние результаты. Старые ID и ранее принятые отчёты не переписываются.
- **Копия, проверка и восстановление Windows-сервера.** Для штатной установки добавлены пункты меню Пуск с выбором папки. Холодная копия включает PostgreSQL, настройки, HTTPS-сертификаты и ключи, с временной остановкой и возобновлением служб. Проверяются состав и SHA-256, свободное место с запасом 1 ГиБ и приватные права доступа. Занятые/вложенные папки, перезапись копий и конфликт с установщиком отклоняются. При восстановлении прежние данные сохраняются отдельно.
- **Ограничение восстановления:** тот же компьютер, установленная Windows и тот же комплект программы. Это не перенос на другую машину и не возврат бинарных файлов к старой версии. Для выполнения нужны права администратора, локальная NTFS-папка и перерыв в работе сервера. Подробные шаги: [копия Windows-сервера](docs/server-snapshots.md).
- Скрипт Proxmox в рабочей ветке и Linux-пакете выбирает **preview.7**. Копирование Windows-сервера не добавляет аналогичную операцию Linux; для него по-прежнему нужна согласованная резервная копия PostgreSQL, настроек и ключей.

Проверяются 156 серверных тестов и готовые пакеты на Windows/Linux, Compose/HTTPS/PostgreSQL, установка Proxmox и Windows, переустановка и полный цикл копии/проверки/возврата Windows-сервера через Windows PowerShell 5.1. Отдельно проверены сохранность данных, токена агента и DPAPI-ключей. Это не подтверждает перенос между компьютерами или отключение питания во время восстановления. Установщик пока не подписан. Существующие теги, дистрибутивы и файлы выпусков не заменяются.

# SP Backup Server 0.1.0-preview.6

Накопленный выпуск после preview.5. SDK **10.0.402**, встроенный runtime **10.0.13**, PostgreSQL **17** в Windows-установщике.

**Перед обновлением: схема PostgreSQL изменяется с 4 на 5.** Остановите сервер и сохраните согласованную проверенную копию БД, настроек и сертификатов. Для Windows есть [пошаговая инструкция](docs/server-upgrade-backup.md). Для возврата на preview.5 нужна совместимая БД схемы 4; прежнюю программу нельзя запускать поверх схемы 5. Более старые схемы обновляются последовательно.

- **Папки и подпапки агентов.** Дерево организаций/площадок, просмотр ветки вместе с потомками и раздел «Без папки». В приглашении можно выбрать папку, создать новую подпапку и задать понятное имя агента независимо от имени компьютера. Существующие агенты переименовываются и перемещаются без смены ID, токена, заданий и истории. Удаляются только пустые папки; защищены циклы, одинаковые имена одного родителя и конкурентные изменения.
- **Часовой пояс панели.** В разделе «Сервер» выберите общий пояс отображения дат, включая российские города. Настройка сохраняется и применяется без перезапуска. Время API/БД/диагностики остаётся UTC; часы ОС и расписания агентов не меняются.
- **Причины и что делать.** Для новых отчётов alpha.31 рядом с результатом задания, историей и хранилищами показаны причина, этап и действие администратора. Передаются только разрешённые коды и числовые сведения. Для прежних отчётов без причин панель предлагает открыть подробности на компьютере агента.
- **Состояние сервера.** На главной странице и в разделе «Сервер» видны предупреждения: место ниже 1 ГиБ / 256 МиБ, недоступные сведения о диске, сертификат с остатком до 30 дней, истёкший или ещё не действующий. Проверяется том папки данных и сертификат действующего процесса. Замена/удаление PFX после запуска не ломает панель; новый PFX применяется после перезапуска. Внешний сертификат обратного прокси и диск отдельной PostgreSQL проверяйте отдельно. Автоматической очистки нет.
- **Установщик Proxmox.** В Linux-архив включён скрипт нового непривилегированного Debian 13 LXC с PostgreSQL17 и HTTPS. Он проверяет размер/SHA-256 выпуска и явно создаёт базу UTF8 даже при SQL_ASCII в кластере. Существующая несовместимая база отклоняется без преобразования; её перенос требует отдельной резервной копии. Скрипт не обновляет установленный сервер и не удаляет контейнеры/данные при ошибке. [Инструкция](docs/server-proxmox.md).

Клиент alpha.31 нужен для новых причин; папки и пояс не требуют обновления агента. Managed и файловый веб-мастер сохраняют ограничения preview.5: другие источники, шифрование и защищённые секреты из панели пока не назначаются. Удалённый ручной запуск и резервное копирование самого сервера остаются следующими этапами.

Проверены **156 серверных тестов без пропусков и 1 проверка готового пакета на каждой платформе Windows/Linux**, Windows-установка/переустановка, Compose HTTPS/PostgreSQL и 16 сценариев нативной установки Debian13/PostgreSQL17. В нативном Proxmox-стенде systemctl записывается; настоящий Proxmox/systemd и вся матрица Windows этим не подтверждаются. Установщик пока не подписан. Существующие теги, ветки дистрибутивов и файлы прежних выпусков не заменяются.

# SP Backup Server 0.1.0-preview.5

Управление файловыми заданиями Windows и история серверных планов. SDK **10.0.402**, встроенный runtime **10.0.13**, PostgreSQL **17** в Windows-установщике.

**Перед обновлением: схема PostgreSQL изменяется с 3 на 4.** Остановите сервер и сохраните согласованную проверенную копию БД, настроек и сертификатов. Для штатной Windows-установки есть [пошаговая инструкция](docs/server-upgrade-backup.md). При обновлении со схемы 2 также применяется миграция 2 → 3. После успешного перехода preview.4 нельзя запускать поверх схемы 4: для возврата нужна соответствующая копия БД схемы 3.

- **Веб-мастер файловых заданий:** создание, изменение, отключение и удаление, файлы/папки и ZIP файловой 1С, полные/инкрементные копии, день полной копии и до восьми локальных/UNC-хранилищ. «Создать на основе…» создаёт отдельное задание с выключенным расписанием; название подставляется по источнику. Конфликт редактирования отклоняется без перезаписи чужих изменений.
- **Работа Windows-агента alpha.30:** Managed исполняется фоновым агентом или службой, принятый план сохраняется после перезапуска и исполняется без связи. Подключение и смена режима выполняются через интерфейс Windows без ручного ввода технических ключей. Принятие настроек и результат копирования различаются.
- **История 100 планов:** дата, автор, просмотр полного набора настроек и возврат прежнего плана новой ревизией. Возврат защищён текущей ревизией и подтверждением; аудит и настройки записываются атомарно. При миграции сохраняется только действующий план: прежние изменения не восстанавливаются задним числом. Начатая копия, история запусков и архивы не удаляются.

**Ограничения веб-мастера:** другие источники, шифрование и защищённые привязки секретов пока не назначаются с сервера. Отдельный NAS-логин alpha.30 настраивается в локальном мастере Windows; не вводите пароль в UNC-путь. Удалённый ручной запуск из панели остаётся следующим этапом. История планов и диагностический ZIP не заменяют резервную копию сервера.

Для серверного исполнения требуется **alpha.30**; старые агенты сохраняют режим мониторинга. Минимальный клиент мониторинга — **alpha.20**. Проверены по 112 серверных тестов и отдельной проверке готового пакета на Windows/Linux, Compose HTTPS/PostgreSQL, Windows-установщик, переустановка и перезапуск. Managed с production-сервером/PostgreSQL и нативный SCM с контролируемым HTTPS-сервером проверяются отдельными сценариями; они не подтверждают полную матрицу Windows или реальные доменные перезагрузки.

Установщик пока не подписан. Существующие теги, ветки дистрибутивов и файлы прежних выпусков не заменяются.

# SP Backup Server 0.1.0-preview.4

Накопленный выпуск Windows-сервера мониторинга после preview.3. SDK **10.0.402**, встроенный runtime **10.0.13**, PostgreSQL **17** в Windows-установщике.

**Перед обновлением: схема PostgreSQL изменяется с 2 на 3.** Остановите сервер и сохраните согласованную копию БД, настроек и сертификатов. Для штатной Windows-установки есть [пошаговая инструкция](docs/server-upgrade-backup.md). Миграция добавляет журнал предложений/подтверждений, сохраняя агентов, настройки и историю; её откат при ошибке проверен. После успешного перехода прежний сервер со схемой 2 нельзя запускать поверх схемы 3: для возврата нужна соответствующая копия БД.

- **Установка Windows:** светлая/тёмная тема панели, выбор порта HTTPS и отдельное разрешение открыть его в брандмауэре. Имя системы мониторинга и HTTPS-адрес подключения задаются отдельно. Прежние настройки и правило брандмауэра сохраняются при переустановке.
- **Обслуживание:** смена пароля администратора с завершением прежних сеансов, журнал действий и безопасный ZIP диагностики. Диагностика не содержит конфигурацию, БД, токены и закрытые ключи и не заменяет резервную копию.
- **Подготовка управления заданиями:** ограниченный административный API для файлов/папок и ZIP файловой 1С с одним локальным/UNC-хранилищем. Строгая проверка всего набора, обязательный If-Match, конфликт без перезаписи и атомарный аудит. Остальные источники и защищённые привязки этим начальным API не принимаются.
- **Подтверждения настроек:** отдельно видны желаемая, проверенная/сохранённая и отклонённая конфигурации. Предложение связано с документом, ревизией и текущим подключением; повторы и ответы не по порядку не отменяют принятие. Прежний кэш сохраняется при отказе; очередь клиента повторяет ответы после перезапуска.

**Полное серверное управление ещё не подключено:** веб-мастер и реальное исполнение Managed в службе остаются следующими этапами. Подтверждение означает проверку и сохранение настроек, а не запуск расписания или создание копии. Нынешний агент не объявляет Managed-исполнение, неподдерживаемые задания ему не выдаются. Мониторинг автономных агентов продолжает работать; для исправлений клиента рекомендуется **alpha.29**, минимальный клиент мониторинга — **alpha.20**.

Проверяются 72 серверных теста на Windows/Linux, готовые пакеты, настоящий Compose HTTPS/PostgreSQL, Windows-установка, переустановка и перезапуск. Установщик пока не подписан. Существующие теги, ветки дистрибутивов и файлы прежних выпусков не заменяются.
