## Обновление контейнера и ограничения

После публикации штатный клиент выбора выпуска подтвердил:
`latest_version() == server-v0.1.0-preview.9`, серверный тег получен через Git
и разрешён в **1d1b070e96c5b020e408db3099c75d86d01f583e**.

Из checkout с новой командой:

```sh
./deploy/server/update.sh --version server-v0.1.0-preview.9
```

Без `--version` выбирается последний опубликованный серверный выпуск.
[Параметры .env/проекта, комплект возврата и границы](server-container-update.md).
Перед обновлением Windows используйте [подготовку снимка](server-upgrade-backup.md);
в preview.8 инструмент подготовки берётся из ZIP preview.9 до запуска установщика.

Открытые условия этапа 7 сохраняются: неподтверждённая матрица ОС, домен/внешний
NAS, UAC/настоящая перезагрузка, независимое прохождение новичком и сертификат
подписи. Пропущенная настоящая 1С, отсутствие удалённого SQL-стенда и отдельная
задача Telegram/MAX не объявляются завершёнными. Нативный Linux/systemd и новые
архитектуры не принимаются по факту Compose-проверки.

Прежние server-preview.8, Windows alpha.35, их теги и ветка дистрибутива
server-preview.8 сохранены; refs до и после публикации совпали. Старые файлы
выпусков и теги не заменялись.
