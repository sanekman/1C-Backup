# Задания Windows-агента в панели сервера

Мастер доступен в разрабатываемой версии после alpha.29 / server preview.4. Эти выпуски ещё не содержат описанный интерфейс.

## Перед первым заданием

1. Установите сервер, войдите в его HTTPS-панель и создайте приглашение через **Подключить агент**. [Первая установка сервера](server-first-start.md).
2. На компьютере, где находятся исходные файлы, установите Windows-агент. Откройте **Настройки → Подключения → Подключить по приглашению…**, перенесите адрес, код и отпечаток сертификата.
3. Там же выберите **Задания с сервера**, нажмите **Применить режим**, затем **Включить автоматически**. Для работы без входа пользователя установите службу. Локальные задания при переключении сохраняются.
4. Вернитесь в панель сервера, откройте карточку этого компьютера и нажмите **Настроить задания на сервере**. Затем **Создать задание**.

Настройки можно подготовить, пока компьютер выключен. Агент получит их после включения и соединения с сервером. При отсутствии связи действует последний принятый план. Подключение только для мониторинга само по себе не включает серверные задания.

## Шаг 1. Источник

Выберите **Файлы и папки** или **Файловая база 1С — архив ZIP**. Название можно оставить пустым: после нажатия **Далее** мастер подставит имя папки или файла. Для пути `C:\Базы\Бухгалтерия\1Cv8.1CD` получится **Бухгалтерия**, а не имя файла базы. Для корня `C:\` — **Диск C**.

Если вернуться и поменять источник, автоматическое название обновится. Чтобы задать своё, введите, например, **Документы бухгалтерии**: оно сохранится при изменении пути. Чтобы снова использовать имя источника, очистите название. При редактировании существующего задания его прежнее название сохраняется.

Путь относится к компьютеру **агента**, а не сервера. Примеры:

- `C:\Документы` — папка на диске агента;
- `C:\Базы\Бухгалтерия\1Cv8.1CD` — файл файловой базы 1С;
- `\\files\Базы\Бухгалтерия` — общая сетевая папка, доступная агенту.

Сервер не открывает проводник удалённого компьютера и не проверяет наличие этой папки. Полный путь можно скопировать в проводнике Windows. Не вводите адрес сайта или относительный путь.

Для файловой базы лучше закрыть 1С перед запуском. Разрешение копировать открытую базу допускает совместное чтение с предупреждением, если база действительно открыта; закрытая база сама по себе предупреждения не вызывает. Это архив файловой базы, а не выгрузка через платформу 1С. SQL, WebDAV и серверные базы 1С пока настраиваются локально.

## Шаг 2. Расписание

Выберите один вариант:

- **Только вручную** — копия по кнопке в Windows-программе при работающем агенте;
- **Каждый день** — один или несколько запусков, например `09:00, 23:00`;
- **В выбранные дни недели** — время и хотя бы один отмеченный день;
- **При запуске Windows** — один запуск за загрузку системы, когда начинает работать агент или служба.

Время относится к выбранному часовому поясу. По умолчанию используется **Время компьютера агента**: для агента во Владивостоке `23:00` означает 23:00 на этом компьютере, независимо от расположения сервера. Можно выбрать явный пояс, например **Владивосток (UTC+10)**.

Галочка **Включить расписание задания** управляет автоматическими запусками. Снятая галочка не запрещает ручную копию. Для варианта «Только вручную» время и дни не запускают задание автоматически. На следующем шаге и при возврате назад введённые значения сохраняются; переход между шагами ничего не публикует.

## Шаг 3. Хранилище

Укажите отдельную папку: например `D:\Копии` на агенте или `\\storage\Копии` в сети. Исходник, рабочая папка и папка копий не должны находиться друг внутри друга.

Для второй копии нажмите **Добавить ещё одну папку копий**. Можно указать до восьми папок: основную и семь дополнительных. Для каждой дополнительной папки укажите путь и её лимит архивов. Пустой лимит означает **как в основном хранилище**: если основной лимит изменится, дополнительная папка унаследует новое значение. Явно заданное число останется отдельным.

Для защиты от отказа диска выбирайте другой носитель или сетевое хранилище: две папки на одном диске от его поломки не защищают. Папки копий должны находиться отдельно друг от друга. Повтор того же пути с другим регистром, завершающим разделителем или вложенная папка не принимаются.

Архив создаётся один раз и доставляется во все указанные папки. Ошибка одной доставки не отменяет остальные: в истории будет **Частичная доставка**, а успешные архивы сохранятся. В карточке агента результаты пронумерованы в порядке папок в ревизии задания: основная — хранилище 1. Проверьте результат каждого хранилища, а не только общий статус.

Кнопка **Убрать это хранилище из задания** меняет только черновик. После итогового сохранения агент перестанет доставлять туда новые копии; существующие архивы не удаляются. Переход назад и изменение других полей сохраняют оставшиеся папки и их лимиты.

Для службы используйте UNC-путь `\\сервер\папка` вместо буквы подключённого сетевого диска. Пользователю службы нужен доступ к общей папке и файлам. Пароль Windows здесь не вводится. [Настройка службы и сетевого доступа](windows-service.md).

Укажите количество хранимых архивов. Для файлов и папок выберите полные копии либо полную основу и последующие изменения. Первая копия всегда полная. Последующие полные можно делать по числу архивов или в определённый день недели. Пропущенный день переносит полную копию на ближайший запуск. Ошибки отдельных файлов не должны превращать очередной инкрементный запуск в полный вне плана.

Для восстановления инкрементной копии нужна вся цепочка. Поэтому число архивов иногда временно превышает лимит: действующая цепочка сохраняется до появления новой полной основы. Файловая база 1С в этом мастере всегда получает полный ZIP.

Рабочую папку обычно оставляют пустой: агент использует свою стандартную. Если указываете её вручную, обеспечьте свободное место для архива и отдельное расположение относительно источника и копий.

## Шаг 4. Проверка и первая копия

1. Проверьте имя, путь, расписание, пояс, папку копий и режим. Кнопкой **Назад** можно исправить значения.
2. Нажмите **Сохранить задание** один раз. Сервер создаст новую ревизию плана, сохранив остальные задания.
3. Откройте **Карточку агента** и дождитесь подтверждения, что ревизия проверена и сохранена агентом. Если подтверждения нет, проверьте связь, версию и включение режима **Задания с сервера** на компьютере агента.
4. В Windows-программе выберите полученное задание и нажмите **Создать копию**. Для этого агент должен работать; расписание задания можно оставить выключенным.
5. Проверьте результат в истории, доставку в папку копий и возможность восстановления. Сохранение плана и его принятие агентом ещё не означают, что резервная копия создана.

## Изменение задания

В списке серверных заданий нажмите **Изменить**. Другие задания и их параметры сохранятся. Для временного отключения снимите галочку расписания на втором шаге.

## Новое задание на основе существующего

1. В списке заданий нужного агента найдите похожее и нажмите **Создать на основе…**. Откроется новый черновик с его источником, расписанием, рабочей папкой, режимом копирования и всеми папками хранения с лимитами. Само открытие ничего не сохраняет.
2. На первом шаге укажите другую папку или базу 1С. Название автоматически изменится по источнику; при желании введите своё. Исходное задание останется прежним.
3. На втором шаге проверьте время и дни. У нового задания галочка **Включить расписание задания** сначала снята. Включите её, если копия должна запускаться автоматически; для пробного ручного запуска можно оставить снятой.
4. Проверьте все папки копий и лимиты на третьем шаге. Если копия предназначена для другого носителя, замените пути. Они относятся к тому же Windows-агенту.
5. На последнем шаге сохраните новое задание, дождитесь принятия ревизии и сделайте пробную копию. У нового задания отдельный ID, история и инкрементная цепочка. Старые архивы не становятся его полной основой.

**Отмена** или возврат в список до сохранения оставляют план без изменений. Повторная отправка старой формы и параллельное изменение плана не создают дубль и не перезаписывают новую ревизию. Копирование настройки между разными агентами здесь не предусмотрено.

## Если план изменился или задание больше не нужно

Если другой администратор уже изменил план, сервер покажет конфликт и сохранит ваши значения в форме. Откройте актуальный список в другой вкладке, сравните изменения и повторите нужное редактирование из свежего списка. Автоматической перезаписи чужой ревизии нет. Повторная отправка старого подтверждения также не создаёт вторую ревизию.

**Удалить…** открывает отдельное подтверждение. Удаление убирает задание из будущего плана после его получения агентом. Архивы, история и уже начатое копирование сохраняются. Для отозванного агента изменение плана запрещено. Если текущая конфигурация содержит параметры, не поддерживаемые мастером, она не заменяется пустым планом.

Мастер поддерживает до восьми локальных или сетевых каталогов назначения. Шифрование, SQL/WebDAV, FTP и безопасная настройка их паролей остаются отдельными этапами. [Правила исполнения серверного плана](managed-execution.md).

## Вернуть прежние настройки

Если вы ошиблись с расписанием, папкой хранения или удалили нужное задание, откройте **История планов и возврат к прежним настройкам** в списке заданий этого компьютера.

1. Выберите ревизию по дате, автору и количеству заданий. Нажмите **Посмотреть план**. Пока вы только смотрите, настройки агента не меняются.
2. Проверьте **весь план**, а не только нужное задание: источники, папки копий, лимиты, время и дни. Возврат заменяет все серверные задания этого компьютера. Для сравнения откройте **текущие задания** по ссылке в новой вкладке.
3. Обратите внимание на включённые расписания: после принятия плана агентом они снова смогут запускать копии. Если нужно вернуть только одно задание, безопаснее создать или исправить его через мастер, сверяясь с сохранённым планом.
4. Нажмите **Опубликовать этот план новой ревизией**. Например, возврат ревизии 2 при текущей ревизии 5 создаст ревизию 6 с настройками из 2. Номера назад не переводятся. Прежний текущий план также остаётся в истории.
5. Дождитесь подтверждения агента в его карточке. Публикация ещё не означает принятия или успешного копирования. Уже начатая копия продолжит работу с настройками своего запуска.

История хранит **последние 100 ревизий на компьютер**, включая текущую. Старейшие записи автоматически удаляются при сохранении нового плана. Повторная отправка подтверждения не создаёт дубль; если другой администратор уже изменил план, сервер запретит возврат из устаревшей формы. Откройте историю заново и сравните изменения.

При обновлении на версию с историей сохраняется только действовавший на тот момент план. Изменения до обновления задним числом не восстанавливаются; для исходной записи автор указан как **Исходный план / система**. При повторном подключении того же агента история сохраняется. Для отозванного агента просмотр доступен, возврат запрещён.

Возврат плана не возвращает удалённые файлы архивов, не отменяет уже выполненную очистку и не меняет историю копирования. Это также не резервная копия БД, сертификатов и настроек самого сервера. Перед обновлением сервера выполните [подготовку резервной копии](server-upgrade-backup.md).
