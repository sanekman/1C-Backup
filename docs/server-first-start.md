# Первый запуск сервера мониторинга на Windows

Этот раздел нужен, если вы хотите видеть результаты нескольких компьютеров в одной панели. Для резервного копирования на одном компьютере сервер не обязателен: начните с [первой копии](user-guide.md).

Сервер собирает сведения о работе агентов. Файлы ваших резервных копий продолжают отправляться в хранилища, выбранные в заданиях.

## 1. Выберите компьютер для сервера

1. Выберите постоянно включённый компьютер Windows x64. Вначале удобнее проверить работу на Windows 11 или Windows Server 2022/2025 с графическим интерфейсом. Другие целевые ОС и ограничения описаны в [совместимости](windows-compatibility.md).
2. Для установки понадобится пароль администратора Windows. Внешнюю базу PostgreSQL или .NET отдельно ставить не нужно: установщик сервера включает необходимые компоненты.
3. Решите, по какому постоянному адресу компьютеры будут обращаться к серверу. Если используете уже настроенное имя компьютера, можно оставить предложенный установщиком HTTPS-адрес. Если нужен IP, подготовьте постоянный IPv4-адрес этого компьютера.
4. Чтобы посмотреть текущий IPv4, нажмите **Win + R**, введите **cmd**, нажмите Enter. В открытом окне введите **ipconfig** и нажмите Enter. В активном подключении Ethernet или Wi-Fi найдите строку **IPv4-адрес**. Пример: **192.168.1.50**. Если подключений несколько или адрес выдаётся автоматически и может поменяться, уточните постоянный адрес у ответственного за сеть перед установкой.

**Не копируйте адрес из примера буквально:** 192.168.1.50 должен быть заменён адресом вашего компьютера. Для подключения других компьютеров нельзя использовать localhost или 127.0.0.1: для каждого из них это адрес самого себя.

## 2. Подготовьте три значения

- **Имя сервера** — понятная подпись системы мониторинга, например **Бухгалтерия — основной сервер**. Это не сетевой адрес. Допустимы кириллица и пробелы. Если серверов несколько, разные имена помогут их различать.
- **Адрес сервера** — полный HTTPS-адрес, по которому агенты подключаются к этому компьютеру. Например, **https://192.168.1.50:7443/**. Здесь адрес и порт относятся к вашему серверу; порт 7443 можно оставить предложенным. Нужен именно https, не http.
- **Пароль администратора панели** — придуманный вами пароль для входа в 1C-Backup Server. Это не пароль Windows и не пароль PostgreSQL. Запишите его в надёжном месте; первоначальный пользователь панели — **admin**.

Приглашения будут содержать этот HTTPS-адрес. Установщик создаёт сертификат для указанного имени или IP. Поэтому сначала проверьте адрес, а потом устанавливайте; изменение только подписи «Имя сервера» не исправит неверный адрес подключения.

## 3. Скачайте и установите сервер

1. Откройте [список выпусков](https://github.com/sanekman/1C-Backup/releases).
2. Выберите **1C-Backup Server**, например **server-v0.1.0-preview.3**.
3. В **Assets** скачайте **1C-Backup-Server-…-windows-x64-setup.exe**. Не выбирайте обычный установщик агента, Linux-архив или Source code.
4. Запустите файл двойным щелчком и подтвердите запрос Windows на установку.
5. Оставьте предложенную папку программы. Введите подготовленные имя, HTTPS-адрес и пароль администратора с повтором.
6. Дождитесь завершения: установка включает PostgreSQL, подготовку БД, HTTPS и служб. Не закрывайте установщик во время подготовки компонентов.
7. Откройте созданный ярлык панели **на самом сервере**. Если мастер предложил открыть панель, используйте это действие.
8. Войдите с именем **admin** и своим паролем панели.

**Проверьте:** открылась панель с вашим понятным именем сервера. На системной странице есть сведения о сервере и базе данных. Если панель не открылась, перейдите к разделу 6 ниже.

Сначала работайте с панелью на самом сервере. Для открытия панели в браузере другого компьютера может понадобиться установка доверия к сертификату; это отдельный шаг. Подключение агента выполняется по приглашению с проверкой отпечатка сертификата.

## 4. Подключите первый компьютер

На сервере:

1. На странице **Агенты** нажмите **Подключить агент**. Укажите **Название приглашения**, например **Компьютер бухгалтерии**. Поле **ID существующего агента** для первого подключения оставьте пустым. Укажите срок действия, например **30** минут, и нажмите **Создать приглашение**.
2. Сохраните три значения из приглашения: **HTTPS-адрес**, **одноразовый код**, **SHA-256 сертификата**. SHA-256 — длинная строка, по которой агент проверит, что подключается именно к вашему серверу; переносите её целиком.

На компьютере, который создаёт копии:

3. Установите и откройте обычный Windows-агент 1C-Backup. Если его ещё нет, используйте [пошаговую инструкцию](user-guide.md).
4. Откройте **Настройки → Подключения → Подключить по приглашению…**. В alpha.24 найдите блок **Мониторинг на сервере Windows** на общей странице настроек.
5. Вставьте адрес, одноразовый код и отпечаток, полученные от своего сервера, и подтвердите подключение. Не заменяйте отпечаток значением от неизвестного источника, если соединение не проходит.
6. Сохраните существующие локальные задания. Для мониторинга не нужно включать экспериментальный режим «Управление через сервер».
7. Создайте ручную тестовую копию. Затем оставьте агент или службу работающими, чтобы отправка продолжалась при закрытом окне.

**Проверьте на сервере:** появился компьютер. Откройте его карточку: должны быть задания и результат тестовой копии. Передача и обновление панели занимают некоторое время, обычно до следующего обновления страницы. Само сообщение «компьютер на связи» ещё не означает успешную копию — проверьте строку результата.

## 5. Добавьте остальные компьютеры

Для каждого следующего компьютера создайте новое приглашение и повторите подключение. Не распространяйте один код как постоянный общий пароль: код одноразовый. Локальные задания и хранилища каждого агента сохраняются.

Проверяйте отдельно связь, дату последней копии, предупреждения о пропусках и доставку во все хранилища. Запись о неполной копии не означает, что все свежие файлы удалось сохранить.

## 6. Если что-то не получилось

**Панель не открывается на самом сервере:**

1. Попробуйте открыть её ярлыком ещё раз после завершения установщика.
2. Нажмите **Win + R**, введите **services.msc**, нажмите Enter. Найдите **1C-Backup Server** и **OneCBackupServerDatabase**, созданные установщиком, и проверьте, что они запущены. Не останавливайте другие службы PostgreSQL, если на компьютере есть посторонние базы.
3. Сохраните точный текст ошибки, адрес из строки браузера и примерное время. Чтобы открыть стандартную папку данных, нажмите **Win + R**, вставьте **%PROGRAMDATA%\OneCBackupServer** и нажмите Enter. Здесь найдите **setup.log**, а журналы приложения — в **data\logs**. Если при развёртывании меняли папку данных, используйте выбранное тогда расположение.
4. Повторный запуск того же установщика может продолжить подготовку существующей конфигурации; он сохраняет администратора и базу. Не удаляйте вручную папку БД ради повторной установки.

**Агент не подключается:**

1. Сравните его адрес с настроенным HTTPS-адресом сервера. Проверьте https, имя/IP, порт и завершающий путь.
2. Убедитесь, что компьютер агента находится в сети, где доступен сервер. Имя, доступное только серверу, не подойдёт другому компьютеру.
3. Проверьте, что код приглашения ещё действует и не был использован. При необходимости создайте новое приглашение.
4. Перенесите SHA-256 целиком. При ошибке имени, срока или отпечатка сертификата сначала сверьте адрес и данные приглашения; повторный щелчок с произвольным сертификатом не является исправлением.
5. Если связь не восстановилась, сохраните диагностику агента через **Настройки → Помощь → Сохранить диагностику…** и журнал сервера с описанием шага, на котором возникла ошибка.

**Компьютер виден, а результата нет:** проверьте локальную историю агента — копия могла не запускаться или завершиться ошибкой. Затем проверьте, работает ли фоновый агент/служба. При восстановлении связи недоставленные результаты отправляются из локальной истории.

## 7. Обновление и сохранение данных

Не удаляйте постоянную папку сервера для обновления. Перед обновлением подготовьте резервную копию его БД и конфигурации по технической инструкции; простое копирование работающей папки PostgreSQL не заменяет корректную резервную копию БД. Запускайте новый установщик поверх существующей установки. Повторная установка сохраняет имя, адрес, пароль администратора, сертификат и данные.

Настройка другого порта, пути в URL, доверия удалённого браузера, Linux/Docker и состав постоянных данных: [подробная техническая инструкция сервера](server-start.md).
