# Копия перед обновлением Windows-сервера до preview.4

Preview.4 переводит БД со схемы 2 на 3. Выполните копирование **до запуска нового установщика**. Это инструкция для штатного офлайн-установщика со встроенной PostgreSQL 17 и каталогом `%ProgramData%\OneCBackupServer`. Она не заменяет отдельную процедуру резервного копирования/восстановления сервера.

Разрабатываемый пакет после preview.4 с историей планов переводит БД **со схемы 3 на 4**. До запуска его установщика также нужна проверенная копия БД, настроек и сертификатов. История начинается с действующего плана; предыдущие изменения не восстанавливаются. Возврат плана через панель не откатывает схему БД. Для возврата приложения preview.4 требуется восстановить совместимую копию БД схемы 3; старую программу нельзя запускать поверх схемы 4.

Если используется внешняя PostgreSQL, другой каталог данных, внешние сертификаты или вынесенные табличные пространства, согласованную копию этих данных должен подготовить администратор БД. Не копируйте работающую PostgreSQL как обычную папку.

1. Сохраните установщик прежней версии. Он понадобится вместе с прежней БД для возврата. Автономные агенты продолжают копировать по локальному расписанию, пока панель недоступна; серверные отчёты передадутся после восстановления связи.
2. Убедитесь, что на отдельном диске достаточно свободного места для **всего** каталога `C:\ProgramData\OneCBackupServer`. Он содержит БД, настройки и секреты. Выберите закрытую папку, доступную только администратору; не отправляйте её в чат или публичное хранилище.
3. Откройте **Службы** от администратора: Win + R → `services.msc`. Остановите сначала **OneCBackupServer**, затем **OneCBackupServerDatabase**. У обеих служб состояние должно стать «Остановлена». Если остановка не удалась, не начинайте копирование.
4. В PowerShell от администратора скопируйте весь каталог, например на диск `D:`. Папка назначения должна быть новой; замените диск, если у вас другой:

```powershell
$serverBackup = 'D:\SP-Backup-Server-before-preview4-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
if (Test-Path -LiteralPath $serverBackup) { throw 'Выберите новую папку копии.' }
if ((Get-Service OneCBackupServer).Status -ne 'Stopped' -or
    (Get-Service OneCBackupServerDatabase).Status -ne 'Stopped') { throw 'Сначала остановите обе службы.' }
robocopy "$env:ProgramData\OneCBackupServer" $serverBackup /E /COPYALL /DCOPY:DAT /XJ /R:1 /W:1
if ($LASTEXITCODE -ge 8) { throw 'Копирование завершилось ошибкой. Не обновляйте сервер до исправления.' }
Write-Host "Копия находится: $serverBackup"
```

5. Проверьте отчёт robocopy: не должно быть пропущенных из-за ошибок файлов. В копии должны присутствовать `server.json`, `connection-string.txt`, `server.pfx`, `certificate-password.txt`, каталог `data` и каталог `postgresql` с `PG_VERSION`. Проверьте права доступа папки копии. Наличие файлов само по себе не подтверждает успешное восстановление — для важных данных отдельно проверьте возврат на изолированном стенде.
6. Только после успешного копирования запускайте новый установщик. Он запустит службы. Откройте панель по прежнему адресу, проверьте вход, список агентов, историю и свежий отчёт от агента. Если отложили обновление, запустите сначала `OneCBackupServerDatabase`, затем `OneCBackupServer`.

При сбое миграции её транзакция откатывается. После **успешной** миграции нельзя вернуть прежний EXE и оставить новую БД: возврат требует прежней версии программы и соответствующей согласованной копии данных. Не смешивайте файлы разных копий и не удаляйте рабочий каталог, пока не подготовлен проверенный план восстановления.
