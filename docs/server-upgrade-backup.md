# Обновление Windows-сервера и проверенный возврат

Инструкция для пакета этапа 6 из PR №2. Последний публичный сервер — **preview.8**; существующие выпуски не заменяются. Новые пункты меню и полный комплект возврата появятся в следующем выпуске. Штатная установка: тот же Windows-компьютер, встроенная PostgreSQL 17, прежние пути программы и данных, локальные NTFS-диски. Для внешней БД, сертификатов, табличных пространств и переноса Windows нужна отдельная процедура.

Текущая программа использует схему **6**, публичный preview.8 — **5**. Установщик выполняет миграции транзакционно. Старую программу нельзя запускать с уже обновлённой БД. Обычная [копия данных](server-snapshots.md) не возвращает файлы программы.

## До обновления

1. Выберите время обслуживания: панель и приём отчётов ненадолго остановятся. Агенты продолжают принятый план без связи и передадут очередь позже.
2. Сохраните установщик прежнего выпуска. Откройте **Пуск → SP Backup Server → Подготовить обновление сервера**. Подтвердите запрос администратора, выберите отдельный локальный NTFS-диск. Нужны объём программы, всего каталога данных и ещё 1 ГиБ; свободное место не резервируется от других программ. Старые комплекты не перезаписываются.
3. Дождитесь окончания копирования и SHA-256. В готовой папке находятся `snapshot.json`, `data`, `program` и отдельный `Server-Snapshot.ps1` для аварийного возврата. Отсутствие `snapshot.json` означает незавершённый комплект. Копирование программы проверяется до остановки служб; данные PostgreSQL копируются после её корректной остановки. Службы возвращаются к исходному состоянию.
4. Откройте **Проверить комплект возврата**, выберите готовую папку. Проверка не останавливает службы, сверяет файлы и папки данных и программы, компьютер и пути. Она работает и после смены установленной версии. Содержимое `program` включает .NET runtime, зависимости, PostgreSQL, скрипты и файлы удаления программы.
5. Комплект содержит пароли, токены, ключи и сертификат. Доступ — только Администраторы и SYSTEM. Не отправляйте его в чат или поддержке. Кроме локального комплекта нужна отдельная системная копия Windows: DPAPI не переносится этим инструментом.

Если обновляете публичный preview.8, в нём ещё нет нового пункта подготовки. **До запуска нового установщика** распакуйте доверенный ZIP кандидата в отдельную папку и запустите его новый инструмент из Windows PowerShell от администратора, указав установленную программу:

```powershell
& 'C:\Пакет-кандидат\windows\Server-Snapshot.ps1' -Action PrepareUpgrade `
  -BackupDirectory 'D:\SP-Backup-before-upgrade' `
  -InstallDirectory "$env:ProgramFiles\SP Backup Server"
& 'C:\Пакет-кандидат\windows\Server-Snapshot.ps1' -Action VerifyUpgrade `
  -BackupDirectory 'D:\SP-Backup-before-upgrade' `
  -InstallDirectory "$env:ProgramFiles\SP Backup Server"
```

Замените пути своими. Не запускайте Configure-Server и не копируйте новый EXE поверх установленного сервера до подготовки комплекта. Для иной папки данных также укажите `-DataDirectory` с её прежним путём.

## Установить новую программу

Запустите новый установщик поверх прежней установки. Он сохраняет имя, адрес, порт, выбор брандмауэра, администратора, БД, сертификат и ключи. Перед началом мастер напоминает о полном комплекте возврата. После установки откройте прежний HTTPS-адрес, войдите прежним паролем, проверьте агентов, историю, часовой пояс и свежий отчёт. Проверка только `/health/ready` не заменяет эту сверку.

При ошибке миграции приложение не запускается; установщик оставляет существующие данные и отмечает этап `schema-and-administrator` в `%ProgramData%\OneCBackupServer\setup.log`. Транзакция миграции откатывается, но файлы новой программы уже установлены. Сохраните журналы и проверьте место/службу БД. Исправьте причину и повторите **тот же** установщик либо верните полный комплект. Не удаляйте БД и не запускайте произвольный старый EXE.

## Вернуть прежнюю программу вместе с данными

1. Выберите **Пуск → SP Backup Server → Вернуть программу и данные** и папку готового комплекта. Прочитайте предупреждение и явно подтвердите возврат. Он возвращает также пароли, права и токены на дату комплекта; изменения после этой даты не объединяются.
2. Программа проверит весь комплект и подготовит отдельные папки программы и данных. Лишь после проверки остановит службы, сохранит текущие деревья рядом с именами `.before-restore-...`, заменит оба дерева и запустит прежние службы. ACL данных выдаёт NetworkService изменение; ACL программы — только чтение и выполнение. Проверяется готовность по HTTPS с обычным доверием Windows.
3. Если запуск не подтвердился, инструмент возвращает **оба** предыдущих дерева и исходное состояние служб. Подготовленные и предыдущие папки не удаляются. При сбое ОС/питания сохраните все папки и не смешивайте файлы вручную.
4. После успеха откройте панель и проверьте прежние данные и пароль. Инструмент возвращает файлы удаления и отображаемую версию установленной программы. Он не откатывает настройки ОС, доверие сертификатам, Visual C++, правила брандмауэра и ярлыки меню. Запустите сохранённый установщик прежнего выпуска для восстановления его ярлыков; делать это нужно **после** возврата согласованной пары программа/БД. Сохранённые текущие папки пока не удаляйте.

Если панель/ярлык обслуживания недоступны или прежняя программа не содержит нового инструмента, используйте сохранённый **отдельно от `program`** инструмент комплекта. Из Windows PowerShell от администратора:

```powershell
& 'D:\SP-Backup-before-upgrade\Server-Snapshot.ps1' -Action VerifyUpgrade `
  -BackupDirectory 'D:\SP-Backup-before-upgrade' `
  -InstallDirectory "$env:ProgramFiles\SP Backup Server"
& 'D:\SP-Backup-before-upgrade\Server-Snapshot.ps1' -Action RollbackUpgrade `
  -BackupDirectory 'D:\SP-Backup-before-upgrade' `
  -InstallDirectory "$env:ProgramFiles\SP Backup Server"
```

Не запускайте инструмент из заменяемой подпапки `program`. Если служба или реестр установки повреждены настолько, что штатные пути не подтверждаются, автоматический возврат откажет; сохраните комплект и восстановите регистрацию штатным установщиком с помощью администратора.
