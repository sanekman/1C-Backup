# Возврат preview.11 из-за прав каталогов системной задачи

15 ноября 2026 года пользователь передал диагностику и снимок результата
обновления настоящего CT 107: переход preview.10 → preview.11 кнопкой
не выполнен, прежние программа и данные восстановлены. Комплект:
`/var/backups/onec-backup-server/20261115T074153Z-23200ff7`.

Диагностика от 17:42:11 Владивосток (07:42:11 UTC) показывает preview.10,
runtime 10.0.13, Debian 13 x64, готовую БД схемы 6, действительный сертификат
и около 12,9 ГиБ свободного места. Журнал root-компонента в диагностический
архив веб-панели не входит. Статус панели подтверждает штатный автоматический
возврат при этой ошибке; отдельная сверка пользовательских данных ещё не получена.

## Причина и исправление

Системный worker имеет `UMask=0077`. Python `mkdir(mode=0755)` учитывает маску,
поэтому каталоги публичного пакета получали 0700 root:root. Файлы программы
имели 0755, но пользователь `onec-backup-server` не мог пройти родительский
каталог для миграции/запуска. Пользователь подтвердил для preview.11 ровно
`700 root:root` на каталоге и `755 root:root` на исполняемом файле.
Локальное воспроизведение также дало 0700 у корня, wwwroot и вложенных каталогов.

На **bed546d700355e90d4cf2ec84770cd0370086755** каталоги проверенного пакета
явно получают 0755 после распаковки. При повторном использовании пакета с
совпадающим маркером версии/SHA-256 эти права восстанавливаются и у кешированной
версии. Перед изменением отклоняются ссылки и специальные файлы; меняются
только каталоги публичной программы. Файлы программы сохраняют 0755/0644.
Маска worker 0077 не ослаблена: код/состояние брокера, конфигурация, секреты,
журналы и комплекты возврата сохраняют закрытые права.

Проверки: 58/58 Python локально, включая распаковку под 0077 и повторное
использование недоступного каталога без переключения current.
Нативный профиль теперь также наследует 0077, использует кешированную версию
с 0700 и проверяет настоящие миграцию/HTTPS под сервисным пользователем,
права программы и закрытость брокера. [CI 43691450745](https://github.com/sanekman/1C-Backup/actions/runs/43691450745)
успешен на bed546d: 43 профильных теста, 16 сценариев установки и 15
обновления/брокера. Настоящие PostgreSQL/HTTPS/процессы/UID; systemctl и
активация сокета записываются стендом (`realSystemdTested: false`,
`realProxmoxTested: false`). Windows-программа и её проверки не менялись.

## Подключение исправления

После успешной проверки исправленного компонента команды выполняет пользователь
в Shell узла Proxmox. Это замена системного компонента, не новая версия сервера.
Пакеты и тег preview.11 не изменяются.

```sh
wget --https-only -O /root/update-sp-backup-server.py 'https://raw.githubusercontent.com/sanekman/1C-Backup/bed546d700355e90d4cf2ec84770cd0370086755/deploy/server/create-proxmox-lxc.py'
```

```sh
python3 /root/update-sp-backup-server.py --enable-web-updates --id 107
```

Команда проверит текущую установку и заменит закрытый код обновлятора;
веб-программа/БД/пароли не меняются, служба панели не перезапускается.
После успешного подключения открыть «Настройки → Проверить обновления →
Обновить до 0.1.0-preview.11». Скачанный при неудаче пакет может использоваться
повторно с исправлением прав его каталогов.

Сохранить новый результат и путь комплекта, проверить версию, агентов,
задания и историю. Первоначальный комплект возврата не удалять.
Успех повторной установки на CT 107 **ожидает пользователя**.
