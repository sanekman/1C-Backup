# Агент и API сервера управления, версия 1

Сервер предстоит разработать. Этот документ задаёт первый контракт, реализованный клиентом агента; готового сервера в репозитории пока нет.

## Роли компонентов

- Агент — локальная служба Windows: доступ к базам, расписание, создание копии, ZIP, доставка, проверка и очистка. Единственный исполнитель заданий на компьютере.
- WPF-интерфейс — настройка и наблюдение за локальным агентом. Для службы нужен защищённый локальный IPC (именованный канал с ACL); интерфейс не запускает второй планировщик.
- Сервер — регистрация агентов, назначение заданий, контроль состояния и будущий приём отчётов. Агент сам устанавливает исходящие HTTPS-соединения; сервер не подключается к открытым портам агента.
- Хранилища — локальный диск, UNC и FTP/FTPS; далее Яндекс Диск, Облако Mail.ru и S3. Файлы копий идут непосредственно в выбранное хранилище. API управления передаёт настройки и метаданные.

## Режимы и работа без сети

| Режим | Источник заданий | Обращение к серверу |
| --- | --- | --- |
| `Standalone` | Локальный `jobs.json` | Отсутствует; сервер и токен не требуются |
| `Managed` | Последняя принятая серверная конфигурация | Периодическая синхронизация и heartbeat |

Автономный режим установлен по умолчанию. В серверном режиме ошибка сети, HTTP 401/403/5xx или некорректный ответ не стирают принятую конфигурацию: планировщик продолжает использовать её из локального кэша. Без первой конфигурации серверные задания не выполняются; локальные задания автоматически не подмешиваются.

Локальный и серверный наборы хранятся раздельно. Переключение в автономный режим возвращает локальные задания. В серверном режиме задания доступны в интерфейсе только для просмотра. Кэш связан с адресом сервера и `agentId`; после смены сервера или агента старый кэш не используется. Пустой набор с новой ревизией означает явное удаление серверных заданий.

Сетевой обмен и планировщик работают в независимых циклах `BackupAgent.RunAsync`. Зависший запрос API не удерживает блокировку локального исполнения. Планировщик не восполняет события за период остановки службы; он начинает со следующего события, как описано в README.

## Идентификация и подключение

`AgentSettingsStore` создаёт постоянный UUID `agentId` и сохраняет режим, HTTPS-адрес сервера, период синхронизации (по умолчанию 60 секунд) и `CredentialKey`.

Для первого серверного подключения администратор должен зарегистрировать этот `agentId` на сервере и привязать к нему отдельные учётные данные. API автоматической регистрации и интерфейс выдачи токена ещё предстоит разработать. Токен не является UUID агента и не выводится из него.

Запросы используют `Authorization: Bearer <token>`. Клиент получает токен во время запроса через `IAgentCredentialProvider` по идентификатору `CredentialKey`; токен не хранится в JSON и не передаётся в URL. Реализация защищённого хранилища Windows пока не подключена. Сервер обязан проверять, что токен имеет права именно на агента, указанного в пути и теле запроса.

`ServerAddress` — HTTPS-адрес корня приложения, например `https://backup.example.com/` или `https://example.com/backup/`; клиент добавляет к нему `api/v1/...`. Не включайте в него `/api/v1`, пароль, query или fragment. Производственный клиент проверяет сертификаты средствами ОС и не следует перенаправлениям. На запрос установлен таймаут 30 секунд.

Пароль ZIP передавать в конфигурации запрещено. Необязательное поле `archivePasswordKey` у задания — ссылка на запись хранилища текущего пользователя Windows; при её наличии нужна архивация в ZIP (либо способ `FileArchive`). Ссылка сохраняется также в `StoredBackup`, чтобы копии после смены пароля использовали прежнюю запись. Передача паролей с сервера и их первоначальная выдача ещё не реализованы: запись нужно создать локально на агенте.

## Получение конфигурации

Необязательное поле задания `temporaryDirectory` задаёт полный путь к рабочей папке на компьютере агента. Если поле отсутствует или равно `null`, используется стандартная папка агента. Относительный или пустой путь не принимается. Каждый запуск формирует копию и архив в отдельном подкаталоге; проверка FTP использует собственные временные файлы в этой же папке. Параметр общий для всех назначений, не является адресом хранилища и не заменяет `sqlServer.serverBackupDirectory`.

Задание может содержать необязательный массив `additionalDestinations` (до 7 элементов помимо основного хранилища). Каждый элемент задаёт `storageKind`, `destinationDirectory` и, для FTP, `ftp` с адресом, портом, режимом TLS и ссылкой `credentialKey`. База, архивация, пароль, расписание и `keepLast` общие. Агент создаёт файл один раз; доставка и очистка выполняются отдельно по каждому назначению. При частичной доставке локальный запуск имеет статус `PartiallySucceeded` и список `Destinations` с записью копии либо ошибкой каждого места. Серверный приём результатов локальных запусков ещё не реализован.

```http
GET /api/v1/agents/{agentId}/configuration
Authorization: Bearer <token>
Accept: application/json
If-None-Match: "42"
```

При первом запросе `If-None-Match` отсутствует. Ответ `200 OK`:

```json
{
  "protocolVersion": 1,
  "agentId": "79a5eb94-fbc4-47d6-9f29-a412d69f04d1",
  "revision": 43,
  "jobs": [
    {
      "id": "11256fc7-1e84-44d7-a141-7f2636ae4d78",
      "name": "Бухгалтерия",
      "kind": "OneCFile",
      "source": "D:\\Bases\\Accounting",
      "destinationDirectory": "E:\\Backups",
      "storageKind": "LocalDirectory",
      "dailyAt": "23:00:00",
      "additionalDailyTimes": ["09:00:00", "13:00:00"],
      "scheduleKind": "Daily",
      "daysOfWeek": "Monday",
      "timeZoneId": "Vladivostok Standard Time",
      "keepLast": 7,
      "enabled": true,
      "archiveCopies": true
    }
  ]
}
```

`agentId`, `revision`, `jobs` и идентификатор каждого задания обязательны. Ревизия — положительное 64-битное число, которое увеличивается при изменении содержимого. ID заданий уникальны и стабильны между ревизиями. Имена перечислений передаются строками; недельная маска, например `"Monday, Wednesday, Friday"`. Секреты в задания не включаются: FTP использует локальную привязку `credentialKey`.

Неизменившийся набор возвращается как `304 Not Modified` без тела. Значение ETag соответствует ревизии в кавычках. `304` при отсутствии подходящего локального кэша считается ошибкой.

Клиент принимает весь набор атомарно после проверки агента, версии протокола, ревизии и всех заданий. Более новая ревизия заменяет кэш; меньшая отвергается. Одинаковая ревизия с другим содержимым также отвергается. Ошибка одного задания отклоняет весь ответ. Ограничения текущего клиента: 4 МиБ на тело конфигурации и 10 000 заданий. Сервер должен оставаться в этих пределах.

Изменения расписания действуют со следующего опроса планировщика, не создавая очередь прошедших событий. Обновление настроек не прерывает уже начатую резервную копию; будущий исполнитель должен получать неизменяемый снимок задания на каждый запуск.

Задания файловой 1С также поддерживают `oneCMethod`: `PlatformDump` (значение по умолчанию при отсутствии поля) или `FileArchive` — ZIP файла базы без платформы. Для `FileArchive` настройки `oneC` не требуются, а `archiveCopies` не создаёт повторный ZIP. Принятие конфигурации не подтверждает доступность эксклюзивной блокировки файла; она проверяется при запуске задания.

## Сигнал состояния

```http
POST /api/v1/agents/{agentId}/heartbeat
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "agentId": "79a5eb94-fbc4-47d6-9f29-a412d69f04d1",
  "agentVersion": "0.1.0",
  "backupExecutionAvailable": false,
  "configurationRevision": 43,
  "sentUtc": "2026-10-11T00:00:00Z"
}
```

Успех: `204 No Content` (клиент также допускает другой успешный 2xx). Сервер использует собственное время получения для определения доступности, а `sentUtc` — как дополнительную метку. `configurationRevision` может быть `null`, пока нет принятой конфигурации. `backupExecutionAvailable` должен отражать наличие подключённого реального исполнителя, а не факт запуска процесса. `ConnectOnceAsync` по умолчанию сообщает `false`; `RunAsync` предполагает, что хост уже предоставил реальный исполнитель.

Синхронизация и heartbeat повторяются с настроенным интервалом; отдельный цикл проверяет необходимость связи каждые 15 секунд. Ошибка heartbeat сообщается отдельно от результата загрузки конфигурации. Ревизия не является подтверждением успешного выполнения копии.

## Следующие части API

Клиент также поддерживает `POST /api/v1/agents/{agentId}/external-backups` для наблюдений SQL Server/PostgreSQL с постоянной очередью и ключом идемпотентности. Контракт и ограничения описаны в [external-backup-monitoring.md](external-backup-monitoring.md). Серверный обработчик и автоматическая отправка хостом пока отсутствуют.

Ещё не реализованы:

- Регистрация и отзыв агентских учётных данных.
- Отчёты о запусках: постоянная локальная очередь, уникальные `runId`, идемпотентный приём на сервере и повторная отправка после восстановления сети.
- Команды ручного запуска: уникальный `commandId`, подтверждение получения и защита от повторного исполнения.
- Серверная база данных, панель управления, права операторов и аудит изменений.
- Подтверждение принятия или отказа конкретной ревизии, административное редактирование с проверкой исходной ревизии и API мониторинга. Требования и предлагаемые маршруты описаны в [server-management.md](server-management.md).

До реализации очереди отчётов хост должен сохранять возвращаемые результаты локально; текущий API-клиент их на сервер не отправляет.

## Состояние реализации

В ядре реализованы режимы, сохранение агентского ID, отдельный кэш, валидация ревизий, HTTP-клиент конфигурации/heartbeat и независимые циклы связи и расписания с подключаемым исполнителем. В интерфейсе сохраняются режим и параметры сервера, серверные задания показываются без возможности редактирования.

Готовая служба Windows, локальный IPC, защищённое хранилище токенов и сам сервер ещё не реализованы. В автономном интерфейсе подключены ручной запуск и расписание для файловой 1С, SQL Server и PostgreSQL; интерфейс не запускает API-цикл. Настройки SQL-исполнителей описаны в [sql-backups.md](sql-backups.md). Текущие настройки интерфейса находятся в `%LOCALAPPDATA%\\OneCBackup`; при внедрении службы нужно перенести общие настройки, кэш и журнал в `%PROGRAMDATA%\\OneCBackup` с подходящими ACL и явной миграцией. Нельзя запускать службу и интерфейс как независимых исполнителей.

Тесты проверяют клиент через подменённый HTTP-транспорт, изоляцию режимов, обработку ошибочных ответов и продолжение тестового исполнения при отключённом или зависшем API. Подключение к настоящему серверу и запуск службы должны проверяться после их реализации.
