# Обновление сервера из «Настроек»

**Функция подготовлена в рабочей ветке; опубликованный preview.9 её не содержит.**
Обновление настоящего CT 107 до preview.9 принято отдельно в
[отчёте Proxmox](server-proxmox.md#успешное-обновление-настоящего-ct-107).
Новая функция не является новым выпуском и не меняет существующие пакеты.

## Пользовательский сценарий

1. Администратор открывает **Настройки → Обновление сервера**.
2. Нажимает **Проверить обновления**. Сервер проверяет публичный серверный выпуск
   и манифест; несовместимый пакет не предлагается.
3. Если новая версия доступна, нажимает **Обновить до …**. Понижение не предлагается.
4. Системная задача сохраняет полный комплект возврата, выполняет миграцию,
   переключает программу и проверяет HTTPS. Во время перезапуска страница ждёт
   восстановления связи. Закрытие браузера не прекращает системную задачу.
5. После соединения страница показывает подтверждённый результат и путь к комплекту.
   Следующая проверка версии сохраняет результат прошлой установки отдельно.

Проверка версии и установка — разные действия. Автоматической установки,
повторного исполнения после ошибки, выбора произвольного URL или команды нет.
Повторное нажатие при занятой задаче возвращает её текущее состояние.
Проверка старше 30 минут требует обновить сведения перед установкой.
Агенты продолжают выполнять уже принятые расписания при недоступной панели.

Ссылка **Сервер** в меню заменена на **Настройки**; старый адрес `/system`
продолжает работать, основной адрес — `/settings`. Часовой пояс, диагностика,
смена пароля и журнал действий остаются доступны на той же странице.

## Поддерживаемая установка и разовое подключение

Кнопка установки поддерживает **Debian 13 amd64 в LXC из мастера SP Backup,
без Docker**, со штатными путями и службой. Поддерживаются локальная UTF8-база
`onecbackup` и именованная `onecbackup_utf8_ГГГГММДД_ЧЧММСС`, пользователь БД
`onecbackup`, PostgreSQL 17/main на порту 5432 и существующий HTTPS.

Для существующего LXC системный администратор один раз подключает задачу
командой `--enable-web-updates --id <CT>` из Shell узла Proxmox.
[Закреплённый скрипт и команды](server-proxmox.md#подключить-обновление-из-настроек).
Проверяется текущая установка; программа, БД и пароли при подключении не меняются,
служба веб-панели не перезапускается. Для появления раздела нужен новый серверный
пакет с этой функцией: одно подключение задачи не добавляет страницу в preview.9.

Веб-сервер продолжает работать под `onec-backup-server`, без root.
Системная часть устанавливается отдельно и выполняется от root в собственных
systemd-задачах. Самостоятельно повысить права через браузер нельзя.
Если задача не подключена, панель показывает инструкцию вместо кнопки установки.
Обновление веб-программы не заменяет код системного компонента и его units;
при необходимости их обновляет администратор повторным разовым подключением
при отсутствии выполняющейся задачи. Для Windows остаётся штатный установщик; обновление Windows/Compose из этой
кнопки не заявляется. Docker обновляется [своей принятой командой](server-container-update.md).

## Доступ, исполнение и результаты

Все HTTP-маршруты требуют сеанс администратора. Формы проверки и запуска
требуют CSRF; агентский токен не даёт доступа. Состояние не кешируется.
При истёкшем сеансе страница открывает вход вместо бесконечного ожидания.

Протокол локального Unix-сокета допускает только `status`, `check` и `start`.
Для установки передаётся только идентификатор совместимой опубликованной версии;
другие поля отклоняются. Сокет `/run/onec-backup-server-update.sock` принадлежит
root, группа `onec-backup-server`, права 0660; дополнительно проверяется UID
подключившегося процесса через SO_PEERCRED. Принимаются root и сервисный UID.
Сокет не слушает TCP и не доступен агентам по сети.

Файлы системной части находятся в `/usr/local/lib/onec-backup-server-updater`,
состояние и журналы — в `/var/lib/onec-backup-server-updater`; каталоги принадлежат
root с правами 0700. Веб-процесс не может подменить код, запрос задачи или журнал.
В панель передаются только разрешённые поля состояния, без сырых логов,
настроек, паролей, токенов и закрытых ключей.

Проверка и установка запускаются в фиксированных units
`onec-backup-server-update-check.service` и `onec-backup-server-update-run.service`.
Рабочий процесс не является потомком службы веб-панели. Он использует прежний
обновлятор: проверку пакета/SHA-256 до остановки, общий запрет параллельного
обслуживания, закрытый комплект программы/БД/настроек/данных/unit, миграцию
сервисным пользователем и возврат при обычных ошибках. Комплект сохраняется
в `/var/backups/onec-backup-server`; этот путь не передаётся из HTTP-запроса.

| Состояние | Что показывает панель |
| --- | --- |
| Проверка выполняется | Идёт проверка выпуска; повторный запуск отключён. |
| Обновление выполняется | Операция принята системной задачей; это ещё не успех. |
| Связь потеряна | Ожидание соединения, результат не подтверждён. |
| Обновлено | CLI завершился успешно и журнал установки указывает целевую версию; CLI предварительно проверил HTTPS. |
| Прежняя версия восстановлена | CLI вернул ошибку, комплект имеет подтверждённый статус `rolled-back`. |
| Возврат не завершён | Нужен администратор и проверка сохранённого комплекта. |
| Задача прервана | Результат неизвестен; повторная установка из панели блокируется до проверки администратором. |

Выключение CT, `kill -9` и отказ диска не превращаются в автоматический возврат.
Протокол не добавляет перенос на другой CT, внешнюю БД, новую архитектуру или
произвольную нестандартную установку. Первоначальные ограничения
[нативного обновлятора](server-proxmox.md#6-обновить-существующий-lxc) сохраняются.

проверены повторно отдельным режимом `scope=reports`; статус прежнего workflow
не переписывался.

У общего Linux workflow успешно завершён серверный job. Соседний LXC-job
остановился на расположении тестового systemctl вне ограниченного PATH.

серверные/Compose проверки не повторялись. Производственный PATH не расширялся.

В LXC-стенде проверены установка закрытого root-компонента, синтаксис четырёх
units настоящим systemd-analyze, реальный Unix-сокет и SO_PEERCRED с запросами
от `onec-backup-server`, фиксированные команды units, запрет повторного запуска
и настоящий дочерний CLI-переход **preview.8 → preview.9 / схема 5 → 6**.
Использованы опубликованные пакеты и настоящие PostgreSQL/HTTPS. Сохранены
пароль, администратор, сертификат, сессия и токен агента. Статус `updated` и
путь к полному комплекту прочитаны через сокет после перезапуска приложения.
Также прошли проверки возврата после завершённой миграции и ошибки готовности,
неизменность соседней SQL_ASCII-базы, повтор версии без перезапуска и отказ
понижения версии. Каталоги системного кода/состояния — root/0700, журналы и JSON состояния закрыты правами 0600.

Браузер прошёл проверку версии, нажатие с клавиатуры, запрет повторного нажатия,
ожидание потери связи, успешное соединение, путь комплекта, сохранение прошлого
