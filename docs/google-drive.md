# Хранилище Google Drive

Google Drive доступен как основное или дополнительное хранилище. Подключение работает через официальный API; установленный Google Drive for desktop и синхронизируемая папка не требуются.

## Подключение

1. В Google Cloud Console создать или выбрать проект и включить **Google Drive API**.
2. Настроить Google Auth Platform / экран согласия. Для личного аккаунта выбрать External; в режиме Testing добавить свой аккаунт в Test users.
3. Создать OAuth Client ID типа **Desktop app** и скачать JSON клиента.
4. В мастере задания выбрать «Google Drive» → «Подключить Google Drive…» → выбрать OAuth JSON → войти в браузере. Пароль вводится на сайте Google.
5. Программа создаст папку «SP Backup». Сохранить задание и выполнить «Проверить хранилища»: она загружает, проверяет и удаляет небольшой тестовый файл.

Пока у проекта нет общего OAuth-клиента, JSON необходим для первого подключения. В нём нет пароля аккаунта; программа использует client ID / client secret только для OAuth и сохраняет подключение в защищённом хранилище Windows. Не отправляйте JSON, refresh token или пароль в чат / диагностику.

Область доступа — **drive.file**: только файлы, созданные / открытые этим OAuth-приложением. Полный доступ ко всем файлам аккаунта не запрашивается. Служебные аккаунты не используются: для обычного личного Drive у них нет собственной квоты хранения.

В External / Testing Google обычно ограничивает срок refresh token семью днями для этого набора разрешений. Для постоянного расписания нужно перевести собственное OAuth-приложение в Production и выполнить требования Google для его конфигурации. При отзыве доступа или истечении токена копия завершится ошибкой; повторное подключение проверяет доступ к прежней папке и сохраняет связь с историей. Для смены аккаунта добавьте новое хранилище, сохранив прежнее для проверки / восстановления старых копий.

Официальные сведения: [создание OAuth-клиента](https://developers.google.com/identity/protocols/oauth2/native-app), [области доступа Drive](https://developers.google.com/workspace/drive/api/guides/api-specific-auth), [срок действия refresh token](https://developers.google.com/identity/protocols/oauth2#expiration).

## Копирование и проверка

Один готовый файл задания доставляется в выбранные хранилища; для каждого действует свой KeepLast. ZIP и AES-256 применяются до отправки и работают с Google Drive так же, как с диском / FTP. Полные и инкрементные файловые цепочки сохраняют свою основу по общим правилам программы.

Большие файлы отправляются через resumable upload частями по 8 МиБ. В этом выпуске после обрыва загрузка не продолжается между запусками задания: следующий запуск создаёт новую копию. Проценты показывают отправку и последующее чтение для проверки. Успех регистрируется только после обратного чтения и сверки длины / SHA-256. Это расходует входящий трафик размером с копию, но не создаёт дополнительный проверочный файл на SSD.

Каждая копия хранится под отдельным Google file ID; совпадающие имена не перезаписываются. Очистка работает по локальному каталогу зарегистрированных копий, проверяет SHA-256, папку и метку задания, затем удаляет только точный file ID. Другие файлы и сама папка не удаляются. Неудачная загрузка пытается удалить только созданный ею временный файл; при недоступности Google незарегистрированный остаток может остаться в папке. Его нельзя считать успешной копией.

Сохранение копии на компьютер и восстановление файловых цепочек используют тот же адаптер чтения. Извлечение 1Cv8.1CD напрямую из облака отдельной кнопкой пока не включено: сначала сохраните ZIP на компьютер.

## Фоновый агент и служба

Refresh token хранится в Windows Credential Manager. Для службы под другим пользователем используется существующий защищённый кэш профиля: секреты зашифрованы DPAPI, права каталога ограничены; подключение экспортируется при установке службы. Браузер для фоновых запусков не требуется. Если доступ отозван, повторное подключение выполняется владельцем профиля в окне программы.

## Проверка реализации

Автоматически проверяются OAuth state / PKCE на локальном callback, отмена, загрузка частями, SHA-256, очистка сбоев, запрет постороннего адреса загрузки, чужой папки / задания, сохранение настроек и смешанная доставка на диск / Google. HTTP-ответы Google моделируются. В Windows smoke добавлено отображение Google Drive в основном и дополнительном мастере.

Реальный вход, загрузка в аккаунт Google и доступ службы к Windows-секретам ещё требуют проверки на Windows с вашим OAuth-клиентом. Без такой проверки интеграцию нельзя считать подтверждённой на реальном аккаунте.
