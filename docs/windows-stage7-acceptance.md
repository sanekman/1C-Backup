Все пути и распакованные файлы двух ZIP побайтно совпали, включая Desktop, Agent, Core, runtime и справку. Хеши контейнеров и EXE различаются: это отдельные сборки одного исходника, а не приёмка одного и того же EXE на двух ОС. Основной EXE принят на Server 2025; на Server 2022 принят его отдельно собранный эквивалент с указанным SHA-256.

Повторно просмотрены снимки **установленного** кандидата на обеих ОС: ввод пароля при занятом профиле, изменение черновика и компактный мастер. Кнопка пароля активна, основные действия видимы; WPF-сценарий также проверяет ввод FTP, отмену без изменения прежних секретов и границы кнопки сохранения диалога.

Для установки кандидата: скачать основной артефакт, распаковать его и запустить EXE. Перед заменой файлов дождаться завершения текущей копии и остановить прежний исполнитель по инструкции обновления; затем использовать программу и службу из одного комплекта. После установки изменение локальных заданий не требует остановки службы. Профиль и копии не удалять. Возврат программы — остановить исполнитель и установить сохранённый прежний комплект; не пытаться повторить уже исполненные команды. Это не приёмка понижения версии нового защищённого задания: старый агент может пропускать неподдерживаемые параметры.

Режим packaging требует успешного блока verify именно на выбранной ОС, проверяет родство коммитов и отсутствие изменений продуктовых исходников. Исключение — сгенерированная HTML-справка: она обязана точно совпадать с Markdown по штатному `--check`, сам генератор не меняется. Затем повторяются настоящая служба, сборка и проверка установленного пакета; пропуск общей проверки не является безусловным.

Новая нативная проверка использует отдельного пользователя службы: без смены PID/сеанса сохраняет и удаляет защищённое задание, добавляет пароль Windows при работающей службе, создаёт зашифрованный ZIP и сверяет восстановленные байты, затем подтверждает сохранность прежнего пароля. Рабочая база пользователя не используется.

На Server 2022 первый прогон выявил несовместимость сертификата тестового PostgreSQL с прежним libpq: IP SAN поддерживается иначе. В тестовом сертификате CN теперь также равен `127.0.0.1`; IP SAN, `verify-full`, проверка CA и отрицательные сценарии имени/пароля сохранены. Проверка TLS не отключалась.
