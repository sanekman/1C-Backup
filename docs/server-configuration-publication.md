# Публикация серверной конфигурации: начальный контракт

API опубликован в server preview.4; библиотечная поддержка — в alpha.29. В разработке после этих выпусков подключён [headless Managed-хост](managed-execution.md), но веб-мастер и простой интерфейс включения ещё не завершены. Автономный клиент не объявляет managed-execution-v1 и не получает непустые серверные задания. [Протокол подтверждений](configuration-receipts.md) означает проверку и сохранение конфигурации, а не результат копии. Локальные автономные задания сохраняются отдельно.

## Что поддерживается

Контракт ограничен Windows-заданиями **Файлы и папки** и **Файловая 1С → ZIP файла базы**, с одним локальным или UNC-хранилищем. Поддерживаются расписание, часовой пояс исполнителя (`Local`) или явный часовой пояс, полные/инкрементные файловые копии и день полной копии. Новое задание по умолчанию выключено и имеет ручное расписание.

SQL, WebDAV, FTP, дополнительные хранилища, выгрузка `.dt`, шифрование архива и ссылки на локальные секреты в этот начальный контракт не входят. Их поля отклоняются, а не отбрасываются. Пароли, токены и DPAPI-данные сюда передавать нельзя. Конфигурация с неподдерживаемыми полями, уже находящаяся в БД, также не читается и не заменяется этим API: ответ `409 stored_configuration_not_editable` сохраняет прежний документ.

Пути проверяются как Windows-пути независимо от ОС сервера: абсолютный путь диска или UNC, без устройств, ADS, переходов `..`, неоднозначных конечных точек/пробелов. Источник, хранилище и временная папка не должны пересекаться. Сервер не проверяет существование файлов и права пользователя удалённой службы; это будущая проверка на агенте.

## Прочитать текущую ревизию

`GET /api/v1/management/agents/{id}/configuration`

Нужен административный cookie-сеанс. Ответ `200` содержит `agentId`, `revision`, `protocolVersion` и `jobs`. Заголовок `ETag`, например `"1"`, нужен для последующей записи. Ответ не кэшируется (`Cache-Control: no-store`). Неизвестный агент возвращает `404`.

## Сохранить следующую ревизию

`PUT /api/v1/management/agents/{id}/configuration`

Нужны административный cookie-сеанс, действующий `X-CSRF-TOKEN`, `Content-Type: application/json` и один сильный `If-Match` из последнего чтения. Значение `*`, слабые ETag, списки и число без кавычек не принимаются. Номер новой ревизии назначает сервер; поля `revision` в запросе нет.

```json
{
  "agentId": "b7ed4b31-9fb6-43c9-a468-a9e6d3de1f12",
  "protocolVersion": 1,
  "jobs": [
    {
      "id": "1f564dde-0f9a-455d-bb21-f88e9ef6f18d",
      "name": "Документы",
      "kind": "FilesAndFolders",
      "source": "C:\\Company\\Documents",
      "destinationDirectory": "D:\\Backups",
      "storageKind": "LocalDirectory",
      "enabled": false,
      "scheduleKind": "Manual"
    }
  ]
}
```

`agentId` должен совпадать с адресом запроса. ID заданий обязательны, уникальны в наборе и сохраняются при редактировании. Весь набор заменяется целиком; `jobs: []` задаёт пустую желаемую конфигурацию, не удаляя архивы и не подтверждая остановку исполнителя. Для UNC-хранилища нужен `storageKind: "NetworkShare"` и полный путь `\\server\share\folder`.

Варианты `kind`: `FilesAndFolders`, `OneCFile`; `oneCMethod` допускает только `FileArchive`. `scheduleKind`: `Manual`, `Daily`, `Weekly`, `SystemStartup`. Поля расписания: `dailyAt` (по умолчанию `23:00:00`), `additionalDailyTimes` (до 47 дополнительных уникальных времён), `daysOfWeek` (например `Monday, Friday`), `timeZoneId` (по умолчанию `UTC`). `None` разрешён только для ненедельного расписания. `keepLast`: 1–10 000, по умолчанию 7. Файловый план: `fileBackupMode` (`Full`/`Incremental`), `fullBackupEvery` (1–365, по умолчанию 7), `fullBackupDayOfWeek` (например `Sunday` либо `null`). `temporaryDirectory` необязателен. Для ZIP базы 1С доступен `allowOpenOneCDatabase`, по умолчанию `false`.

Ограничения: 1 МиБ для тела запроса и сохранённого документа, 256 заданий, 256 символов в имени, 4096 в пути. Неизвестные поля, дубли свойств JSON, числовые значения перечислений и неизвестная версия протокола отклоняют весь запрос. Ошибка не содержит имя задания, путь или исходный JSON.

Для крупных запросов используйте `Expect: 100-continue`: сервер сможет отклонить заведомо слишком большой `Content-Length` до отправки тела. При передаче превышающего лимит тела без этого согласования HTTP-соединение может закрыться; изменение конфигурации не происходит.

## Результаты и конфликты

| Статус | Значение |
| --- | --- |
| `200` | Желаемая ревизия сохранена; тело содержит назначенный номер, `ETag` обновлён. |
| `428` | Нет обязательного `If-Match`. |
| `400` | Некорректный ETag/JSON/набор, неподдерживаемые поля или неверный CSRF. |
| `412` | Другой редактор уже изменил ревизию. Прочитайте актуальную конфигурацию и сравните правки; не повторяйте запись вслепую. |
| `409` | Доступ агента отозван, прежняя конфигурация не поддерживается этим редактором либо номера ревизий исчерпаны. |
| `413` | Превышен размер, в том числе при передаче без `Content-Length`. |
| `415` | Не JSON. |
| `401` / `403` | Нет административного сеанса либо `agentId` не совпадает с адресом. Агентский bearer не даёт права публикации. |

При одновременной записи с одним ETag успешна только одна операция. Повтор той же операции со старым ETag получает `412`, не создавая вторую ревизию или запись аудита. Изменение документа, увеличение номера и событие `ConfigurationPublished` фиксируются одной транзакцией. Сбой аудита откатывает запись целиком. Смена сеансов администратора и отзыв доступа агента учитываются в этой транзакции. Сам API публикации использует исходные таблицы. Для журнала [подтверждений](configuration-receipts.md) следующему пакету нужна схема БД **3**; переход выполняется отдельной транзакционной миграцией.

**Сохранено на сервере** и **принято агентом** — разные состояния. Публикация не меняет сообщённую агентом ревизию и не доказывает выполнение копирования. Перед выдачей конфигурации сервер по-прежнему проверяет возможности клиента, включая условный запрос `304`. Старый клиент без поддержки исполнения продолжает отправлять мониторинг.

## Пользовательский интерфейс

На карточке агента откройте **Настроить задания на сервере**. Мастер использует те же типизированную проверку, атомарную публикацию и контроль ожидаемой ревизии, что API. До последнего подтверждения изменения остаются в форме; конфликт сохраняет введённые значения и требует сравнения со свежим планом. [Подробные шаги](server-job-wizard.md).
