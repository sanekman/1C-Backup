# SP Backup: переименование проекта

Программа, сервер мониторинга и шлюз хранилища теперь называются **SP Backup**. Решение — `SPBackup.slnx`; проекты, пространства имён и основные программы — `SPBackup.*`. Новые установщики и архивы Windows используют префикс `SP-Backup-`, пакеты шлюза — `SPBackup-Storage-`.

## Обновление установленной программы

1. Дождитесь завершения копирования. Выберите «Выйти полностью» или остановите службу.
2. Запустите новый установщик и оставьте прежнюю папку установки. Он использует прежний идентификатор приложения, поэтому установка обновляется на месте.
3. Откройте **SP Backup** через меню «Пуск». Проверьте задания, историю, расписание и подключение к серверу. Сделайте пробную копию и проверьте восстановление.

Профиль агента остаётся в `%LOCALAPPDATA%\OneCBackup`, данные сервера — в `%PROGRAMDATA%\OneCBackupServer`. Переименовывать эти папки вручную не нужно. Настройки, история, каталог копий, пароли Windows и защищённые секреты службы используют прежние идентификаторы. Сохранённое пользователем имя сервера не меняется.

Системные имена служб `OneCBackupAgent`, `OneCBackupServer`, `OneCBackupServerDatabase`, правило брандмауэра и технические имена Linux-служб сохраняются. Отображаемое имя продукта меняется на SP Backup. В пакет входят совместимые точки запуска `OneCBackup.*`: ранее настроенная служба и механизм обновления запускают через них новые сборки `SPBackup.*`.

## Копии и обмен данными

Прежние архивы и инкрементные цепочки поддерживаются. Идентификатор `1C-Backup` внутри манифеста архива и экспорта задания остаётся частью формата обмена. Его нельзя заменять в старых файлах. Техническое имя установщика `1C-Backup-windows-x64-setup.exe` сохраняется как копия нового установщика для прежних клиентов обновления.

Существующие теги, ветки дистрибутивов и опубликованные файлы не переименовываются и не перезаписываются. Поэтому старые выпуски и примеры их имён по-прежнему содержат 1C-Backup. Пространство Docker-пакетов `ghcr.io/sanekman/1c-backup-storage` сохраняется для совместимости с опубликованными образами; каждый новый выпуск требует отдельного тега.

## Адрес репозитория

Переименование продукта подготовлено независимо от адреса GitHub. Запрос смены адреса на `sanekman/SP-Backup` отклонён GitHub API с `403 Resource not accessible by integration`: подключению недоступна эта административная операция. До смены имени владельцем используются рабочие ссылки `sanekman/1C-Backup`.

Новый клиент обновления обращается к постоянному ID репозитория `1413316996` и не зависит от его имени. Отключение перенаправлений сохраняется: токены не передаются по адресу из ответа сервера. Маршруты списка выпусков и файлов по ID проверены на действующем репозитории.

**Сначала распространите новый клиент, затем меняйте адрес репозитория.** Прежние опубликованные клиенты обращаются к `sanekman/1C-Backup` и отклоняют HTTP-перенаправления. После смены имени пользователям таких версий потребуется скачать новый установщик вручную со страницы выпусков; существующие копии и настройки при установке сохранятся.

Владелец может сменить имя через **Settings → General → Repository name → SP-Backup → Rename**. GitHub создаёт перенаправление со старого адреса; после этого следует обновить адрес `origin` и ссылки в документации, установщиках, CI и кнопке открытия страницы выпуска. API нового клиента использует постоянный ID. Существующие теги и файлы выпусков при этом сохраняются.
