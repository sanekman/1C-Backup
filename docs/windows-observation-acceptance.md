# Наблюдение внешних копий: агент → сервер → панель

Проверено 9 ноября 2026 года в невыпущенном пакете. Исправление касается центральной панели; оно не меняет механизм создания копий, локальные секреты или протокол мониторинга.

## Исправленная проблема

После смены SQL-подключения с тем же именем базы агент выбирал правильный текущий результат. Но панель искала подробности по самой поздней дате среди всей истории задания. Если у прежнего источника были более новые копии, расшифровка ошибки текущего источника пропадала.

Теперь сервер загружает конкретные отчёты, указанные агентом, и проверяет принадлежность агенту и заданию. Запрос выполняется одним пакетом, максимум для 1000 ID; пустой список не обращается к базе. Первая страница истории и её порядок не ограничивают поиск. При задержке доставки подробностей показано явное сообщение ожидания; чужие и неподходящие отчёты не подставляются.

## Проверки

| Сценарий | Подтверждение |
| --- | --- |
| Смена адреса SQL или каталога PostgreSQL при том же имени базы | Старый успех, дата опроса и сведения о типах копий сразу перестают быть текущими; история остаётся. |
| Пустой успешный опрос | Возникает предупреждение об отсутствии свежей копии. До опроса новый источник не выдаётся за проверенный. |
| Отказ чтения | В панели отображаются ошибка опроса и безопасная категория доступа; текст тестового исключения с условным секретом не передаётся. |
| Ошибка внешней копии, дата которой старее прежнего источника | В строке задания показаны правильные время, подтверждение и «Причины и что делать». |
| Восстановление | Успех заменяет ошибку, повторный опрос не дублирует записи и не обновляет дату обнаружения. |
| История больше одной страницы | Подробности выбранного отчёта доступны за пределами первых 50 записей. |
| Разделение доступа | Отчёт другого агента или другого задания не подставляется; неизвестный ID даёт сообщение ожидания. |
| Пояс и перезапуск | UTC сохраняется, панель показывает Asia/Vladivostok; актуальный отчёт и история переживают перезапуск сервера. |

Сначала два новых сценария воспроизвели потерю расшифровки на старом коде. После исправления прошли 18 связанных проверок и полный локальный серверный набор: **159 тестов, 0 ошибок, 0 пропусков**. Счётчик обязательных CI-проверок увеличен на три новые проверки; пропуски не допускаются.

Chromium дополнительно проверил три состояния: восстановленный успех, раскрытую причину текущей ошибки и новый источник без опроса. Просмотрен снимок ошибки; горизонтального переполнения нет. Для браузера доверен только открытый ключ собственного временного сертификата стенда; глобальное отключение проверки HTTPS не используется.

## Границы результата

В этой проверке настоящий HTTPS-клиент агента передаёт данные настоящему серверу с изолированной PostgreSQL, который формирует реальные HTML-страницы. Коллектор внешних наблюдений использует управляемые тестовые данные. Это проверка передачи и отображения, а не повторное доказательство работы SQL Server или запуска платформы 1С. Реальное создание и восстановление SQL-копий подтверждено [отдельным стендом](windows-sql-stand.md).

На исходнике **3c4ad440b2809a411f3dd2af4968ea993f6a37cb** [штатный серверный CI](https://github.com/sanekman/1C-Backup/actions/runs/42630070895) завершился успешно: на Windows и Linux пройдены по **159 тестов и одной проверке установленного пакета**, без ошибок и пропусков. В журналах сверены исходник checkout и строгие счётчики обязательных проверок; Windows-установщик также принят. Дистрибутивы из CI не считаются опубликованным выпуском.

Все **шесть прогонов CI** исходника успешны. [Windows-прогон агента](https://github.com/sanekman/1C-Backup/actions/runs/42630070934) подтвердил 965 тестов и 6 проверок профилей без ошибок/пропусков, установленный интерфейс и девять сценариев обновления с alpha.25. Скачанный отчёт обновления проверен по источнику, результату и SHA-256 ZIP: **25f585f970f8da314ce252f92959a9fde8d6084912d7b37a2cb610a5085b7ba1** (артефакт **13681496999**). Код агента и создания SQL-копий в этом пакете не менялся; отдельно принятый SQL-стенд повторно не запускался.
 Удалённый MS SQL под службой, полная матрица версий PostgreSQL и настоящие открытый UNC-сеанс/DT 1С остаются отдельными незавершёнными частями этапа 4.
