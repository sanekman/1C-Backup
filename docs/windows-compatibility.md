# Совместимость локального Windows-приложения

Первый целевой сервер: **Windows Server 2016 x64 с Desktop Experience**, со свежими обновлениями Windows. Далее: Server 2019, 2022 и 2025 x64. Это приложение агента с WPF-окном; требования центрального веб-сервера описаны отдельно в `server-roadmap.md`.

| ОС | Сборка ОС | Установщик с alpha.3 | Нативная проверка |
| --- | --- | --- | --- |
| Server 2016 | 14393 | Допускается | Требуется |
| Server 2019 | 17763 | Допускается | Требуется |
| Server 2022 | 20348 | Допускается | Ядро/WPF и SCM-служба проверены; текущий установщик ещё не принят, см. ниже |
| Server 2025 | 26100 | Допускается | Этапы 1–3 приняты; ядро/WPF и SCM-служба текущего пакета проверены; текущий установщик ещё не принят |
| Windows 10 22H2 / Windows 11 x64 | 19045 и выше | Допускается | Отдельный стенд |
| Server 2008 R2 / 2012 / 2012 R2 | Ниже минимального требования | Не допускается | Пока вне текущего этапа |

.NET 10 официально включает Server 2016–2025: [матрица .NET 10](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md). Среды .NET и Windows Desktop входят в дистрибутив. Это подтверждает платформенную предпосылку, а не проверку всех функций SP Backup на этих ОС. Server Core без Desktop Experience не является целевым вариантом GUI-дистрибутива на этом этапе.

До alpha.3 оба установщика ошибочно применяли порог Windows 10 22H2 (19045) к серверной Windows, блокируя Server 2016 и 2019. NSIS теперь использует тип ОС и отдельный порог 14393 для сервера; Inno использует MinVersion 10.0.14393 и проверку ProductType для сохранения порога 19045 на рабочих станциях. Контроллер домена распознаётся как серверная ОС; это не рекомендация устанавливать агент на контроллер домена.

## Проверка на Server 2016

На отдельном тестовом сервере с Desktop Experience, не на рабочих базах:

1. Установить EXE в Program Files под администратором, открыть GUI обычным пользователем, проверить светлую / тёмную тему и трей.
2. Создать задание на тестовые файлы, доставить в локальную папку и UNC, проверить проценты двух хранилищ, архив и восстановление.
3. Проверить файловую 1С: закрытая база, отказ при блокировке, разрешённое чтение открытой базы с предупреждением. Целостность ZIP не подтверждает целостность работающей базы.
4. Проверить платформу 1С, SQL Server / PostgreSQL установленными на стенде версиями, включая восстановление созданной копии. Совместимость конкретной версии платформы 1С / SQL / pg_dump с ОС требуется отдельно.
5. Установить службу под выбранным пользователем, проверить доступ к локальному и UNC-источникам, секреты и расписание без входа пользователя. Использовать UNC вместо подключённых букв сетевых дисков.
6. Проверить обновление через штатный Windows PowerShell 5.1 с HTTPS / TLS 1.2, остановку службы перед заменой файлов, перезапуск и сохранение заданий / истории.
7. Проверить штатный выход, остановку службы и удаление без удаления копий / рабочего профиля.

Дополнительная проверка границ NSIS на изолированной Windows с установленным makensis: `python tests/distribution/nsis_os_smoke.py`. Она запускает отдельный установщик без установки файлов и моделирует версии сервера / рабочей станции, включая Server 2016, 2019, 2022, 2025, контроллер домена и отказ для прежних ОС.

В Linux проверяются сборка Windows-пакета, компиляция NSIS, целостность, версии и клиент обновления. Нативные SCM / WPF / ACL / UAC и Windows PowerShell 5.1 здесь не выполняются. Поддержку Server 2016 можно считать проверенной после прохождения сценариев на этом сервере.
