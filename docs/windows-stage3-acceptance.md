## Исправленная ошибка запуска после перезагрузки

Реальное выключение и включение ВМ выявило ошибку прежнего определения загрузки: `SystemBootEnvironmentInformation.BootIdentifier` остаётся GUID записи загрузчика. Из-за этого уже выполненное стартовое задание могло не запускаться после следующих загрузок Windows. Идентификатор дополнен временем создания системного процесса PID 4; чтение списка процессов не требует открытия защищённого процесса. Разбор 32-/64-разрядного буфера ограничен размерами и количеством попыток; сохраняется только успешно полученный результат. Время создания процесса не меняется при коррекции часов ([Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/nf-ntddk-psgetprocesscreatetimequadpart)).

Для прежних отметок, не содержавших конкретной загрузки, документирован однократный запуск включённого стартового задания после обновления. Дальнейшие перезапуски службы и смена её пользователя не повторяют копию в пределах одной загрузки. Ручные подтверждения и прежние архивы сохраняются.

## Границы приёмки

Проверка перезагрузки относится к конкретному Windows Server Evaluation в изолированном KVM-госте. Это реальная новая загрузка ОС после выключения виртуальной машины, а не перезапуск службы; физическое отключение питания оборудования не воспроизводится. Доменный двухмашинный SMB-стенд, настоящая платформа 1С и полная матрица Windows относятся к следующим этапам. Частичные результаты настоящей 1С на alpha.34 записаны [отдельно](windows-onec-results.md) и не подменяют эту приёмку. Встроенная тестовая файловая база 1С подтверждает сохранность байтов, а не проверку согласованности настоящей открытой базы платформы.

Проверки удалённых цепочек используют контролируемый транспорт с корректными FTP(S)-адресами и реальными архивами, манифестами, SHA-256 и восстановлением. Они проверяют общую логику восстановления/доставки; нативный SMB и отдельный FTP integration CI подтверждают транспортные операции.
