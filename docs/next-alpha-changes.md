# Следующий пакет Windows после alpha.28

Последний опубликованный клиент — **alpha.28**, сервер — **preview.3**. Следующие изменения накапливаются для общего выпуска; существующие теги и файлы выпусков сохраняются.

## Создание заданий и результаты копирования 1С

- При создании задания **На основе…** выбор другой базы 1С подставляет её название; ручной путь к базе или папке подставляет имя папки. Название, которое пользователь затем ввёл самостоятельно, сохраняется при смене источника. Исходное задание не меняется.
- Разрешение копировать открытую базу не добавляет предупреждение само по себе. Сначала исполнитель получает и удерживает эксклюзивный доступ до конца архивации; при закрытой базе результат успешный без этого предупреждения. Если эксклюзивный доступ недоступен и используется разрешённое совместное чтение, риск отражается в результате и истории. Проверка источника использует то же правило.

## Подготовка серверного управления заданиями

- Неизвестные поля серверной конфигурации, вложенных заданий и кэша отклоняются целиком; прежний принятый снимок не заменяется. Автономные задания не зависят от серверного кэша.
- Клиент сообщает возможности чтения конфигурации и TLS отдельным HTTP-заголовком. Исполнение Managed не заявляется: оно ещё не подключено к реальному хосту.
- Сервер выдаёт непустой набор заданий только при явной поддержке исполнения, строгой проверки конфигурации и нужных параметров TLS. Проверка действует и перед `304 Not Modified`; HTTP-кэш различает наборы возможностей.
- Сведения от работающего автономного агента сохраняются в существующем снимке мониторинга без миграции БД. В карточке видно, что задания пока настраиваются на компьютере агента; административный API возвращает последнюю декларацию возможностей. Старый клиент без заголовка продолжает передавать мониторинг и сбрасывает прежнюю декларацию при следующем снимке.
- Веб-мастер, расширение публикации на остальные источники и защищённые привязки, подтверждения принятия/отказа и исполнение Managed остаются следующими этапами. Эти изменения не входят в опубликованную alpha.28.
- Добавлен начальный административный API [публикации файловых заданий](server-configuration-publication.md): строгий ограниченный контракт, серверный номер ревизии, обязательный `If-Match`, конфликт без перезаписи и атомарный аудит. Сохранение желаемой конфигурации не означает её принятия агентом. Неподдерживаемые прежние документы не заменяются; секреты и остальные типы заданий этим API не принимаются.

## Выпущено в alpha.28

### Защищённое подключение PostgreSQL

- В мастере можно явно включить TLS с проверкой имени сервера и сертификата, выбрать корневой сертификат PEM или стандартное доверие libpq. Одинаковая политика применяется при проверке источника, создании и проверке дампа.
- Защищённые задания хранятся отдельно от файла, который читает старый агент. Обычные задания остаются доступны старой версии; переход в защищённый режим требует остановки исполнителя. Незавершённая запись восстанавливается из подготовленного снимка.
- Нативные проверки используют TLS/SCRAM PostgreSQL, неверные CA/имя, настоящую службу, создание и восстановление копии. Совместимость старой версии проверяется опубликованной сборкой alpha.25. Результаты CI фиксируются в PR.

### Надёжность агента в alpha.28

- После аварии агента уже принятое ручное задание получает завершённое подтверждение «Прервано», даже если команда уже удалена из очереди. Новый сеанс не повторяет копирование; завершённые подтверждения сохраняются.
- Подготовлен [Hyper-V-стенд](windows-lab.md) для отдельного доменного SMB-сервера, обрыва доставки и настоящего выключения ВМ во время `pg_dump`. Наличие сценария не означает, что он уже выполнен: результаты перезагрузки и доменного SMB требуют запуска на отдельном Windows-хосте.

- При аварийном завершении Windows-агента завершаются и запущенные им утилиты копирования. Защита включается до запуска утилит у фонового агента и службы; прямое копирование в окне программы и выполняемый на SQL-сервере `BACKUP DATABASE` имеют другой жизненный цикл.
- Нативный сценарий завершает только родительский процесс службы, пока настоящий `pg_dump` ожидает таблицу отдельной тестовой базы. Проверяются выход дочернего процесса, новый сеанс, итог «Прервано», сохранность прежних архивов и восстановление данных из следующей явно запущенной копии.
- После перезапуска агента окно и трей очищают прогресс прежнего процесса. Долгая SQL-копия действующего исполнителя остаётся видимой даже без обновления числа байтов.
- Добавлена проверка настоящего обрыва собственной SMB-шары во время записи: повтор доставки сохраняет байты/SHA-256, одну регистрацию новой копии, прежний архив и очистку временных файлов. Сетевое исключение возвращает Windows; момент обрыва задаётся контролируемой паузой записи.
- Добавлен отдельный SCM-сценарий сетевого доступа от пользователя службы без входа в Windows: разрешённая и запрещённая SMB-шары при одинаковых разрешениях NTFS, проверка действующего пользователя без остановки расписания, зашифрованная UNC-копия с проверкой владельца, SHA-256 и восстановлением данных. Результат нового сценария фиксируется в CI.
- Повторная доставка уже завершённой ручной команды после перезапуска сохраняет её прежнее подтверждение. Нативный SCM-сценарий возвращает настоящую завершённую команду в очередь перед запуском службы и сверяет сохранность подтверждения и истории. Несовпадающие задание или сеанс не меняют старый результат и не запускают копирование; показывается предупреждение. Дополнена проверка повторной доставки, пока запись итогового подтверждения недоступна: готовая копия не создаётся повторно, следующее задание продолжает работать.
- Окно проверяет, что подтверждение ручного запуска относится к тому же заданию и сеансу. При несовпадении оно предлагает проверить историю и не снимает защиту от повторного запуска; другие задания остаются доступны.
- В пошаговом руководстве уточнено, как проверить пользователя службы, UNC-путь и оба уровня прав — сетевой доступ и саму папку — до пробной копии и восстановления.

Результаты окончательного пакета и ссылки CI фиксируются в PR №2. Локальные SMB-сценарии не подтверждают доменную сеть, отдельный файловый сервер или перезагрузку Windows. Эти проверки требуют своих стендов.

## Опубликованная alpha.27

- Кнопка «Проверить хранилища» работает через запущенного агента/службу без остановки расписания. Проверка выполняется от его пользователя, а результат показывает учётную запись и различает исполнителя и окно. Отдельная команда не запускает копирование; смена сеанса, устаревшая команда, изменённое задание и отсутствие поддержки у старого агента не дают ложного подтверждения.
- При кратковременной сетевой ошибке файлового хранилища повторяется доставка готового архива после пауз 2 и 5 секунд. Источник повторно не копируется, исправные хранилища не отправляются заново. Отмена прекращает ожидание; права, пароли, нехватка места и несовпадение SHA-256 требуют исправления причины.
- При потере подтверждения переименования проверяются размер и SHA-256 уже появившегося архива, затем он регистрируется один раз. Существующие до доставки файлы не принимаются как свои и не заменяются. Ошибка удаления своего `.tmp` сохраняется в диагностике и не скрывает основной результат.
- Добавлены подсказки по сети/VPN/UNC, пользователю службы, конфликту сетевых учётных данных и нехватке места во время записи. В интерфейсе виден повтор подключения; серверу передаётся совместимый этап подключения к хранилищу.
- Добавлен сквозной сценарий для длинных путей с русскими именами: источник, хранилище, рабочая папка и восстановление за пределами 260 символов, включая обрыв доставки, неполный инкремент и восстановление индекса.

## Опубликованная alpha.26

Клиент — alpha.26. Сервер остаётся preview.3; описанные ниже серверные доработки готовятся отдельным выпуском.

- Карточка агента и трей различают работающий планировщик, службу, фонового агента и разовый запуск; видны ближайший запуск и настройка автозапуска текущей копии. Чужая запись автозапуска не удаляется и не перезаписывается; повторное нажатие во время запуска не создаёт второго исполнителя.
- После потери или отставания индекса программа восстанавливает основу инкрементной цепочки по зарегистрированным и проверенным локальным/UNC-архивам. Сохраняются недельный план полной копии и последние доступные версии пропущенных файлов. Для хранения только на удалённом сервере восстановление индекса из архивов пока не реализовано.
- Перед переносом готового архива в локальную/сетевую папку проверяется доступное место. При нехватке сообщение показывает требуемый и доступный объём; остальные хранилища продолжают получать копию, прежние копии заполненного хранилища сохраняются. Проверка хранилищ показывает место временной папки и доступных файловых хранилищ. Неизвестный объём не блокирует обычную запись; проверка не резервирует место и не предсказывает размер будущего архива.
- Для известных ошибок MS SQL добавлены понятные действия: вход, истёкший пароль, недоступная база, недостаток прав, сеть, тайм-аут и ошибки сертификата. Используются коды драйвера и системы, а не поиск слов в локализованном тексте. Подсказки одинаковы при проверке источника, копировании и внешнем мониторинге; технические коды сохраняются в диагностике. Неизвестные ошибки сохраняют прежнее описание, отмена остаётся отменой.
- Проверка PostgreSQL объясняет, какие настройки перепроверить при неудаче psql, и не выдаёт код выхода за доказательство неверного пароля. Ошибка недоступных сохранённых данных MS SQL направляет к повторному вводу и сохранению настроек.
- Для мониторинга внешних копий MS SQL добавлен выбор Windows-входа или SQL-логина. Пароль хранится в Windows Vault; JSON содержит только ссылку. Ручной и автоматический опрос используют общее подключение с обязательным TLS и проверкой сертификата. При смене сервера нужен новый пароль; новые источники не наследуют чужую привязку.
- Пароль несохранённого SQL-черновика не передаётся службе. Сохранение задания или источника подготавливает защищённый DPAPI-кэш до публикации настроек; установка службы экспортирует также пароли сохранённых источников мониторинга.
- В окне мониторинга убрана устаревшая надпись об отсутствии серверной отправки. Добавлены пошаговые указания по настройке SQL-мониторинга.

Следующие доработки снова накапливаются пакетами перед выпуском. Оповещения Telegram/MAX остаются отдельной задачей.

## Следующий пакет Windows-сервера после preview.3

- Светлая/тёмная тема панели переключается кнопкой в шапке и сохраняется в браузере. Поддерживаются вход, переходы страниц, системное оформление до первого выбора и узкий экран.
- В мастере первой установки отдельный шаг HTTPS-порта и разрешения брандмауэра. Выбранный порт применяется к прослушиванию/адресу/приглашению; отказ от собственного правила сохраняется при обновлении и миграции. Явное разрешение меняет только правило программы для Domain/Private и сохраняет ограничения удалённых адресов.

- На странице «Сервер» доступны смена пароля администратора, журнал действий и скачивание ZIP диагностики.
- Смена пароля требует текущий пароль и повтор нового, завершает все прежние сеансы панели и сохраняет подключение агентов. Хеш и запись аудита меняются атомарно; конкурентный запрос со старым сеансом отклоняется.
- Журнал показывает успешные входы, приглашения, подключения, отзыв доступа и смену пароля, с пагинацией и сохранением после перезапуска.
- Диагностика содержит фиксированный набор сведений о состоянии и до 200 технических событий без исходных журналов, конфигурации, БД, имён, адресов, паролей, токенов и закрытых ключей. Требуются права администратора и CSRF. Это не копия сервера.
- Нативная проверка установщика Windows меняет пароль через HTTPS, проверяет страницы и ZIP и затем подтверждает сохранность нового пароля при переустановке, перезапуске и удалении/повторной установке. Существующие выпуски не заменяются.

## Опубликованный пакет alpha.25

Изменения клиента **alpha.25** по сравнению с **alpha.24**. Сервер **preview.3** устанавливается отдельно.

## Windows-агент: удобство и надёжность

- Несохранённое задание защищено при «Отмена», Esc и полном выходе: можно сохранить, отказаться от изменений или вернуться в редактор. Сохранение доступно с любого шага и проверяет все настройки; ошибка проверки или записи оставляет черновик открытым. Сворачивание в трей сохраняет редактор без подтверждения. Неизменённое задание не вызывает лишних вопросов; импортированные и дублированные задания защищены сразу. Смена режима агента недоступна до закрытия редактора.
- Уточнено предупреждение о хранении инкрементной цепочки: архивы сверх лимита удаляются автоматически, когда перестают быть нужны сохраняемым копиям. Следующая полная копия сама по себе не гарантирует очистку всей старой цепочки.

- Ручной запуск через фоновый агент доступен после успешного восстановления его очереди. Медленное чтение или ошибка восстановления не разрешают повторную команду для уже принятого задания. Окно повторяет проверку; после восстановления другие задания снова доступны.
- В карточке выбранного файлового/WebDAV-задания виден сохранённый план: полная при каждом запуске, день недели полной копии с переносом пропуска либо число архивов в инкрементной цепочке. Для проверки плана не нужно открывать редактор.
- «Настройки» разделены на пять страниц: «Основное», «Фоновая работа», «Обновления», «Подключения» и «Помощь». Разделы всегда доступны сверху, текст крупнее, технические поля закрыты по умолчанию. Диагностика доступна в «Помощи», действия службы — в «Фоновой работе». Переключение разделов не меняет сохранённые настройки.
- Подсказка автозапуска направляет к установке службы Windows для работы без входа пользователя. Дорожные карты учитывают уже готовые службу агента и сервер мониторинга.

- Добавлено пошаговое руководство для первого запуска: установка, пробная копия с конкретными папками, проверка восстановления, расписание, служба, полная по дню недели, 1С, сеть, SQL и разбор ошибок. Кнопка в «Помощи» открывает установленный HTML без интернета; в комплект входит пример экрана настроек. README и инструкция в ZIP направляют к этому руководству.
- На пустом экране заданий доступна инструкция с пробной копией; ненужные до создания задания кнопки действий скрыты. Кнопка «Помощь на этом шаге» в мастере открывает нужный раздел локального руководства с учётом источника и текущего шага; заполненное задание остаётся открытым. Добавлены подробные шаги WebDAV/Nextcloud, пояснения выбора хранилища и корректная подсказка о работе службы без входа в Windows.

## Доведение Windows перед Linux

- Приоритет Windows зафиксирован в [списке готовности](windows-readiness.md); устаревшие отметки об отсутствии службы и управления ею исправлены. Новое развитие Linux отложено.
- MS SQL: выбор входа через Windows или SQL-логин. Пароль хранится в Windows Vault и защищённом экспорте службы, в JSON остаётся ссылка. Проверка источника и копирование используют одинаковое подключение. При импорте с другим SQL-сервером или без доступного пароля мастер требует сохранить данные заново; новые задания не наследуют чужой SQL-логин.
- PostgreSQL: поиск установленных утилит на Windows, выбор версии и согласованной пары pg_dump/pg_restore. Ручные пути доступны в отдельном блоке; неудачный поиск их не стирает.
- Пароль PostgreSQL можно задать в интерфейсе и передать службе через защищённый DPAPI-кэш. Он не попадает в JSON, аргументы процесса и архив; одноразовый файл подключения создаётся с закрытыми правами и удаляется после операции. Прежний способ входа сохраняется для старых заданий. Импорт на другое подключение требует нового пароля.
- Отдельный Windows CI проверяет настоящую службу агента под временным пользователем без входа в систему: SCM, задания при запуске и вручную, DPAPI-пароль архива, восстановление, остановка, повторный запуск и сохранение профиля при удалении службы.

## Проверка

Windows WPF-сценарий задерживает восстановление реальной принятой команды, имитирует временную ошибку, проверяет блокировку дубликата и восстановление работы. Проверка карточки задания сравнивает сохранённый день полной копии и возврат к числу архивов.
