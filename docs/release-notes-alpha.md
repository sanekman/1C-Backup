# SP Backup 0.2.0-alpha.29 — Windows x64

Накопленные исправления Windows-клиента после alpha.28 и подготовка протокола серверных настроек.

- **Задание «На основе…».** При выборе другой базы 1С подставляется её название из списка; при выборе папки — имя папки. Для прямого пути к `1Cv8.1CD` используется имя родительской папки. Название, введённое вручную, не затирается. Исходное задание не меняется.
- **Копирование закрытой базы 1С.** Включённое разрешение копировать открытую базу больше не добавляет предупреждение само по себе. Сначала удерживается эксклюзивный доступ на всё время архивации; закрытая база завершается успешно без этого предупреждения. Если фактически понадобилось разрешённое совместное чтение, риск остаётся в результате и истории. Проверка ZIP не проверяет целостность работающей базы.
- **Строгая серверная конфигурация.** Неизвестная политика отклоняется целиком без замены прежнего принятого кэша. Возможности согласуются явно; агент не объявляет ещё не подключённое Managed-исполнение.
- **Подтверждения проверки/сохранения.** Предложение связано с ревизией и подключением, кэш проверяется по контрольной сумме, отдельная ограниченная очередь переживает перезапуск. Ошибка новой ревизии не превращается в отказ от прежней, повторные ответы не дублируют аудит. Это подготовка библиотеки, а не включение серверного исполнения в службе.

**Обновление:** остановите приложение и фоновый агент/службу, запустите новый установщик под прежней учётной записью, затем запустите исполнителя, проверьте ближайший запуск и восстановление пробной копии в новую папку. Профили, Vault/DPAPI, существующие архивы и инкрементные цепочки сохраняются; перед обновлением сохраните каталог профиля. Форматы автономных заданий и совместимые технические имена не меняются.

Сервер **preview.4** устанавливается отдельно: новая схема БД 3, административный API ревизий и подтверждений, улучшения панели/установки. Перед обновлением сервера нужна согласованная копия БД, настроек и сертификатов; см. [инструкцию](https://github.com/sanekman/1C-Backup/blob/feature/local-backup-agent/docs/server-upgrade-backup.md). Обновление сервера для обычного автономного копирования не требуется. Веб-мастер и настоящий Managed-исполнитель ещё не подключены.

SDK **10.0.402**, runtime **10.0.13**. Проверяются 794 Windows-теста без пропусков, WPF, настоящие служба/SQL/SMB, установка и обновление с alpha.25. Реальный Hyper-V/domain SMB/reboot и полная матрица ОС остаются отдельными испытаниями. Установщик пока не подписан; прежние теги и файлы выпусков не заменяются.

# SP Backup 0.2.0-alpha.28 — Windows x64

Накопленный пакет защиты подключений и восстановления Windows-агента после alpha.27.

- **Защищённое подключение PostgreSQL.** В мастере можно включить TLS с проверкой сертификата и имени сервера, выбрать корневой сертификат PEM или стандартное доверие libpq. Проверка источника, создание и проверка дампа используют одну политику `verify-full`; внешние сервисные настройки и GSS-шифрование не обходят проверку сертификата.
- **Совместимость со старым агентом.** Защищённые PostgreSQL-задания хранятся отдельно: прежний агент их не видит и не может выполнить без TLS. Обычные задания остаются совместимыми. Для изменения защищённого задания сначала остановите исполнителя; незавершённая запись настроек восстанавливается из подготовленного снимка.
- **Восстановление после аварии.** Дочерние утилиты копирования завершаются вместе с аварийно остановленным фоновым агентом или службой. История получает результат «Прервано», принятые ручные подтверждения не остаются «Принято», старые команды не запускаются снова. Завершённые результаты сохраняются при повторной доставке команды. Окно и трей очищают прогресс прежнего процесса.
- **Нативные Windows-проверки.** Проверены настоящая служба под отдельной учётной записью, авария во время активного `pg_dump`, новый сеанс и восстановление следующей копии. Проверены настоящий обрыв собственной SMB-шары, разрешённый/запрещённый UNC-доступ пользователя службы, шифрование, SHA-256 и восстановленные данные. PostgreSQL проверен с TLS/SCRAM, неверными CA и именем сервера. Установка и переход с опубликованной alpha.25 сохраняют профиль, секреты и прежние архивы.
- Подготовлены изолированный Hyper-V-стенд и пошаговая инструкция для настоящей перезагрузки ОС и отдельного доменного SMB-сервера. **Эти испытания ещё не выполнены**; локальные шары и завершение процесса их не заменяют. Полная матрица Windows, реальная платформа 1С и MS SQL со смешанным режимом/сертификатами требуют отдельных стендов.

**Обновление:** завершите приложение, остановите фоновый агент или службу и запустите установщик под прежней учётной записью Windows. После обновления перезапустите исполнителя, проверьте ближайший запуск и восстановите пробную копию в новую папку. Для TLS PostgreSQL используйте имя, указанное в сертификате; корневой PEM должен читаться пользователем службы. Сам сертификат и пароли не переносятся экспортом настроек. Сохраняйте весь каталог профиля и всю инкрементную цепочку.

SDK **10.0.402**, runtime **10.0.13**. Установщик пока не подписан. Сервер мониторинга устанавливается отдельно; серверное управление заданиями остаётся следующим этапом. Существующие теги и дистрибутивы не заменяются.

# SP Backup 0.2.0-alpha.27 — Windows x64

Пакет надёжности Windows-агента после alpha.26.

- Проверка хранилищ через работающий агент или службу под её пользователем, без остановки расписания и создания копии. Отчёт различает окно и агент и показывает учётную запись.
- При известных временных сетевых ошибках повторяется только доставка готового архива через 2 и 5 секунд. Источник и исправные хранилища не обрабатываются повторно. Ошибки прав, паролей, места и SHA-256 требуют исправления причины.
- Потерянное подтверждение переименования проверяется по размеру и SHA-256; посторонние файлы не заменяются. Ошибки очистки собственного временного файла сохраняются в диагностике.
- Понятные сообщения по UNC/VPN и правам пользователя службы, обновлённое пошаговое руководство.
- Проверены длинные пути с русскими именами, неполный инкремент, восстановление индекса, сохранение готовой копии при новом запуске и отклонение команды старого сеанса. Настоящая перезагрузка Windows и обрыв доменного SMB требуют отдельного стенда.

SDK 10.0.402, runtime 10.0.13. Установщик пока не подписан. Сервер устанавливается отдельно; существующие выпуски и дистрибутивы сохраняются.

# SP Backup 0.2.0-alpha.26 — Windows x64

Накопленный пакет удобства и надёжности Windows-агента после alpha.25.

- **Переименование в SP Backup.** Новые названия программы, установщика и проектов; прежние профили, задания, пароли Windows Vault/DPAPI, службы и архивы совместимы. Старые имена EXE продолжают запускать новые сборки. Настоящее обновление установленной alpha.25 проверено автоматически.
- **Понятное состояние автоматического копирования.** Карточка и трей различают службу, фонового агента, планировщик программы и разовый запуск. Видны ближайший запуск, задания при включении компьютера и автозапуск текущей копии. Устаревшее состояние не выдаётся за работающий планировщик; повторное нажатие не запускает второго исполнителя. Автозапуск другой переносной копии не удаляется и не перезаписывается.
- **Восстановление индекса после сбоя.** Потерянный, повреждённый или отставший индекс инкрементной цепочки восстанавливается по зарегистрированным локальным/UNC-архивам после проверки размеров, SHA-256 и манифестов, включая шифрованные архивы. Сохраняются день полной копии и последние доступные версии пропущенных файлов. Для хранения только на удалённом сервере такое восстановление индекса пока не реализовано; повреждённая или утраченная основа требует новой полной копии.
- **Место в хранилищах.** Перед переносом готового архива в локальную/сетевую папку проверяется доступное пользователю место. При нехватке сообщение показывает нужный и доступный объём. Другие хранилища продолжают получать копию, старые копии заполненного хранилища сохраняются. В проверке хранилищ видно место временной папки и файловых хранилищ; раскрытый отчёт сразу прокручивается в видимую область. Неизвестный объём не блокирует обычную запись. Проверка не резервирует место и не предсказывает размер будущего архива.
- **Подключения к базам.** Понятные действия при известных ошибках MS SQL и неудаче psql. Для мониторинга внешних MS SQL-копий доступен SQL-логин; пароль хранится в Windows Vault и защищённом кэше службы, в JSON остаётся ссылка. Смена сервера требует нового пароля; несохранённые черновики не передают пароль службе.
- Компактные заголовки оставляют больше места для таблиц и мастера. Пошаговое офлайн-руководство обновлено.
- Клиент обновления обращается по постоянному ID репозитория и готов к будущему изменению его имени. Репозиторий пока доступен по прежнему адресу `sanekman/1C-Backup`.

**Обновление с alpha.25:** завершите приложение и фоновый агент или остановите службу. Запустите новый установщик под прежней учётной записью Windows; он сохранит прежнюю папку и профиль. После обновления перезапустите агент/службу, проверьте показанный следующий запуск, сделайте пробную копию и восстановите файл в новую папку. Не удаляйте старые архивы и каталог профиля: для инкрементного восстановления нужна вся цепочка.

Проверены Windows-интерфейс, настоящая служба под отдельной учётной записью, LocalDB, PostgreSQL с парольной аутентификацией, свежая установка и переход с опубликованной alpha.25 с сохранением Vault/DPAPI и восстановлением прежних/новых копий. Реальные UNC-квоты, MS SQL со смешанным режимом и вся матрица Windows Server требуют отдельных стендов; CI не подтверждает их полностью.

Сервер мониторинга остаётся отдельным [preview.3](https://github.com/sanekman/1C-Backup/releases/tag/server-v0.1.0-preview.3); его переустановка для обновления клиента не требуется. Оповещения Telegram/MAX развиваются отдельно.

.NET / ASP.NET Core — **10.0.13**, SDK — **10.0.402**. Установщик пока не подписан. Существующие теги, выпуски и файлы не заменяются.

# Из предыдущих версий

## alpha.25

Большой пакет удобства и надёжности Windows-агента:

- Исправлено сохранение профиля и истории при одновременной работе окна и фонового исполнителя: доставленная копия больше не остаётся в состоянии «Выполняется» из-за конфликта доступа к файлу профиля.
- «Настройки» разделены на пять страниц с более крупным текстом. Технические поля свёрнуты; диагностика и пошаговая инструкция находятся в «Помощи». Офлайн-руководство объясняет установку, первую копию, восстановление, расписание и службу. Помощь доступна прямо из мастера задания.
- При отмене редактирования, Esc и полном выходе можно сохранить изменения, отказаться от них или вернуться. Ошибка сохранения оставляет черновик открытым. Сворачивание в трей сохраняет редактор.
- Для MS SQL добавлен вход по SQL-логину; проверка источника и копирование используют одинаковое подключение. Для PostgreSQL добавлены поиск установленных утилит и ввод пароля в программе. Пароли хранятся в Windows Vault, для службы передаются через защищённый DPAPI-кэш; в JSON остаются только ссылки. Импорт на другое подключение требует повторного ввода пароля. Прежние способы входа сохраняются; проверка TLS не отключается.
- После восстановления очереди ручных команд другие задания снова доступны без повторного запуска уже принятой команды. В карточке задания виден план полной копии. Предупреждение о длинной цепочке поясняет, что архивы удаляются автоматически, когда перестают быть нужны сохраняемым копиям; следующая полная копия сама по себе не гарантирует очистку всей старой цепочки.

Проверены Windows-интерфейс, настоящая служба под отдельной учётной записью, копирование и восстановление PostgreSQL с парольной аутентификацией, LocalDB, установщик и установленное приложение. Вход MS SQL по SQL-логину требует проверки на вашей конфигурации сервера; нативная SQL-проверка выпуска использует Windows-аутентификацию LocalDB.

**Обновление с alpha.24:** полностью завершите приложение и фоновый агент или остановите службу, затем запустите новый установщик под прежней учётной записью Windows. После обновления перезапустите агент/службу, проверьте следующий запуск и сделайте пробную копию. Настройки, история и архивы сохраняются. Формат архивов не изменён; неполные копии и инкрементные цепочки продолжают следовать выбранному плану. Для восстановления нужна вся цепочка.

Сервер мониторинга остаётся отдельным выпуском [preview.3](https://github.com/sanekman/1C-Backup/releases/tag/server-v0.1.0-preview.3); его переустановка для обновления клиента не требуется. Оповещения Telegram/MAX развиваются отдельно.

.NET / ASP.NET Core — **10.0.13**, SDK — **10.0.402**. Установщик пока не подписан. Старые выпуски и дистрибутивы не заменяются.



## alpha.24

Для инкрементных заданий «Файлы и папки» и WebDAV добавлен выбор дня недели полной копии. Первая копия всегда полная; последующие полные создаются при первом запуске в выбранный день, а если день пропущен — при ближайшем запуске после него. Остальные запуски инкрементные. Используется часовой пояс задания. Несколько запусков в один день не создают повторную полную копию.

В мастере выберите «Когда делать полную копию» → нужный день. Для прежнего режима выберите «По числу архивов». Выбранный день сохраняется в задании и переносится при экспорте/импорте; старые задания без него работают как раньше. Защитный предел цепочки — 365 архивов. Ошибки отдельных файлов и неполные копии сохраняют выбранный план; неудачная попытка полной копии не отменяет её повтор при ближайшем запуске. После обновления перезапустите агент/службу вместе с приложением.

Включены изменения alpha.23:

Название источника и упоминания СУБД в интерфейсе, подсказках и сообщениях приведены к «MS SQL». Настройки подключения и сохранённые задания совместимы.

Включены исправления alpha.22:

Исправлена очередь ручных запусков: ошибка записи подтверждения одной команды больше не блокирует другие задания. Проблемная команда повторяется с паузой; после восстановления доступа предупреждение снимается. Ошибка записи итогового подтверждения не приводит к повторному созданию уже завершённой копии.

После повторного открытия окна приложение восстанавливает сведения о ручных запусках, уже принятых фоновым агентом или службой. Повторный щелчок такого задания остаётся заблокированным до завершения попытки, а другие сохранённые задания доступны для запуска.

Включены исправления alpha.21:

Ручной запуск сохранённого задания доступен при включённом расписании в окне, фоновом агенте и службе Windows. Это относится и к заданиям без расписания или с отключёнными автоматическими запусками. Если исполнитель занят, ручной запуск ждёт своей очереди; копии выполняются последовательно, расписание продолжает работать. Повторный щелчок не добавляет ещё один запуск того же задания. Команды привязаны к сеансу агента и не воспроизводятся после его перезапуска; если сеанс прерван, проверьте историю перед повторным запуском. Для этой функции обновите и перезапустите фоновый агент или службу вместе с приложением.

Исправлена остановка отправки мониторинга из фонового агента после временной ошибки HTTP или тайм-аута. Агент продолжает повторные попытки, показывает предупреждение и снимает его после восстановления связи. Резервное копирование продолжает работать независимо от доступности сервера.

Сохранены возможности alpha.20:

Добавлено простое подключение к серверу мониторинга: **Мониторинг на сервере Windows → Подключить по приглашению**. Перенесите из панели адрес сервера, одноразовый код и SHA-256 сертификата. Токен сохраняется в защищённом хранилище Windows; задания и локальное расписание остаются на месте. Режим Managed для мониторинга включать не нужно.

В общей панели доступны связь с компьютером, задания и следующий запуск, текущая стадия и процент, история, неполные копии, результаты доставки по хранилищам и внешние SQL-копии. Недоставленные отчёты сохраняются в локальной истории и повторяются после восстановления связи без дублей; ошибка отдельного отчёта не блокирует остальные. Для отправки при закрытом окне включите фоновый агент или службу Windows.

Сервер устанавливается отдельно: [SP Backup Server 0.1.0-preview.3](https://github.com/sanekman/1C-Backup/releases/tag/server-v0.1.0-preview.3). Сохранены изменения файлового копирования из alpha.19:


Большое задание «Файлы и папки» больше не начинает архив заново из-за ошибки отдельного файла. Доступные файлы сохраняются сразу, а проблемные получают одну повторную попытку после остальных. Если файл всё ещё недоступен, занят, изменяется или не читается, он остаётся в списке пропусков; проверенная и доставленная копия завершает задание с предупреждениями. Успешно захваченные версии не перечитываются из-за последующих изменений источника.

Ошибки не превращают инкрементную копию в полную. Полные копии создаются по заданному интервалу; следующая копия после неполной также следует этому плану. Для пропущенных файлов инкремент сохраняет последние доступные версии из предыдущих архивов, если они есть. Пропуск не считается удалением. Следующий запуск снова пытается прочитать эти файлы. При неполном перечислении папки сохраняются уже найденные данные. Конфликт имён, различающихся только регистром, явно отмечает родительскую папку неполной.

Каталог, проверка и восстановление показывают неполноту копии и нужное число архивов цепочки. При восстановлении пропущенного файла может использоваться прежняя версия; её наличие не подтверждает актуальность. Неполная копия не запускает удаление прежних архивов, а очистка сохраняет все необходимые зависимости.

**Совместимость:** неполные инкременты и частично перечисленные папки используют формат индекса 3. Для проверки и восстановления таких архивов нужна alpha.19 или новее и вся цепочка. Старые архивы форматов 1 и 2 поддерживаются. Не удаляйте старые архивы и каталог приложения при обновлении.

Каждый файл предварительно читается и проверяется в закрытой временной папке; дополнительное место требуется для одного файла за раз. Ошибка чтения не оставляет оборванную запись в ZIP. Ошибки записи архива, нехватка места, повреждение ZIP, отмена и неудачная доставка не выдаются за успешную копию.
