# 1C-Backup 0.2.0-alpha.25 — Windows x64

Большой пакет удобства и надёжности Windows-агента:

- Исправлено сохранение профиля и истории при одновременной работе окна и фонового исполнителя: доставленная копия больше не остаётся в состоянии «Выполняется» из-за конфликта доступа к файлу профиля.
- «Настройки» разделены на пять страниц с более крупным текстом. Технические поля свёрнуты; диагностика и пошаговая инструкция находятся в «Помощи». Офлайн-руководство объясняет установку, первую копию, восстановление, расписание и службу. Помощь доступна прямо из мастера задания.
- При отмене редактирования, Esc и полном выходе можно сохранить изменения, отказаться от них или вернуться. Ошибка сохранения оставляет черновик открытым. Сворачивание в трей сохраняет редактор.
- Для MS SQL добавлен вход по SQL-логину; проверка источника и копирование используют одинаковое подключение. Для PostgreSQL добавлены поиск установленных утилит и ввод пароля в программе. Пароли хранятся в Windows Vault, для службы передаются через защищённый DPAPI-кэш; в JSON остаются только ссылки. Импорт на другое подключение требует повторного ввода пароля. Прежние способы входа сохраняются; проверка TLS не отключается.
- После восстановления очереди ручных команд другие задания снова доступны без повторного запуска уже принятой команды. В карточке задания виден план полной копии. Предупреждение о длинной цепочке поясняет, что архивы удаляются автоматически, когда перестают быть нужны сохраняемым копиям; следующая полная копия сама по себе не гарантирует очистку всей старой цепочки.

Проверены Windows-интерфейс, настоящая служба под отдельной учётной записью, копирование и восстановление PostgreSQL с парольной аутентификацией, LocalDB, установщик и установленное приложение. Вход MS SQL по SQL-логину требует проверки на вашей конфигурации сервера; нативная SQL-проверка выпуска использует Windows-аутентификацию LocalDB.

**Обновление с alpha.24:** полностью завершите приложение и фоновый агент или остановите службу, затем запустите новый установщик под прежней учётной записью Windows. После обновления перезапустите агент/службу, проверьте следующий запуск и сделайте пробную копию. Настройки, история и архивы сохраняются. Формат архивов не изменён; неполные копии и инкрементные цепочки продолжают следовать выбранному плану. Для восстановления нужна вся цепочка.

Сервер мониторинга остаётся отдельным выпуском [preview.3](https://github.com/sanekman/1C-Backup/releases/tag/server-v0.1.0-preview.3); его переустановка для обновления клиента не требуется. Оповещения Telegram/MAX развиваются отдельно.

.NET / ASP.NET Core — **10.0.13**, SDK — **10.0.402**. Установщик пока не подписан. Старые выпуски и дистрибутивы не заменяются.

# Из предыдущих версий

## alpha.24

Для инкрементных заданий «Файлы и папки» и WebDAV добавлен выбор дня недели полной копии. Первая копия всегда полная; последующие полные создаются при первом запуске в выбранный день, а если день пропущен — при ближайшем запуске после него. Остальные запуски инкрементные. Используется часовой пояс задания. Несколько запусков в один день не создают повторную полную копию.

В мастере выберите «Когда делать полную копию» → нужный день. Для прежнего режима выберите «По числу архивов». Выбранный день сохраняется в задании и переносится при экспорте/импорте; старые задания без него работают как раньше. Защитный предел цепочки — 365 архивов. Ошибки отдельных файлов и неполные копии сохраняют выбранный план; неудачная попытка полной копии не отменяет её повтор при ближайшем запуске. После обновления перезапустите агент/службу вместе с приложением.

Включены изменения alpha.23:

Название источника и упоминания СУБД в интерфейсе, подсказках и сообщениях приведены к «MS SQL». Настройки подключения и сохранённые задания совместимы.

Включены исправления alpha.22:

Исправлена очередь ручных запусков: ошибка записи подтверждения одной команды больше не блокирует другие задания. Проблемная команда повторяется с паузой; после восстановления доступа предупреждение снимается. Ошибка записи итогового подтверждения не приводит к повторному созданию уже завершённой копии.

После повторного открытия окна приложение восстанавливает сведения о ручных запусках, уже принятых фоновым агентом или службой. Повторный щелчок такого задания остаётся заблокированным до завершения попытки, а другие сохранённые задания доступны для запуска.

Включены исправления alpha.21:

Ручной запуск сохранённого задания доступен при включённом расписании в окне, фоновом агенте и службе Windows. Это относится и к заданиям без расписания или с отключёнными автоматическими запусками. Если исполнитель занят, ручной запуск ждёт своей очереди; копии выполняются последовательно, расписание продолжает работать. Повторный щелчок не добавляет ещё один запуск того же задания. Команды привязаны к сеансу агента и не воспроизводятся после его перезапуска; если сеанс прерван, проверьте историю перед повторным запуском. Для этой функции обновите и перезапустите фоновый агент или службу вместе с приложением.

Исправлена остановка отправки мониторинга из фонового агента после временной ошибки HTTP или тайм-аута. Агент продолжает повторные попытки, показывает предупреждение и снимает его после восстановления связи. Резервное копирование продолжает работать независимо от доступности сервера.

Сохранены возможности alpha.20:

Добавлено простое подключение к серверу мониторинга: **Мониторинг на сервере Windows → Подключить по приглашению**. Перенесите из панели адрес сервера, одноразовый код и SHA-256 сертификата. Токен сохраняется в защищённом хранилище Windows; задания и локальное расписание остаются на месте. Режим Managed для мониторинга включать не нужно.

В общей панели доступны связь с компьютером, задания и следующий запуск, текущая стадия и процент, история, неполные копии, результаты доставки по хранилищам и внешние SQL-копии. Недоставленные отчёты сохраняются в локальной истории и повторяются после восстановления связи без дублей; ошибка отдельного отчёта не блокирует остальные. Для отправки при закрытом окне включите фоновый агент или службу Windows.

Сервер устанавливается отдельно: [1C-Backup Server 0.1.0-preview.3](https://github.com/sanekman/1C-Backup/releases/tag/server-v0.1.0-preview.3). Его офлайн-установщик включает PostgreSQL 17, .NET 10.0.13, HTTPS и службы Windows. Для первоначальной установки отдельно задаются понятное имя системы мониторинга, полный HTTPS-адрес подключения и пароль администратора. [Инструкция](https://github.com/sanekman/1C-Backup/blob/feature/local-backup-agent/docs/server-start.md).

Сохранены изменения файлового копирования из alpha.19:


Большое задание «Файлы и папки» больше не начинает архив заново из-за ошибки отдельного файла. Доступные файлы сохраняются сразу, а проблемные получают одну повторную попытку после остальных. Если файл всё ещё недоступен, занят, изменяется или не читается, он остаётся в списке пропусков; проверенная и доставленная копия завершает задание с предупреждениями. Успешно захваченные версии не перечитываются из-за последующих изменений источника.

Ошибки не превращают инкрементную копию в полную. Полные копии создаются по заданному интервалу; следующая копия после неполной также следует этому плану. Для пропущенных файлов инкремент сохраняет последние доступные версии из предыдущих архивов, если они есть. Пропуск не считается удалением. Следующий запуск снова пытается прочитать эти файлы. При неполном перечислении папки сохраняются уже найденные данные. Конфликт имён, различающихся только регистром, явно отмечает родительскую папку неполной.

Каталог, проверка и восстановление показывают неполноту копии и нужное число архивов цепочки. При восстановлении пропущенного файла может использоваться прежняя версия; её наличие не подтверждает актуальность. Неполная копия не запускает удаление прежних архивов, а очистка сохраняет все необходимые зависимости.

**Совместимость:** неполные инкременты и частично перечисленные папки используют формат индекса 3. Для проверки и восстановления таких архивов нужна alpha.19 или новее и вся цепочка. Старые архивы форматов 1 и 2 поддерживаются. Не удаляйте старые архивы и каталог приложения при обновлении.

Каждый файл предварительно читается и проверяется в закрытой временной папке; дополнительное место требуется для одного файла за раз. Ошибка чтения не оставляет оборванную запись в ZIP. Ошибки записи архива, нехватка места, повреждение ZIP, отмена и неудачная доставка не выдаются за успешную копию.

.NET / ASP.NET Core — 10.0.13, SDK — 10.0.402. Перед обновлением полностью завершите приложение и агент или остановите службу. Настройки, секреты и копии сохраняются. Установщик пока не подписан.
