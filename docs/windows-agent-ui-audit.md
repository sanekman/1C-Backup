# Аудит интерфейса Windows-агента SP Backup

18 ноября 2026 года. Проверены исходники WPF на `301a2ad` и сохранённые снимки
установленной alpha.35 (`0da787d`), в том числе компактное окно и тёмная тема.
Изменений WPF между этими коммитами нет. Это аудит по коду и снимкам.
Новый живой прогон Windows, клавиатуры и экранного диктора не выполнялся.

Предлагаю начать с двух вещей. Пользователь должен видеть, для какого адреса
он задаёт доступ и кто его проверяет. В «Настройках» на первом экране каждого
раздела должны помещаться его основные действия.

Здесь результат проверки относится к сохранённому заданию. В черновике
можно предложить сохранить задание и затем использовать имеющуюся проверку
через нужного исполнителя. Подключение из окна не подтверждает доступ
службы. Проверка должна различать ошибку входа, прав, сети и сертификата
в тех случаях, когда исполнитель их различает.

| Назначение | Что показывать в форме |
| --- | --- |
| FTP / FTPS | Адрес, порт, режим защиты, логин и пароль для хранилища. |
| NAS / UNC | Сетевая папка и выбранный способ входа. При отдельном входе — логин и пароль именно для этой папки. |
| WebDAV | Адрес источника и логин. Если выбранный провайдер требует пароль приложения, объяснить это рядом с полем. |
| MS SQL и наблюдение SQL | Сервер и способ входа. При входе Windows показать, чьи права используются. При SQL-входе — поля SQL-логина и пароля. |
| PostgreSQL | Сервер, порт, пользователь и способ входа. Пользователь задаётся один раз, пароль в отдельной форме. Внешние настройки описывать относительно исполнителя. |
| Выгрузка 1С в DT | Папка базы и пользователь информационной базы, поля логина и пароля 1С. |
| Служба Windows | Пользователь, под которым запускается служба, и пароль Windows при установке или смене учётной записи. Уточнение про PIN разместить у поля. |
| Шифрование ZIP | Только пароль архива. Подтверждение при создании, отдельный одноразовый ввод для восстановления. Предыдущие копии сохраняют свой пароль. |
| Приглашение, Google Drive, GitHub и оповещения | Сохранить соответствующий вид доступа. Для приглашения — код и HTTPS. Для Google Drive — вход в браузере. Для GitHub и оповещений — явно названные токены. |

В работе с секретами сохранить отдельную запись черновика, применение после
сохранения, сохранность старых копий и защищённую передачу нужному исполнителю.
Подтвердить, что отмена не меняет действующий доступ. Поддержка смены
серверных привязок при работающей службе требует отдельной проверки.

## Настройки

Снимки компактных «Подключений» и «Фоновой работы» показывают общую проблему.
Заголовок, пояснение, карточка автоматического копирования и ряд разделов
занимают верхнюю часть окна. После этого основное действие службы или применения
режима находится ниже видимой области. В «Основном» при этом отдельная большая
страница содержит почти только выбор темы. [Разметка настроек](../src/SPBackup.Desktop/MainWindow.xaml#L611)

| Раздел | Что предлагаю |
| --- | --- |
| Общая верхняя панель | На «Заданиях» сохранить действие управления расписанием. В настройках, истории и копиях оставить компактное состояние исполнителя, а предупреждения и текущую операцию по-прежнему показывать явно. Убрать строку под заголовком, которая перечисляет вкладки. |
| Основное | Объединить выбор темы, установленную версию и вход в помощь. Убрать кнопку «Перейти к заданиям», поскольку раздел уже виден слева. |
| Фоновая работа | Сверху показать, что сейчас запускает задания и под каким пользователем. Ниже оставить автозапуск после входа и службу без входа. Для установленной службы показать «Запустить» / «Остановить» рядом со статусом, ввод пароля открывать только при настройке. Режим работы в окне оставить в дополнительных параметрах. |
| Подключения | Вынести карточку «Сервер управления» с адресом, состоянием связи и временем последнего подтверждения. Пока сервер не подключён, оставить основным действие «Подключить по приглашению…». После подключения показать текущий источник заданий и эффект его смены. Параметры опроса хранить рядом с настройками сервера. Шлюз хранилища оставить в дополнительных, переход к оповещениям показать отдельной строкой. |
| Обновления | Показать установленную версию, результат и время последней проверки. Показывать установку и «Что нового», когда версия найдена. В дополнительных параметрах оставить канал, автоматические действия и закрытый репозиторий при необходимости. |
| Помощь и завершение работы | Выделить «Открыть инструкцию» и «Сохранить диагностику…», ниже разместить сведения о сборке и журналы. Перенести «Выйти полностью» в меню приложения рядом с закрытием окна и подписать текущий эффект для агента и службы по фактическому поведению. |

Для каждого поля явно показать момент применения. Тема и предпочтения
обновления сохраняются сразу, режим агента и автозапуск требуют действий,
а установка службы — отдельного подтверждения Windows. Если действие
недоступно, рядом с ним должна быть причина и следующий шаг.

## Порядок исправлений

1. **Доступ и предсказуемое применение.** Начать с FTP/FTPS, NAS и ZIP в мастере,
   включая дополнительные хранилища и повторное открытие. Проверить привязку
   доступа при смене адреса и аналогичные переходы для WebDAV, SQL и 1С.
   Затем распространить общий шаблон на эти формы и серверные задания.
2. **Настройки и служба.** Собрать компактный макет «Фоновая работа» и
   «Подключения», показать его перед полировкой. Затем привести к нему
   «Основное», «Обновления» и «Помощь».
3. **Рабочие экраны.** Сгруппировать действия заданий и диагностики, упростить
   копии, историю и мониторинг SQL с сохранением текущих фильтров и переходов.

Первый пакет можно принять по сценарию «открыть существующее задание → вручную
сменить адрес или логин → отменить → убедиться, что задание прежнее → повторить,
сохранить и проверить под фактическим исполнителем». Дополнительно проверить
неверный пароль, недоступный адрес, активную службу, сохранение старого пароля
архива у прежней копии и переход к доступу серверного задания. Для каждой
затронутой формы проверить светлую и тёмную темы, 900×580, масштаб 125–150%,
длинный адрес, Tab, Enter и Esc. Для графической проверки использовать
установленный Windows-пакет и свежие снимки. Пройденные проверки копирования
и восстановления переиспользовать там, где поведение не изменилось.
