# Резервная копия самого Windows-сервера

Базовая возможность доступна с **Server preview.7**; проверка полного состава программы и комплект обновления описаны для кандидата этапа 6 (ещё не опубликован) для штатной Windows-установки. Она копирует **сервер мониторинга**, а не базы и файлы заданий агентов.

Поддерживается штатная Windows-установка со встроенной PostgreSQL 17. Возврат выполняется **на том же компьютере, в прежние папки и с точно тем же комплектом программы**. Не используйте этот способ для переноса на другой ПК или после переустановки Windows: ключи панели защищены Windows DPAPI. Для потери всего компьютера дополнительно нужна проверенная системная копия Windows. Внешняя PostgreSQL, внешние сертификаты/табличные пространства, сетевые папки, SUBST и ссылки требуют отдельной процедуры.

## Создать копию

1. Выберите время обслуживания. Панель и приём отчётов ненадолго остановятся. Агенты продолжают принятый план без связи и передадут очередь позже.
2. Откройте **Пуск → SP Backup Server → Создать резервную копию сервера** и подтвердите запрос администратора.
3. Прочитайте сообщение и выберите папку на **локальном NTFS-диске**, лучше на другом физическом диске. Не выбирайте папку программы или её данных. Внутри выбранной папки автоматически создаётся новое имя с датой; прежние копии не заменяются.
4. Дождитесь результата. Сначала останавливается сервер, затем PostgreSQL. Копируются БД, настройки, сертификат, ключи панели и файлы данных; проверяются SHA-256 всех файлов. Службы возвращаются к исходному состоянию.
5. В готовой папке находятся `snapshot.json` и подпапка `data`. Отсутствие `snapshot.json` означает незавершённую копию — применять её нельзя. Незавершённые файлы сохраняются, рабочие данные не удаляются.

Папка закрыта ACL для **Администраторов и SYSTEM**. Она содержит пароли, закрытый ключ сертификата и данные доступа агентов. Это не диагностический ZIP: не отправляйте её поддержке, не размещайте в общедоступной папке. Файлы внутри не редактируйте. При восстановлении задаются штатные ACL: Администраторы и SYSTEM имеют полный доступ, NetworkService — изменение. Пользовательские ACL не переносятся. Шифрование переносимого архива пока не реализовано.

## Проверить копию

1. Откройте **Пуск → SP Backup Server → Проверить резервную копию сервера**.
2. Выберите саму папку копии с `snapshot.json`, а не её подпапку `data`.
3. Дождитесь проверки состава, папок и SHA-256, компьютера и комплекта программы. Работа сервера не останавливается.

Проверка файлов не заменяет пробное восстановление БД. В текущей реализации поддерживаются до 200000 файлов, до 250000 записей вместе с папками и описание не более 16 МиБ. На диске назначения нужен объём всей копии и ещё 1 ГиБ резерва; при восстановлении это дополнительное место на диске рабочих данных. Свободное место проверяется до копирования и перед каждым файлом, но не резервируется от других программ. При превышении или ошибке не получается «частично готовая» БД: операция завершается без пригодной к восстановлению копии. Прежние копии и рабочая база сохраняются.

## Восстановить

1. Убедитесь, что это тот же компьютер и установлены те же файлы сервера и PostgreSQL. Если обновляли программу, используйте заранее созданный [полный комплект возврата](server-upgrade-backup.md). В новых копиях формата 2 проверяется полный состав программы, runtime, зависимостей и PostgreSQL, кроме изменяемых Inno-файлов `uninsNNN.exe/dat/msg`. Копии формата 1 продолжают проверяться по трём прежним исполняемым файлам; этот старый формат не доказывает совпадение всех зависимостей. Старый EXE нельзя запускать поверх новой схемы БД.
2. Откройте **Пуск → SP Backup Server → Восстановить сервер из копии**, выберите папку готовой копии и подтвердите действие.
3. Программа проверит копию и подготовит отдельную папку. Только после успешной проверки остановит службы и заменит папку данных. Предыдущие данные сохранятся рядом с именем `OneCBackupServer.before-restore-...`.
4. После возврата запускаются PostgreSQL и сервер, затем проверяется готовность по HTTPS. Для штатного сертификата используется `localhost` и обычное доверие Windows: проверка TLS не отключается. Если запуск не подтверждён, программа пытается вернуть предыдущую папку и исходное состояние служб. Подготовленные и прежние данные не удаляются, даже при ошибке возврата.
5. Откройте панель, войдите с **паролем на дату копии**. Проверьте папки, агентов, историю, часовой пояс и свежий отчёт агента. Возвращаются также прежние права доступа и токены: если после даты копии отзывали доступ, повторите отзыв или смену пароля.
6. Не удаляйте прежнюю папку данных, пока не проверили результат. Она тоже содержит секреты и должна храниться закрыто.

Для восстановления после переустановки Windows, на другую машину, с внешней БД/сертификатом или с другим выпуском нужна отдельная процедура. Операция обычного восстановления возвращает только данные. Отдельные операции **Подготовить обновление / Проверить комплект возврата / Вернуть программу и данные** работают с полным комплектом, включающим программу. Ни одна из них не переносит DPAPI между компьютерами.

## Если операция прервалась

Не считайте папку без `snapshot.json` готовой копией. Откройте `services.msc`: штатные службы называются **OneCBackupServerDatabase** и **OneCBackupServer**. После неудачного создания копии данные остаются на месте; при необходимости запустите сначала БД, затем сервер. После прерванного восстановления сохраните папки `.restore-...` и `.before-restore-...`; не смешивайте их файлы вручную. Убедитесь, какая папка находится по рабочему пути, и используйте проверенную копию. Если запуск Windows/доверие сертификату повреждены, одна копия данных не исправит настройки ОС.
