# 1C-Backup

Начата серверная часть: минимальная веб-панель, PostgreSQL, регистрация агентов, конфигурация и heartbeat. [Запуск на Windows, Linux и через Docker Compose](docs/server-start.md). Управляемое копирование и редактор серверных заданий ещё предстоит подключить; автономное приложение продолжает работать отдельно.

Агент резервного копирования для Windows с графическим интерфейсом: файлы и папки, файлы WebDAV, файловые базы 1С, Microsoft SQL Server и PostgreSQL. Может работать автономно или под управлением сервера через API. Ориентир по возможностям — Effector Saver.

## Оформление и имена копий

В «Настройки → Оформление» доступны системная тема (по умолчанию), светлая и тёмная. Выбор сохраняется в профиле пользователя. Системная тема следует изменениям оформления Windows без перезапуска; окно, мастер, таблицы и диалоги используют общую палитру.

Локальные задания всегда используют местное время компьютера. При загрузке старых заданий сохраняются часы запуска, а ранее выбранный пояс заменяется местным. Внутренние отметки UTC в журнале и API остаются для однозначного обмена с сервером. Метки старых внешних SQL-наблюдений переводятся из записанного пояса источника в местное время только для отображения.

Новые файлы копий имеют вид `Бухгалтерия_2026-10-12_14-30-00_a1b2c3.dt.zip`. Дата и время местные; случайный суффикс из 6 символов различает повторные запуски и одноимённые задания. Знаки, запрещённые в именах Windows, заменяются на `_`, имя задания ограничивается 80 символами. Связь с заданием и инкрементной цепочкой остаётся в каталоге; переименование задания сохраняет старые копии и правила хранения.

## Диагностика для анализа

При проблеме откройте **«Настройки → Диагностика → Сохранить диагностику…»**, выберите папку вне рабочего профиля и отправьте полученный ZIP вместе с примерным временем проблемы и описанием ожидаемого результата. Отправка выполняется вручную; приложение ничего не загружает автоматически. Существующие файлы не перезаписываются. Выгрузка доступна также при недоступном источнике или повреждённой истории.

Окно и фоновый агент автоматически ведут отдельные структурированные `.jsonl` в `%LOCALAPPDATA%\OneCBackup\logs` (при отдельном профиле — `<profile>/logs`). Кнопка «Открыть папку логов» открывает этот каталог. Записываются время UTC, компонент / PID / сессия, точная версия и коммит, ID задания и запуска, создание копии, доставка в каждое хранилище, регистрация, очистка, результат / длительность / размер, отмена и сбои. Для WebDAV добавлены этапы перечисления / повторной проверки и количество скачанных файлов / байт. Для внешних программ записывается код завершения, без аргументов и вывода. Опрос `--status` не создаёт новые файлы логов. Обнаруженные при запуске незавершённые операции отмечаются отдельно.

Логи ротируются по UTC-дню и размеру (до 2 МБ на файл), старые журналы удаляются после 14 дней; общий бюджет — 50 МБ. Ошибка записи журнала не останавливает резервное копирование и не заменяет историю выполнения. ZIP содержит распознанные события, сведения о версии / .NET / системе / часовом поясе, до 1000 последних запусков в сокращённом виде и инструкцию. Неполные, неизвестные или недоступные записи пропускаются с указанием количества; повреждённая история помечается как недоступная.

В логи и ZIP не записываются пароли, токены, учётные записи, адреса подключений, пути исходных файлов, названия заданий, настройки, копии, содержимое файлов или сырой вывод SQL / 1С. Для ошибок сохраняются тип, HRESULT, доступный числовой код и стек методов без путей исходного кода. `Exception.Message`, `Data`, строки подключения и сообщения сторонних инструментов намеренно исключены: они могут содержать секреты. Поэтому при отправке полезно описать видимую проблему своими словами. Диагностика не меняет задания, историю и каталог копий.

## Файлы WebDAV

В мастере выберите **«Файлы WebDAV»**, укажите конечный HTTPS-адрес папки и сохраните логин / пароль приложения кнопкой **«Логин и пароль…»**. Поддерживается Basic-аутентификация по HTTPS с обычной проверкой сертификата; OAuth, вход через браузер, HTTP и перенаправления не поддерживаются. Пароль хранится в отдельной записи диспетчера учётных данных Windows текущего пользователя, в JSON передаётся только её идентификатор. Агент должен работать под тем же пользователем. При переносе задания на другой компьютер сохраните учётные данные заново.

Полная копия скачивает все файлы. Инкрементная сначала создаёт полную основу, затем использует сильный `ETag` вместе с размером файла, чтобы не скачивать неизменённое содержимое. Без `ETag` или со слабым `ETag` файл скачивается каждый раз и сравнивается по SHA-256; размер и дата сами по себе не служат доказательством равенства. Периодическая полная копия, ZIP AES-256, несколько хранилищ, независимые лимиты, проверка цепочки и «Восстановить файлы…» работают как для локальных файлов. Новые / изменённые / удалённые файлы и пустые папки учитываются. Восстановление выполняется в новую локальную папку; запись обратно на WebDAV отсутствует.

Список читается рекурсивными `PROPFIND Depth: 1`; нужен доступ на перечисление и чтение всей выбранной папки, включая размер каждого файла. Сильный `ETag` проверяется также при `GET` с `If-Match`. Перед завершением агент повторно читает список и проверяет версии. Ошибка доступа, неполный ответ или обнаруженное изменение прерывают запуск без регистрации копии и очистки прежних архивов. Это **не единый снимок серверной папки**: избегайте изменений во время запуска; сервер должен корректно обновлять `ETag`. Права, владельцы, серверные версии файлов и настройки Nextcloud не сохраняются; копируется только доступное содержимое папки. Если сервер скрывает недоступные элементы без сообщения об ошибке, агент не может определить их наличие.

Выберите временную папку на HDD: файлы скачиваются по одному, архив создаётся и проверяется там же. Полная локальная синхронизация источника не создаётся. Ограничения: 100 000 файлов, 100 000 папок, список одной папки / индекс до 32 МБ; имена должны быть допустимы для восстановления в Windows. Глубина цепочки — от 1 до 365 архивов. По умолчанию ограничение одного запуска — 120 минут, настраивается от 1 до 1440. «Проверить источник» проверяет перечисление папок без скачивания файлов; доступ к содержимому и восстановление проверьте первой копией.

## Текущее состояние

Начальная версия приложения на C#/.NET 10 и WPF: список заданий и пошаговый мастер настройки, отдельные разделы истории запусков и настроек агента, окно мониторинга внешних SQL-копий. Панель автоматического копирования и статус операции доступны во всех разделах. Поддерживаются создание, изменение, отключение, удаление и локальное сохранение заданий. Кнопка «На основе…» создаёт новое задание с настройками выбранного: измените название и источник в мастере. Автоматические запуски нового задания отключены до проверки; исходное задание и его копии сохраняются. Реализована проверка обязательных полей, типа базы, расписания и количества сохраняемых копий. Файл записывается через временный файл; ошибка чтения блокирует перезапись повреждённых настроек.

Доступны два способа копирования файловой базы 1С: выгрузка `.dt` через установленную платформу и ZIP файла `1Cv8.1CD` без платформы. Для SQL Server подключены `BACKUP DATABASE` и проверка, для PostgreSQL — `pg_dump` и проверка каталога дампа. Ручной запуск работает в окне; расписание может выполнять окно или отдельный фоновый агент текущего пользователя. Подключены доставка на локальный диск или в сетевой каталог и очистка зарегистрированных копий. **Фоновая служба пока не реализована.** Исполнители проверены с подменёнными соединениями и процессами; интерфейс и диспетчер учётных данных проверены в Windows CI. В Windows CI проверены настоящие копии и восстановление в отдельных временных SQL Server LocalDB и PostgreSQL, включая ZIP AES-256 и два хранилища. Удалённые SQL-соединения с целевыми сертификатами / правами и настоящая платформа 1С требуют отдельных проверок.

Реализована основа агентской архитектуры: режимы, отдельный кэш серверных заданий, клиент HTTPS API для конфигурации и heartbeat и независимые циклы связи/расписания с подключаемым исполнителем. Начальная серверная основа реализована; рабочее управляемое копирование, локальный IPC, защищённое хранилище агентского токена и готовая служба Windows ещё не подключены. Интерфейс запускает локальные задания и управляет отдельным автономным фоновым агентом; сетевой обмен с сервером не включён.

Версия программы видна в боковой панели. В «Настройках» → «О программе» можно скопировать версию, идентификатор сборки, версию .NET, архитектуру и систему для сообщения об ошибке. Пути, настройки заданий и пароли в эти сведения не включаются. Релизные сборки GUI и агента получают версию из Git-тега, локальные — `0.1.0-dev`. В дистрибутиве также есть `VERSION.txt`.

На шаге «Расписание» мастер показывает три ближайших запуска по местному времени Windows. Даты обновляются при изменении времени и дней и при переходе к шагу; они также включены в итог перед сохранением. Для ручного режима и отключённого расписания показано пояснение. Это плановое время: выполнение требует работающего планировщика и включённого компьютера.

В истории выбранный запуск показывает дальнейшие действия для ошибки, частичной доставки, отмены, прерывания и предупреждений. «К заданию» открывает текущую базу по идентификатору и сбрасывает скрывающий её поиск, чтобы можно было изменить настройки или вручную повторить копирование. Сам переход не запускает копию. Если задание недоступно, история остаётся, кнопка объясняет причину. Повтор частичной доставки создаёт новую копию для всех хранилищ.

Настройки интерфейса: `%LOCALAPPDATA%\OneCBackup\jobs.json`. Пароли в этом файле не хранятся. Для службы будет отдельное общее хранилище с разграничением доступа.

В каталоге копий доступны выбор задания, фильтр локальных / сетевых / FTP-хранилищ и поиск по названию или пути. Кнопка «Последняя копия» открывает копии выбранной базы и снимает скрывающие запись условия. «Сбросить» возвращает общий список. Обновление сохраняет фильтры и выбранную копию. Подробности пути, SHA256 и результатов проверки раскрываются отдельно, чтобы таблица оставалась видна в компактном окне.

В списке заданий кнопка «Включить / Выключить расписание» меняет разрешение автоматических запусков выбранной базы без мастера. Настройки времени, хранилищ, архива и копии сохраняются. Для ручных заданий сначала задайте время через «Изменить». Для выполнения расписания включите автоматическое копирование; работающий планировщик учитывает изменение при следующем обновлении заданий. Уже принятые к выполнению операции продолжаются, ручное копирование остаётся доступным.

## Дистрибутив Windows

Целевые серверные ОС локального приложения: Windows Server 2016, 2019, 2022 и 2025 x64 с Desktop Experience. В alpha.3 исправлена проверка ОС установщика. Нативная проверка на Server 2016 ещё требуется; [матрица и сценарии проверки](docs/windows-compatibility.md).

Готовые ZIP и контрольные суммы доступны в [альфа-релизах GitHub](https://github.com/sanekman/1C-Backup/releases). При локальной сборке архив создаётся как `artifacts/1C-Backup-<версия>-windows-x64.zip`. Он содержит приложение и среды .NET / Windows Desktop для Windows x64; отдельно устанавливать .NET не нужно. Распакуйте **весь архив**, затем запустите `1C-Backup/OneCBackup.Desktop.exe`. Рядом с программой находится инструкция `START-HERE.txt`. Приложение запускается из распакованной папки; один EXE без остальных файлов работать не будет.

Также доступен `1C-Backup-<версия>-windows-x64-setup.exe`: установщик с запросом прав администратора, с ярлыком в меню «Пуск» и необязательным ярлыком рабочего стола. Папка по умолчанию — `C:\Program Files\1C-Backup`. Автозапуск не включается установщиком: его можно настроить в программе. Перед обновлением или удалением выберите «Выйти полностью» в меню трея или в настройках и дождитесь завершения программы. В старой версии остановите автоматическое копирование, дождитесь «Выключено» и закройте окно. Настройки и история в `%LOCALAPPDATA%\OneCBackup`, пароли Windows и резервные копии остаются после удаления. Удаляется только автозапуск, точно указывающий на агент или окно этой установки; запись другой переносной копии сохраняется.

С версии `0.2.0-alpha.1` номер включается в оба имени. Для автообновления прежних preview-клиентов в ветке дистрибутива сохраняется техническая копия установщика с прежним именем; скачивание из описания релиза использует версионные файлы. Версия текущего ZIP записывается в `artifacts/distribution-version.txt`; сборщик установщика использует её автоматически.

Сборка архива из исходников требует .NET SDK 10 и Python 3:

```bash
python tools/build_windows_distribution.py
```

При необходимости задайте путь к SDK через `--dotnet`. Скрипт публикует Release для `win-x64` в новый временный каталог, проверяет наличие встроенных сред, упаковывает файлы без отладочных PDB, проверяет целостность ZIP и создаёт `artifacts/1C-Backup-<версия>-windows-x64.zip.sha256`. Артефакты не включаются в Git. Сборку ZIP можно выполнить на Linux; запуск WPF-приложения требует Windows. Установщик собирается на Windows через Inno Setup 6 из того же проверенного ZIP командой `python tools/build_windows_installer.py`. Для сборки EXE на Linux доступен NSIS: установите `makensis` и выполните `python tools/build_windows_installer.py --kind nsis`. Он использует тот же проверенный ZIP, устанавливает программу в Program Files с повышением прав и оставляет профиль резервного копирования при удалении. Проверка содержимого NSIS EXE выполняется распаковкой через 7-Zip и сравнением всех файлов с ZIP; запуск установки / GUI на настоящей Windows остаётся отдельной проверкой. Windows CI проверяет установку, совпадение всех файлов с ZIP, запуск установленного GUI, отказ обновления / удаления при занятом профиле и сохранение профиля / чужого автозапуска. Архив и установщик пока не подписаны. Windows CI содержит проверки интерфейса; успешное выполнение зависит от доступности GitHub Actions; работу с реальными базами необходимо проверить отдельно.

## Просмотр и проверка сохранённых копий

### Проверить доступ до первого копирования

Выберите задание и нажмите «Проверить источник» при остановленном автоматическом копировании. Для ZIP файловой 1С проверяется непустой `1Cv8.1CD` и кратковременный эксклюзивный доступ (или совместное чтение, если разрешено копирование открытой базы); для `.dt` — файл и наличие платформы без её запуска. SQL Server проверяет Windows-подключение с прежними требованиями TLS, доступ к базе и право `BACKUP DATABASE`; запись службой в серверную папку и сопоставление путей требуют первой копии. PostgreSQL использует `psql` рядом с выбранным `pg_dump`, стандартный файл паролей и `SELECT 1`. Без `psql` эта проверка недоступна, но создание копии по-прежнему использует только `pg_dump` / `pg_restore`. Проверка SQL ограничена 30 секундами и отменяема. Успех показывает доступ сейчас, не подтверждает права чтения всех таблиц, создание дампа или возможность восстановления.

Выберите сохранённое задание и нажмите «Проверить хранилища». Автоматическое копирование должно быть остановлено. Программа проверит запись и чтение во временной папке, затем запись, чтение и удаление небольшого тестового файла в каждом локальном, сетевом или FTP / FTPS-хранилище. Результат каждого места доступен в раскрываемом блоке под кнопками. Ошибка одного назначения не мешает проверке остальных. Проверку можно отменить; удаление доставленного тестового файла выполняется отдельно от отмены. Если удалить его не удалось, результат показывает путь.

Проверка не запускает платформу 1С или SQL, не создаёт записи копий и не применяет правила хранения. Она проверяет доступ с текущими правами и настройками, а не свободное место для большой базы или возможность восстановления. После успешной проверки создайте первую настоящую копию. Проверка использует выбранную временную папку без возврата на стандартный диск при её недоступности; новые папки хранилища при необходимости создаются, посторонние файлы сохраняются.

### Файлы и папки: полная или инкрементная копия

В мастере выберите тип «Файлы и папки», затем один файл или папку. Папка копируется со всеми вложенными обычными файлами и пустыми каталогами. Для нескольких независимых исходных папок создайте отдельные задания. Доступны расписание, ZIP с паролем AES-256, временная папка на HDD и доставка одного архива в несколько локальных, сетевых или FTP / FTPS-хранилищ с отдельными лимитами.

«Полная» каждый раз создаёт самостоятельный архив всех файлов. «Инкрементная» сначала создаёт полную основу; следующие архивы содержат только новые и изменённые файлы и индекс удалений. Изменения определяются по SHA-256: все исходные файлы читаются, но неизменённые данные не записываются во временный архив. Параметр «Архивов в цепочке» включает полную основу; например, 7 означает полную копию и до 6 инкрементных, затем новую полную.

Лимит хранения защищает всю цепочку для последних выбранных точек восстановления: фактическое число архивов может превышать лимит. Программа сообщает об этом в результате. Старые цепочки удаляются только после регистрации новой копии; ошибка удаления инкремента сохраняет его основу. Добавление хранилища, смена источника / пароля, отсутствие цепочки в каталоге или повреждение локального индекса вызывает новую полную копию. «Проверить целостность» и проверка последних копий задания сверяют размер и SHA-256 всех архивов нужной файловой цепочки, а не только последнего инкремента. Каталог сам по себе не подтверждает их сохранность.

Для восстановления выберите файловую копию в разделе «Резервные копии» и нажмите «Восстановить файлы…». Программа получает полную основу и все предшествующие инкременты из того же хранилища, проверяет SHA-256 архивов и итоговых файлов и создаёт новый подкаталог в выбранной папке. Ход операции показывает номер архива в цепочке, полученные байты, проверку SHA-256, сборку файлов, итоговую проверку и прошедшее время. Полоса относится к текущему этапу; при сборке и итоговой проверке считаются файлы. Отмена очищает собственные временные папки, готовый результат публикуется после проверки всей цепочки. Исходные данные и существующие файлы не перезаписываются. Для защищённой цепочки нужен пароль. «Сохранить этот архив…» выгружает только выбранный инкремент и напоминает о зависимостях. Отдельный инкрементный ZIP содержит только изменения и не заменяет всю цепочку; сохраняйте каталог приложения вместе с архивами.

Это копирование обычных доступных файлов, а не образ диска: VSS, права NTFS, дополнительные потоки и системные атрибуты не сохраняются. Символические ссылки и точки соединения отклоняются, недоступные файлы не пропускаются молча. Остановите приложения, которые изменяют данные; для рабочих баз 1С и SQL используйте специальные типы заданий. Исходная папка не должна включать временную папку, профиль приложения или локальные хранилища. Предельный индекс: 100 000 файлов, 100 000 папок и 32 МБ; превышение завершается ошибкой.

### Временная папка на другом диске

На шаге «Хранилище» выберите «Временная папка — где формировать копию», например `D:\1C-Backup-Temp` на HDD. Здесь создаются ZIP файла `1Cv8.1CD`, выгрузка `.dt`, дамп PostgreSQL и промежуточные архивы перед отправкой во все хранилища. Временные файлы проверки FTP также используют эту папку. Настройка сохраняется для ручных и фоновых запусков; пустое поле оставляет стандартный каталог `%LOCALAPPDATA%\OneCBackup\work`.

Каждый запуск использует отдельный подкаталог. После успешной доставки он удаляется; выбранная папка и посторонние файлы сохраняются. При ошибке, отмене или частичной доставке рабочий подкаталог остаётся для восстановления; его путь доступен в истории. Недоступная папка приводит к ошибке до создания копии, без переключения на стандартный диск. Учётной записи агента нужны права записи и свободное место для выгрузки, ZIP и проверки FTP.

SQL Server создаёт исходный `.bak` в «Каталоге на SQL-сервере»; выберите HDD также в этом параметре. Выбранная временная папка агента используется для упаковки `.bak`, но не меняет место выполнения SQL-команды `BACKUP DATABASE`. Исходная база остаётся на прежнем диске. Малые файлы настроек и журнала приложения продолжают храниться в профиле Windows.

### Несколько хранилищ для одного задания

В шаге «Хранилище» укажите основную папку, раскройте «Копировать также в другие хранилища» и нажмите «Добавить хранилище». Можно выбрать локальный диск, сетевую папку UNC или FTP / FTPS; всего до 8 назначений. Затем сохраните задание. Архив и пароль общие: база и ZIP создаются один раз, тот же файл отправляется параллельно — до трёх хранилищ одновременно; остальные ожидают свободного места. Учётные данные FTP задаются отдельно для каждого сервера и сохраняются в Windows.

Для каждого хранилища можно задать своё количество последних успешных копий. На шаге «Расписание» задайте число для основного хранилища. В окне добавления / изменения дополнительного хранилища заполните «Хранить последних успешных копий», например 30 при 7 в основном. Пустое поле использует число основного хранилища и следует его изменениям. Минимум — 1. Итог мастера показывает количество для каждого назначения. Существующие задания сохраняют прежние значения.

Очистка в каждом хранилище начинается только после доставки, проверки и регистрации новой копии туда; уменьшение количества в настройках не удаляет файлы немедленно. Ошибка одной доставки не останавливает остальные и не запускает очистку недоступного места: итог «Частично» означает, что часть мест получила копию. Нажмите «Результат», чтобы увидеть сохранённые файлы и ошибки по каждому назначению. При частичной ошибке или отмене уже доставленные копии сохраняются, рабочие файлы остаются для диагностики; следующая попытка создаёт новую копию базы.

Изменение или удаление дополнительного хранилища из задания не удаляет прежние файлы и записи каталога. Для проверки или извлечения старой копии её хранилище должно оставаться в настройках задания; при необходимости добавьте прежние параметры обратно. Старые задания с одним хранилищем работают без изменения.

Выберите задание и нажмите «Последняя копия», чтобы сразу открыть его последнюю зарегистрированную копию. «Результат» открывает последний запуск в истории, включая ошибки и предупреждения; фильтры истории сбрасываются, чтобы запись была видна. Ошибка новой попытки не мешает открыть предыдущую копию. Во время копирования показан индикатор без процента готовности.

Раздел «Резервные копии» показывает записи журнала `copies.json`: задание, дату создания по времени компьютера, размер, хранилище, расположение и защиту архива. Полный путь и SHA256 доступны в подробностях выбранной записи. Список обновляется после операций и изменений заданий, при открытии раздела и кнопкой «Обновить». Копии удалённых или недоступных заданий остаются видимыми с идентификатором задания. Это журнал зарегистрированных копий: он не сканирует каталоги и не подтверждает, что файл сейчас существует.

Выберите копию и нажмите «Проверить целостность»: приложение читает файл целиком и сверяет размер и SHA256. Для FTP используется полное обратное скачивание с текущими учётными данными Windows. Проверка не меняет журнал, настройки или файлы; её можно отменить. Она доступна при остановленных планировщике и фоновом агенте и не пересекается с созданием копии. Если задание удалено или хранилище изменено, проверка через текущие настройки не выполняется. Проверка содержимого не заменяет пробное восстановление базы.

«Открыть папку» открывает каталог локальной или сетевой копии в Проводнике Windows. Для FTP эта кнопка недоступна. Ошибка чтения журнала показывается в разделе без перезаписи данных.

## Первый запуск и интерфейс

Нажмите «Создать первое задание» или «+ Новое задание». Мастер проведёт через четыре шага: база, хранилище, расписание и итоговая проверка. Ошибка не даёт перейти дальше; исправьте указанное поле. «Назад» сохраняет введённые данные, «Отмена» и Escape возвращают список без сохранения изменений. Кнопки мастера всегда доступны внизу окна.

После сохранения выберите задание и нажмите «Создать копию». Успех или ошибка появятся в истории; рядом с выбранным заданием показывается последний результат и время по расписанию. Чтобы расписание выполнялось после закрытия окна, нажмите «Включить автоматически» в верхней панели. Для автозапуска после перезапуска компьютера включите запуск при входе в Windows в настройках агента. Работа без входа пользователя пока не поддерживается.

Для изменения выберите задание и нажмите «Изменить» либо дважды щёлкните строку. Подробные параметры находятся в раскрываемых разделах. Время в таблицах истории и копий показывается по часовому поясу компьютера; исходные UTC-метки сохраняются в журналах. Основные решения и исследованные интерфейсы описаны в [документе об интерфейсе](docs/interface-design.md).

## Шифрование копий и пароль ZIP

В редакторе задания нажмите «Задать новый пароль архива», введите пароль дважды и сохраните задание. Флажок «Шифровать ZIP паролем (AES-256)» включается автоматически. Для `.dt`, `.bak` и `.dump` также должна быть включена архивация. Архив самого `1Cv8.1CD` шифруется напрямую, без второго ZIP. Защита работает при доставке на локальный диск, UNC и FTP / FTPS и при выполнении фоновым агентом.

Используется стандартный ZIP с WinZip AES-256; его можно открыть в 7-Zip и WinRAR. Встроенный распаковщик Windows может не поддерживать этот формат. Шифруется содержимое; имена файлов и размеры внутри ZIP остаются видимыми. Перед доставкой приложение полностью расшифровывает ZIP, проверяет исходные байты и код аутентификации; затем сохранённая копия проверяется по SHA256. При отмене или ошибке промежуточный архив удаляется.

Пароль хранится в Windows Credential Manager текущего пользователя в записи `OneCBackup/Archive/<идентификатор>`. В задании, каталоге копий, истории и API сохраняется только ссылка, без пароля. При каждом сохранении нового пароля создаётся новая запись: старые копии сохраняют ссылку на прежний пароль, поэтому смена настройки не мешает их извлечению. Выключение шифрования действует только на новые копии. Старые записи не удаляются автоматически, в том числе при удалении задания.

При извлечении зашифрованного `1Cv8.1CD` можно ввести пароль вручную или оставить поле пустым для чтения сохранённой записи Windows. Пароль вручную не сохраняется. Неверный пароль или повреждение архива не создают готовый файл базы. Сохраните пароли отдельно: перенос `jobs.json` / `copies.json` на другой компьютер или в другой профиль Windows не переносит хранилище паролей. Без пароля содержимое восстановить невозможно.

Шифрование относится к конечной копии. Исходная база, SQL-копия в каталоге сервера и временные выгрузки перед упаковкой остаются незашифрованными. Рабочая папка удаляется после успешного выполнения, а при ошибке может сохраняться для диагностики. Для защиты этих файлов используйте права доступа и шифрование диска.

## Извлечение файловой базы из ZIP

В разделе «Резервные копии» выберите ZIP файла базы, созданный способом «Архив файла базы без платформы», и нажмите «Извлечь 1Cv8.1CD». Выберите родительскую папку. Программа сверит размер и SHA256 архива с журналом и извлечёт единственный непустой файл `1Cv8.1CD` в новую папку `1C-Restored-<id>` внутри неё. Каталоги внутри ZIP, дополнительные файлы и пути вроде `../1Cv8.1CD` не принимаются. Исходный архив и существующие базы сохраняются; извлечённый файл не добавляется в журнал копий и не попадает под очистку по количеству копий.

Извлечение поддерживает локальные и сетевые архивы. Для этой операции нужны сохранённое задание и прежние настройки хранилища; остановите планировщик и фоновый агент. Кнопка «Отменить операцию» отменяет извлечение. Добавьте полученную папку как отдельную файловую базу в списке 1С и проверьте её работу. Извлечение файла не проверяет логическую целостность базы; восстановление `.dt`, SQL Server и PostgreSQL автоматически пока не выполняется.

## Ручное резервное копирование файловой 1С

1. В автономном режиме создайте задание типа `OneCFile` и укажите каталог с `1Cv8.1CD`.
2. Выберите способ «Выгрузка .dt через платформу 1С». Укажите полный путь к установленному `1cv8.exe`, например `C:\Program Files\1cv8\8.3.27.1859\bin\1cv8.exe`, и ограничение времени выгрузки (по умолчанию 120 минут).
3. Выберите локальный или сетевой каталог, количество копий и при необходимости ZIP. Сохраните задание, выберите его в таблице и нажмите «Создать копию».

Используется режим Конфигуратора `DESIGNER /F ... /DumpIB ...`; работающую базу программа напрямую не копирует и сеансы принудительно не завершает. Первая реализация поддерживает базы без пароля пользователя 1С. Выгрузка требует эксклюзивного доступа. Кнопка использует сохранённые настройки; флажок включения задания относится к автоматическому расписанию и не запрещает ручной запуск.

Успех требует нулевого кода платформы, непустой выгрузки и проверенной доставки. Это не подтверждает возможность восстановления базы: нужен пробный импорт на тестовой платформе. Ограничение времени и кнопка «Отменить» останавливают процесс платформы перед завершением операции. Пока операция выполняется, обычное закрытие окна блокируется.

В разделе «История запусков» доступны поиск по названию, пути или ошибке, фильтры результатов, полные подробности выбранной операции и открытие её рабочей папки. Кнопка «Экспорт JSON» сохраняет показанные фильтром записи в отдельный файл; экспорт в рабочий профиль приложения запрещён. Журнал содержит пути и диагностические сообщения — учитывайте это при передаче файла другим людям.

История в `runs.json` сохраняет время, итог, путь копии, ошибки и предупреждения очистки. Журнал зарегистрированных копий — `copies.json`; рабочие каталоги — `work/<runId>`, журнал платформы — `platform.log` внутри них. Ошибки `pg_dump` и `pg_restore` сохраняются соответственно в `pg_dump.log` и `pg_restore.log` в рабочей папке; каждый журнал ограничен 1 МБ, лишний вывод продолжает считываться без блокировки процесса. Журнал можно открыть, пока операция выполняется. При отмене утилита завершается до освобождения исполнителя. После успешной доставки рабочий каталог удаляется; при ошибке или отмене он сохраняется для диагностики и восстановления. Если доставка завершилась, но регистрация или последующая проверка завершилась ошибкой, итоговый файл уже может находиться в хранилище — проверьте его перед повторными действиями. Прерванные при аварийном завершении операции помечаются при следующем открытии программы; перед новым запуском проверьте, не остался ли процесс 1С от предыдущей операции.

Одновременно работает один экземпляр интерфейса для данного каталога пользователя; задания выполняются последовательно, отправка одной копии — до трёх хранилищ одновременно. FTP/FTPS подключён к ручному запуску и расписанию через диспетчер учётных данных Windows. Пароли базы не передаются и не сохраняются в заданиях.

### Архив файла базы без платформы

Выберите способ «Архив базы (ZIP)». Источником может быть каталог базы или полный путь к `1Cv8.1CD`. Путь к `1cv8.exe` и пароль пользователя базы для этого способа не нужны. Закройте все сеансы базы, сохраните задание и нажмите кнопку создания копии.

По умолчанию файл открывается с `FileShare.None`: на Windows это исключает совместный доступ к файлу во время чтения. При отказе в эксклюзивном доступе задание завершается ошибкой без очистки прежних копий. Дескриптор удерживается до завершения упаковки и проверки ZIP; исходный файл не переоткрывается между проверкой доступа и чтением. Сеансы автоматически не завершаются.

При включении «Разрешить копирование открытой базы» файл открывается на чтение с `FileShare.ReadWrite`. Предупреждение показывается под настройкой и в итоговой проверке задания; каждый запуск сохраняет его в истории. Если 1С меняет данные во время чтения, копия может оказаться повреждённой. Проверка ZIP не проверяет согласованность базы. Этот режим не использует VSS, не снимает чужие блокировки и не завершает пользователей; если другой процесс запрещает чтение, копирование завершится ошибкой. Для `.dt` эта настройка не действует. Старые и новые задания по умолчанию требуют закрытой базы.

Готовая копия имеет уникальное имя с расширением `.1CD.zip` и содержит один файл `1Cv8.1CD`. Упаковка выполняется потоково, распакованное содержимое проверяется по SHA-256 перед публикацией. Дополнительный ZIP для этого способа не создаётся, независимо от значения `ArchiveCopies`. Пустой или отсутствующий файл считается ошибкой. Правила доставки, истории, отмены и хранения N копий общие с выгрузкой `.dt`.

Архив содержит только файл базы, без внешних файлов, расширений и настроек окружения. Для восстановления нужно извлечь `1Cv8.1CD` в отдельный каталог и проверить открытие тестовой базы совместимой платформой 1С. Проверки содержимого и отказа при занятом файле выполняются на тестовых файлах; поведение блокировки с реальными сеансами 1С и на UNC нужно проверить на Windows до эксплуатации. Старые задания без поля `OneCMethod` продолжают использовать выгрузку `.dt`.

## Работа в фоне

«Запустить в окне» в дополнительных настройках включает планировщик самого окна. «Включить автоматически» запускает отдельный `OneCBackup.Agent.exe` из папки дистрибутива: он выполняет расписание после закрытия окна, от имени текущего пользователя Windows. GUI можно снова открыть для редактирования заданий, просмотра копий, истории и SQL-мониторинга. Задания и источники перечитываются из атомарно сохраняемых файлов.

В разделе «Настройки» можно явно включить автозапуск при входе текущего пользователя в Windows. Используется отдельная запись `OneCBackupAgent` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; отключение удаляет только эту запись. После переноса папки программы настройку нужно сохранить заново. Отмена автозапуска не останавливает уже работающий процесс.

«Остановить агент» записывает запрос для конкретного сеанса. Агент отменяет свою текущую операцию, дожидается её завершения и записи истории, затем освобождает общий замок `engine.lock`. Старый запрос не останавливает новый сеанс. Окно, второй агент и ручной мониторинг не могут параллельно владеть исполнением одного рабочего каталога. Не удаляйте `engine.lock`: блокировка снимается закрытием дескриптора или завершением процесса. Окно не помечает работу активного агента прерванной при открытии.

Агент опрашивает включённые SQL-источники независимо от резервного копирования. Интервал каждого источника — от 15 до 86400 секунд, по умолчанию 60; проверка наступления интервала выполняется каждые 10 секунд. Ошибка одного источника не мешает остальным и не останавливает резервное копирование. История опросов — `external-poll-status.json`, наблюдения — `external-backups.json`; повторные наблюдения не добавляются. В автономном режиме это локальная история без API-запросов. Отправка на сервер и управляемое исполнение будут подключены отдельно.

Фоновый агент пока поддерживает только автономный режим. Это **не служба Windows**: работа без входа пользователя, после выхода из сеанса и до входа после перезагрузки ещё не поддерживается. Учётные данные FTP и доступ к SQL / UNC принадлежат текущему пользователю. Перемещение файлов настроек в каталог службы и защищённый IPC остаются отдельным этапом.

Команды самостоятельного агента из распакованной папки:

```powershell
.\OneCBackup.Agent.exe --run
.\OneCBackup.Agent.exe --status
.\OneCBackup.Agent.exe --stop
.\OneCBackup.Agent.exe --run-job <GUID задания>
```

Для другого каталога данных задайте `--data-dir` с полным путём. После обновления программы остановите агент, замените **всю** папку дистрибутива и запустите агент снова. Остановка не завершает окно; закрытие окна не завершает агент.

## Агент: автономный и серверный режимы

Начальный план серверной части: [дорожная карта](docs/server-roadmap.md). Предусмотрены Windows-приложение / служба, Linux-контейнер и установка через systemd с общей веб-панелью; macOS рассматривается после основных вариантов. Документ описывает план, а не готовые серверные возможности.

Настройка копирования SQL Server и PostgreSQL описана в [sql-backups.md](docs/sql-backups.md). В SQL Server используется Windows-аутентификация, в PostgreSQL — стандартный файл паролей; пароли не сохраняются в заданиях.

В разделе «Режим агента и сервер управления» выбирается режим:

- **Автономный агент** — локальные задания, без сервера и токена. Режим по умолчанию.
- **Управление через сервер** — HTTPS-адрес, идентификатор локальной привязки учётных данных и интервал связи. Используется отдельный набор серверных заданий; локальные задания сохраняются для возврата к автономному режиму. Серверные задания в интерфейсе доступны только для просмотра.

Настройки режима и постоянный ID агента сохраняются в `agent.json` рядом с `jobs.json`; серверный кэш — в `server-jobs.json`. Токен в эти файлы не записывается. При ошибках сети агентский модуль продолжает расписание по последнему принятому кэшу. На первом серверном подключении без кэша заданий нет; локальные задания автоматически не подмешиваются. Смена сервера или ID не активирует чужой кэш.

`BackupAgent.RunAsync` объединяет независимые циклы планировщика и связи; хост передаёт настоящий исполнитель и обработчики результатов. `AgentApiClient` реализует исходящие HTTPS-запросы конфигурации и heartbeat. Проверены сценарии с подменённым HTTP-транспортом, включая остановленный и зависший API; реального сервера пока нет. Очередь отправки результатов после работы без сети будет отдельным этапом.

[Архитектура агента и контракт API v1](docs/agent-api.md) описывают конфигурацию, heartbeat, правила ревизий, режимы работы и следующие части сервера. Служба Windows использует задания владельца профиля и может работать под выбранным пользователем Windows; установка и удаление выполняются повышенным помощником через защищённый локальный канал. Общий машинный профиль и полноценный IPC для редактирования заданий остаются отдельным этапом. См. [режим службы](docs/windows-service.md).

На сервере запланированы веб-панель мониторинга агентов, история результатов и удалённое создание, изменение, отключение и удаление заданий. Сохранённые настройки и подтверждённая агентом ревизия отображаются отдельно: изменения для отключённого агента ожидают следующей связи. Подробности — в [требованиях к серверному управлению](docs/server-management.md).

## Расписание и количество копий

Для копий, создаваемых внешними заданиями SQL, доступно отдельное окно «Мониторинг копий SQL»: чтение истории SQL Server из `msdb` и импорт отчётов скрипта PostgreSQL. Наблюдения сохраняются локально без повторов; ядро содержит очередь и HTTPS-клиент отправки на сервер. Автоматический опрос выполняет локальный фоновый агент; отправка на сервер пока не подключена. Настройка и ограничения описаны в [руководстве по внешним SQL-копиям](docs/external-backup-monitoring.md).

Для каждого задания доступны «Только вручную», «Ежедневно» и «По выбранным дням недели». Указываются до 48 уникальных времён запуска через запятую (например `09:00, 13:00, 23:00`) по местному времени Windows; интерфейс показывает следующий запуск по расписанию. Все времена применяются к выбранным дням. При переходе на летнее время времена в пропущенном часе переносятся на первую доступную минуту и совпавшие запуски выполняются один раз; повторяющийся осенний час тоже выполняется один раз. Выключенное задание автоматически не запускается. Старые настройки сохраняют ежедневное расписание, время и количество копий.

В разделе «Настройки» раскройте «Дополнительно: расписание только при открытом окне» и нажмите «Запустить в окне». Каждые 30 секунд он читает сохранённые задания и запускает включённые ежедневные и недельные задания файловой 1С, SQL Server и PostgreSQL с доставкой на локальный диск, в сетевой каталог или на FTP/FTPS. Приложение должно оставаться открытым; после повторного открытия планировщик нужно включить вручную. Для работы после закрытия окна используйте фоновый агент. Работа без входа пользователя потребует службы Windows, которая ещё не реализована.

Ручные и автоматические операции используют общий диспетчер `LocalBackupDispatcher`, исполнитель и постоянную историю. Операции не перекрываются. «Отменить» отменяет текущую операцию, оставляя планировщик включённым. «Остановить» для планировщика окна отменяет его текущую автоматическую операцию и дожидается записи результата; самостоятельная ручная операция этой кнопкой не отменяется. Для закрытия окна сначала остановите планировщик и дождитесь завершения операций. Пока планировщик работает, смена режима агента и окно внешнего SQL-мониторинга недоступны.

Изменение, отключение и удаление заданий считываются при следующем опросе; уже назначенная к исполнению операция использует свой снимок настроек. Локальный диск, сетевой каталог и FTP/FTPS доступны для всех трёх типов базы. Повреждённый файл заданий останавливает планировщик с сообщением об ошибке, без перезаписи файла. Отсутствие учётных данных или отказ FTP завершает соответствующее задание ошибкой; остальные задания продолжают обрабатываться.

`BackupSchedule.NextRun` рассчитывает следующее событие, а `BackupScheduler.RunAsync` передаёт наступившие задания исполнителю. Ошибка задания сохраняется в истории и не запускает немедленный повтор. При задержке опроса выполняется один запуск вместо очереди всех пропущенных событий. После перезапуска отсчёт начинается со следующего события; автоматического восполнения пропущенных за время остановки запусков нет. Остановка и повторное включение планировщика в том же процессе сохраняют сведения об уже обработанных событиях, исключая повтор одного события.

### Копирование при запуске системы

В расписании задания выберите «Копировать при запуске системы». Время и дни недели для этого режима не задаются. Кнопка «Включить автозапуск агента» запускает агент при последующих входах текущего пользователя в Windows; задание сохраняется отдельно. Сейчас агент не является службой, поэтому до входа пользователя резервное копирование не выполняется. Если агент уже работает, новое включённое задание будет выполнено при ближайшем обновлении списка.

Планировщик делает одну попытку для каждого задания за загрузку системы, используя стабильный идентификатор загрузки ОС и `%LOCALAPPDATA%\OneCBackup\startup-schedule.json`. Перезапуск программы, отключение/включение задания, перевод часов и возобновление той же загрузки после сна не создают повторную копию. Попытка отмечается атомарно перед исполнением; после ошибки, отмены или аварийного завершения автоматического повтора в этой загрузке нет — повторите вручную. При следующей загрузке будет новая попытка. Это расписание работает и в агенте, и в планировщике открытого окна; они используют общий рабочий профиль и блокировку исполнения. Повреждённый файл состояния блокирует расписание, а не разрешает повторы. Не удаляйте его для «сброса»: это разрешит дополнительную попытку.

При переходе часов вперёд несуществующее местное время переносится на первую допустимую минуту этого дня. При повторении часа используется только первое вхождение времени. Если полностью пропущена календарная дата, используется следующий подходящий день.

Поле «Сколько успешных копий сохранять» задаёт число N (минимум 1, по умолчанию 7). `BackupCompletion` доставляет и проверяет новую копию, регистрирует её в постоянном JSON-журнале `BackupCatalog` и затем применяет `BackupRetention`. Локальное приложение использует журнал `%LOCALAPPDATA%\OneCBackup\copies.json` для регистрации копий, очистки и просмотра в интерфейсе. Для службы нужны один экземпляр журнала и один координатор завершения, без параллельной записи из других процессов.

Очистка касается только зарегистрированных копий того же задания и текущего хранилища. Новая копия и N−1 последних предыдущих копий сохраняются. Перед очисткой новая копия проверяется повторно; перед удалением старой сверяются её каталог, размер и SHA-256. Чужие файлы, изменённые копии и копии из предыдущего хранилища не удаляются. Если удаление не удалось, запись остаётся в журнале и ошибка возвращается отдельно; фактическое количество копий может временно превышать N. Повреждённый журнал блокирует очистку. Неудачная доставка новой копии не запускает удаление старых.

Лимит относится к конечному хранилищу. Рабочие исходные файлы в отдельном каталоге не входят в этот лимит. Файлы, зарегистрированные непосредственно в конечном каталоге, являются управляемыми копиями и могут удаляться по правилам хранения. Для FTP проверки перед очисткой также требуют обратного скачивания данных.

## Хранилища копий

В настройках задания можно выбрать:

- **Локальный диск** — каталог, например `D:\Backups`.
- **Сетевую папку** — UNC-путь, например `\\server\share\backups`. Для будущей службы Windows нужны права её учётной записи на эту папку; буква подключённого пользователем диска не используется.
- **FTP / FTPS** — сервер, порт и абсолютный каталог, например `/backups`. По умолчанию включён явный FTPS на порту 21 с проверкой сертификата. Обычный FTP включается отдельно; SFTP является другим протоколом и пока не поддерживается.

Ядро содержит общий контракт `IBackupStorage`, адаптеры `FileBackupStorage` и `FtpBackupStorage`, а также `BackupDelivery` для последовательности «готовая копия → ZIP по настройке → хранилище». Локальные и сетевые файлы проверяются по SHA-256 до переименования временного файла. FTP-копия загружается под временным именем, полностью скачивается для проверки SHA-256 и затем переименовывается; сервер должен разрешать загрузку, чтение, переименование и удаление временных файлов. Проверка FTP требует дополнительного трафика и локального места размером с отправленную копию.

Источник сохраняется при любом результате. Проверенные существующие файлы не перезаписываются. FTP не предоставляет универсального атомарного «переименовать, только если назначения нет»: используйте уникальные имена резервных копий и исключите стороннюю запись в их имена. При потере соединения временный файл на FTP может остаться; он имеет суффикс `.tmp` и не считается успешной копией.

В JSON сохраняется только идентификатор учётных данных FTP (`CredentialKey`). В редакторе FTP нажмите «Настроить логин и пароль»: данные сохраняются в диспетчере учётных данных текущего пользователя Windows под именем `OneCBackup/FTP/<CredentialKey>`. Пустой идентификатор заполняется автоматически. После сохранения учётных данных сохраните само задание. Прежний пароль не отображается; при обновлении вводятся логин и новый пароль, пустой пароль сохраняется как пустой.

Несколько заданий с одинаковым идентификатором используют одну запись. Для изменения логина и пароля через интерфейс остановите планировщик. Перед созданием копии проверяется наличие записи, но доступность FTP и правильность пароля проверяются только при доставке. Сохранение данных в Windows не означает успешное подключение к FTP.

Профиль Windows и каталог настроек являются отдельными хранилищами: перенос одного `jobs.json` не переносит пароль. При работе будущей службы от другой учётной записи потребуется настроить её собственный доступ к секретам. Удаление задания не удаляет общую запись учётных данных; её можно удалить в диспетчере учётных данных Windows. Запись, чтение и удаление учётных данных через Windows API и основные сценарии интерфейса проверяются в Windows CI. В облачной среде проверены маршрутизация с подменённым хранилищем и реальный обычный FTP на временном сервере. Успешный FTPS с доверенным сертификатом требует отдельной проверки.

Поддержка Яндекс Диска, Облака Mail.ru и S3 запланирована отдельными адаптерами; в интерфейсе они пока не предлагаются как работающие хранилища. Сейчас у задания одно конечное хранилище.

## Архивация копий

В редакторе задания доступен флажок «Архивировать копии в ZIP». Он сохраняется для каждого задания; по умолчанию выключен, в том числе для старых файлов настроек.

В ядре реализован `BackupArchiver.PrepareAsync(job, completedBackupPath)`: для файлового хранилища при включённой архивации готовый файл копии (`.dt`, `.bak`, `.dump` и т. п.) упаковывается в ZIP в каталоге копий. Например, `database.bak` становится `database.bak.zip`; имя файла внутри архива сохраняется. Можно также вызвать `CreateZipAsync` с явным путём архива и уведомлениями о числе обработанных байтов. Для доставки на FTP используется `BackupDelivery`: ZIP создаётся в локальном рабочем каталоге, затем отправляется и удаляется только локальный промежуточный архив. Исходная копия остаётся.

Упаковка выполняется потоково, затем содержимое полностью читается из ZIP и сравнивается с исходными данными по SHA-256. Только после проверки временный файл получает окончательное имя. Исходная копия сохраняется; существующие архивы не перезаписываются. При ошибке или отмене временный архив удаляется. Архивация применяется к завершённой, неизменяемой копии, а не к работающей базе, и не заменяет проверку восстановления базы данных. ZIP по желанию защищается паролем с AES-256; уже сжатые копии могут почти не уменьшиться.

Архивация подключена к ручной выгрузке файловой 1С; способ архивации самого `1Cv8.1CD` всегда создаёт ZIP и не упаковывает его повторно. Модуль и последовательность выполнения проверены на тестовых файлах и подменённом процессе платформы; реальную выгрузку и восстановление предстоит проверить на Windows.

## Разработка

Требуется .NET SDK 10.0.401 (версия закреплена в `global.json`). Для запуска интерфейса требуется Windows с .NET Desktop Runtime 10.

Из корня репозитория:

```sh
dotnet restore OneCBackup.slnx
dotnet build OneCBackup.slnx --no-restore
dotnet test tests/OneCBackup.Core.Tests --no-restore
```

Запуск на Windows:

```sh
dotnet run --project src/OneCBackup.Desktop
```

На Linux можно собрать Windows-приложение, выполнить тесты ядра и проверить консольный агент на тестовом файле 1CD; запуск WPF и Windows Credential Manager недоступен.

`python tests/agent_smoke.py` запускает настоящий консольный процесс, проверяет расписание и содержимое ZIP, отказ второго исполнителя и корректную остановку. На запуск оставляется запас не менее 10 секунд перед временем задания; ожидание копии ограничено 90 секундами. Windows-интеграционные тесты диспетчера учётных данных явно пропускаются на Linux и выполняются в Windows CI.

FTP-интеграционные тесты в обычном запуске пропускаются явно. Для проверки против временного локального сервера (Python 3.9+):

```sh
python -m pip install -r tests/ftp/requirements.txt
dotnet build OneCBackup.slnx
python tests/ftp/run_integration.py
```

Скрипт запускает сервер только на `127.0.0.1` с тестовыми учётными данными, выполняет FTP-тесты, возвращает код их завершения и удаляет временные файлы сервера. Проверяются передача файла и ZIP, сохранение существующей копии, отказ при неверном пароле, обнаружение повреждения, очистка зарегистрированных старых копий, отказ от удаления изменённой копии и отсутствие перехода на обычный FTP, когда требуется FTPS. Успешная передача по FTPS и доступ к реальной Windows-сетевой папке требуют отдельной проверки в целевой среде.

## Структура

- `src/OneCBackup.Core` — режимы агента, клиент API, кэш, диспетчер расписания, ZIP, хранилища, журнал копий и очистка.
- `src/OneCBackup.Desktop` — приложение Windows с разделами заданий, истории и настроек агента.
- `src/OneCBackup.Agent` — отдельный автономный исполнитель без WPF, расписание и автоматический мониторинг SQL.
- `tests/OneCBackup.Core.Tests` — тесты настроек, архивации, хранилищ и обработки ошибок.
- `tests/ftp` — временный FTP-сервер и запуск интеграционных проверок.
- [План реализации](docs/product-plan.md) — требования, архитектура, способы копирования и интеграционные проверки.
- [Контракт агентского API](docs/agent-api.md) — самостоятельная работа и управление через сервер.
- [Мониторинг и управление](docs/server-management.md) — панель сервера, удалённые настройки и подтверждение их принятия агентами.

Настоящие SQL-копии и пробное восстановление проверяются отдельным обязательным заданием Windows CI; условия и ручной запуск описаны в [native-sql-tests.md](docs/native-sql-tests.md). Следующий этап: проверка удалённых СУБД в целевой среде и платформы 1С, проверка службы на Windows и расширение локального IPC, а также сервер управления и регистрация агентов.

В списке заданий столбец «Последний запуск» показывает успех, ошибку, частичную доставку, отмену, прерывание или выполнение. Предупреждения отмечаются отдельно от успеха. Подсказка содержит местное время начала / завершения и причину; кнопка «Результат» открывает полную историю выбранного задания. Результат привязан к идентификатору базы, не к названию, и не зависит от фильтра истории. При ошибке чтения вместо прежнего результата показано «Нет данных». Число хранимых копий задаётся в мастере отдельно для каждого хранилища.

Кнопка «Проверить последние копии» в разделе «Задания» проверяет последнюю зарегистрированную копию выбранного задания в каждом текущем хранилище по размеру и SHA-256. Остановите автоматическое копирование, выберите задание и нажмите кнопку. Подробности показывают пути, время, ошибки и хранилища без копии; доступна отмена. Проверка не обращается к исходной базе, не изменяет каталог и не удаляет файлы. FTP требует полного чтения файла и временного места; пробное восстановление базы проверяется отдельно.

В разделе «Резервные копии» выберите файл и нажмите «Сохранить копию…», чтобы скачать с FTP / FTPS или скопировать с локального / сетевого диска в выбранную папку. Остановите автоматическое копирование. Файл проверяется по размеру и SHA-256 до появления окончательного имени. Существующие файлы не перезаписываются; отмена удаляет только временный файл операции. Архив сохраняет исходное шифрование, без ввода пароля. Каталог, история и исходная копия не меняются; сохранённый вручную файл не включается в автоматические правила хранения.

### Сохранённые результаты проверки копий

В списке копий сохраняется последняя ручная проверка размера / SHA-256 и проверка последних копий задания: результат и дата видны после перезапуска. Ошибка или отмена заменяет прежний успех. Состояние хранится отдельно в `verification-state.json`; каталог, история запусков и сами копии не меняются. Отсутствующее хранилище и проверка, не начатая из-за отмены, не создают запись. Повреждённый файл состояния показывает «Нет данных» и не перезаписывается автоматически. Это результат на указанное время, а не подтверждение наличия файла сейчас и не пробное восстановление. Сохранение / скачивание и извлечение сами по себе этот столбец не обновляют.

Таблица копий помещается в окне 900×580: тип хранилища объединён с размером, полный путь выбранного файла доступен под таблицей и в подробностях, длинные названия раскрываются подсказками.

### Значок в трее и полный выход

Крестик окна скрывает приложение в трей рядом с часами Windows. Двойной щелчок по значку открывает окно; повторный запуск ярлыка открывает существующее окно. Правый щелчок даёт команды открытия, остановки автоматического копирования и «Выйти полностью». Полный выход отменяет выполняемые операции и ждёт записи истории и освобождения профиля, затем закрывает окно и агент. Если профиль всё ещё занят, программа сообщает, что остановка не подтверждена, и остаётся открытой. При открытом диалоге настроек сначала закройте его.

Иконка встроена в окно, EXE, ярлыки установки и меню трея. Автозапуск из настроек запускает окно в трее и автономный агент. При первом запуске старая запись автозапуска, точно указывающая на агент этой установки, обновляется; запись другой переносной копии сохраняется. Windows может скрывать значок за стрелкой рядом с часами.

## Обновление Windows-программы

В «Настройки → Обновления» программа проверяет новые версии при запуске и каждые 6 часов. Кнопка «Обновить и перезапустить» скачивает установщик, проверяет размер и SHA-256, затем после подтверждения останавливает копирование, дожидается освобождения рабочего профиля и запускает установку. После успешной установки открывается новая версия; если работал агент или планировщик окна, он запускается снова. Запуск при загрузке системы при этом не повторяет уже выполненную попытку. Незавершённая копия при подтверждённой остановке отменяется по обычным правилам программы.

Для автоматического обновления включите «Обновлять при полном выходе из программы». Новая версия скачивается заранее и устанавливается при «Выйти полностью» после остановки агента. Обычное закрытие окна в трей не запускает установку. После такого полного выхода программа остаётся закрытой. По умолчанию включена только проверка версий; автоматическая установка требует включения флажка. При полном выходе незавершённое скачивание отменяется; непроверенный файл не запускается.

Репозиторий `sanekman/1C-Backup` закрытый. В блоке доступа нажмите «Создать токен на GitHub», создайте fine-grained токен с доступом к этому репозиторию и разрешением **Contents: Read**, вставьте и сохраните его. Вход в GitHub через браузер не передаёт доступ приложению. Токен хранится как `OneCBackup/Updates/GitHub` в диспетчере учётных данных текущего пользователя Windows, не попадает в JSON-настройки, ссылки или логи; его можно удалить из интерфейса. Для открытого репозитория проверка работает без токена. Канал предварительных версий переключается отдельным флажком.

Обновление через установщик доступно только при совпадении папки программы с её регистрацией в установленных приложениях текущего пользователя. Переносной ZIP обновляется вручную; доступна кнопка страницы релиза. Задания и копии находятся вне папки установки. Настройки обновлений — `%LOCALAPPDATA%\OneCBackup\updates.json`, проверенные установщики и результат последней установки — подпапка `updates`. Компонент установки использует Windows PowerShell без профиля и ждёт выхода исходного процесса; процессы принудительно не завершаются. Повторно проверяются хеш, зарегистрированная папка и версия после установки. Ошибка показывается при следующем запуске и записывается в `updates/update-result.json`; основные этапы проверки, скачивания и передачи установщику попадают в диагностические логи без токена.

Для следующих выпусков сборщик установщика создаёт `artifacts/update-manifest.json`. Скрипт `python tools/publish_windows_update.py --notes docs/release-notes-preview.md` проверяет артефакты и публикует их в новой ветке `distribution/windows-x64-<версия>` с отдельным временным Git-индексом. Затем создаётся релиз с файлом `artifacts/release-notes-with-updates.md`: скрытый указатель в описании связывает релиз с проверенным дистрибутивом. Существующая ветка не перезаписывается. Этот шаг также включён в CI для тегов; права публикации — `contents: write`.

Проверка установки и перезапуска на настоящей Windows остаётся обязательной перед эксплуатацией автообновления. В облачной Linux-среде проверяются клиент GitHub, выбор версий, проверка и отмена загрузки, сборка и содержимое пакетов.

Сценарий передачи установщику можно проверить без установки: `python tests/distribution/run_update_handoff.py` на Windows/PowerShell или `--docker` на Linux с заранее загруженным образом Microsoft PowerShell 7.4, указанным в скрипте. В этих проверках реестр и запуск процессов заменены тестовыми; они не подтверждают настоящую установку Windows.

Служба для выполнения заданий до входа в Windows: [настройка и ограничения](docs/windows-service.md).

Цифровая подпись издателя и ограничения SmartScreen: [настройка подписи Windows](docs/windows-signing.md). Текущий preview.42 не подписан; для подписанного выпуска нужен сертификат Code Signing или подключённая служба подписи.

Установщик по умолчанию использует `C:\Program Files\1C-Backup` и запрашивает права администратора. Задания и история остаются в `%LOCALAPPDATA%\OneCBackup` текущего пользователя. После установки откройте программу обычным запуском ярлыка.

В настройках службы доступен выбор локального пользователя и ручной ввод доменного имени. Укажите пароль выбранного пользователя; права на базы и хранилища должны быть у этой учётной записи.
