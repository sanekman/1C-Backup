# 1C-Backup

Агент резервного копирования для Windows с графическим интерфейсом: файловые базы 1С, Microsoft SQL Server и PostgreSQL. Может работать автономно или под управлением сервера через API. Ориентир по возможностям — Effector Saver.

## Текущее состояние

Начальная версия приложения на C#/.NET 10 и WPF: список заданий с редактором справа, отдельные разделы истории запусков и настроек агента, окно мониторинга внешних SQL-копий. Панель планировщика и статус операции доступны во всех разделах. Поддерживаются создание, изменение, отключение, удаление и локальное сохранение заданий. Реализована проверка обязательных полей, типа базы, часового пояса и количества сохраняемых копий. Файл записывается через временный файл; ошибка чтения блокирует перезапись повреждённых настроек.

Доступны два способа копирования файловой базы 1С: выгрузка `.dt` через установленную платформу и ZIP файла `1Cv8.1CD` без платформы. Для SQL Server подключены `BACKUP DATABASE` и проверка, для PostgreSQL — `pg_dump` и проверка каталога дампа. Ручной запуск работает в окне; расписание может выполнять окно или отдельный фоновый агент текущего пользователя. Подключены доставка на локальный диск или в сетевой каталог и очистка зарегистрированных копий. **Фоновая служба пока не реализована.** Исполнители проверены с подменёнными соединениями и процессами; работа с настоящими СУБД, платформой 1С и запуск интерфейса ещё требуют проверки на Windows.

Реализована основа агентской архитектуры: режимы, отдельный кэш серверных заданий, клиент HTTPS API для конфигурации и heartbeat и независимые циклы связи/расписания с подключаемым исполнителем. Сам сервер, локальный IPC, защищённое хранилище токена и готовая служба Windows ещё не реализованы. Интерфейс запускает локальные задания и управляет отдельным автономным фоновым агентом; сетевой обмен с сервером не включён.

Настройки интерфейса: `%LOCALAPPDATA%\OneCBackup\jobs.json`. Пароли в этом файле не хранятся. Для службы будет отдельное общее хранилище с разграничением доступа.

## Дистрибутив Windows

Готовый переносимый архив: `artifacts/1C-Backup-windows-x64.zip`. Он содержит приложение и среды .NET / Windows Desktop для Windows x64; отдельно устанавливать .NET не нужно. Распакуйте **весь архив**, затем запустите `1C-Backup/OneCBackup.Desktop.exe`. Рядом с программой находится инструкция `START-HERE.txt`. Приложение запускается из распакованной папки; один EXE без остальных файлов работать не будет.

Сборка архива из исходников требует .NET SDK 10 и Python 3:

```bash
python tools/build_windows_distribution.py
```

При необходимости задайте путь к SDK через `--dotnet`. Скрипт публикует Release для `win-x64` в новый временный каталог, проверяет наличие встроенных сред, упаковывает файлы без отладочных PDB, проверяет целостность ZIP и создаёт `artifacts/1C-Backup-windows-x64.zip.sha256`. Артефакты не включаются в Git. Сборку можно выполнить на Linux; запуск WPF-приложения требует Windows. Архив не подписан; запуск интерфейса и работу с реальными базами необходимо проверить на Windows.

## Просмотр и проверка сохранённых копий

Раздел «Резервные копии» показывает записи журнала `copies.json`: задание, дату создания в UTC, размер, хранилище, расположение и SHA256 при сохранении. Список обновляется после операций и изменений заданий, при открытии раздела и кнопкой «Обновить». Копии удалённых или недоступных заданий остаются видимыми с идентификатором задания. Это журнал зарегистрированных копий: он не сканирует каталоги и не подтверждает, что файл сейчас существует.

Выберите копию и нажмите «Проверить целостность»: приложение читает файл целиком и сверяет размер и SHA256. Для FTP используется полное обратное скачивание с текущими учётными данными Windows. Проверка не меняет журнал, настройки или файлы; её можно отменить. Она доступна при остановленных планировщике и фоновом агенте и не пересекается с созданием копии. Если задание удалено или хранилище изменено, проверка через текущие настройки не выполняется. Проверка содержимого не заменяет пробное восстановление базы.

«Открыть папку» открывает каталог локальной или сетевой копии в Проводнике Windows. Для FTP эта кнопка недоступна. Ошибка чтения журнала показывается в разделе без перезаписи данных.

## Ручное резервное копирование файловой 1С

1. В автономном режиме создайте задание типа `OneCFile` и укажите каталог с `1Cv8.1CD`.
2. Выберите способ «Выгрузка .dt через платформу 1С». Укажите полный путь к установленному `1cv8.exe`, например `C:\Program Files\1cv8\8.3.27.1859\bin\1cv8.exe`, и ограничение времени выгрузки (по умолчанию 120 минут).
3. Выберите локальный или сетевой каталог, количество копий и при необходимости ZIP. Сохраните задание, выберите его в таблице и нажмите «Создать копию».

Используется режим Конфигуратора `DESIGNER /F ... /DumpIB ...`; работающую базу программа напрямую не копирует и сеансы принудительно не завершает. Первая реализация поддерживает базы без пароля пользователя 1С. Выгрузка требует эксклюзивного доступа. Кнопка использует сохранённые настройки; флажок включения задания относится к автоматическому расписанию и не запрещает ручной запуск.

Успех требует нулевого кода платформы, непустой выгрузки и проверенной доставки. Это не подтверждает возможность восстановления базы: нужен пробный импорт на тестовой платформе. Ограничение времени и кнопка «Отменить» останавливают процесс платформы перед завершением операции. Пока операция выполняется, обычное закрытие окна блокируется.

История в `runs.json` сохраняет время, итог, путь копии, ошибки и предупреждения очистки. Журнал зарегистрированных копий — `copies.json`; рабочие каталоги — `work/<runId>`, журнал платформы — `platform.log` внутри них. После успешной доставки рабочий каталог удаляется; при ошибке или отмене он сохраняется для диагностики и восстановления. Если доставка завершилась, но регистрация или последующая проверка завершилась ошибкой, итоговый файл уже может находиться в хранилище — проверьте его перед повторными действиями. Прерванные при аварийном завершении операции помечаются при следующем открытии программы; перед новым запуском проверьте, не остался ли процесс 1С от предыдущей операции.

Одновременно работает один экземпляр интерфейса для данного каталога пользователя; операции выполняются последовательно. FTP/FTPS подключён к ручному запуску и расписанию через диспетчер учётных данных Windows. Пароли базы не передаются и не сохраняются в заданиях.

### Архив файла базы без платформы

Выберите способ «Архив файла базы без платформы». Источником может быть каталог базы или полный путь к `1Cv8.1CD`. Путь к `1cv8.exe` и пароль пользователя базы для этого способа не нужны. Закройте все сеансы базы, сохраните задание и нажмите кнопку создания копии.

Файл открывается с `FileShare.None`: на Windows это исключает совместный доступ к файлу во время чтения. При отказе в эксклюзивном доступе задание завершается ошибкой без очистки прежних копий. Дескриптор удерживается до завершения упаковки и проверки ZIP; исходный файл не переоткрывается между проверкой доступа и чтением. Сеансы автоматически не завершаются.

Готовая копия имеет уникальное имя с расширением `.1CD.zip` и содержит один файл `1Cv8.1CD`. Упаковка выполняется потоково, распакованное содержимое проверяется по SHA-256 перед публикацией. Дополнительный ZIP для этого способа не создаётся, независимо от значения `ArchiveCopies`. Пустой или отсутствующий файл считается ошибкой. Правила доставки, истории, отмены и хранения N копий общие с выгрузкой `.dt`.

Архив содержит только файл базы, без внешних файлов, расширений и настроек окружения. Для восстановления нужно извлечь `1Cv8.1CD` в отдельный каталог и проверить открытие тестовой базы совместимой платформой 1С. Проверки содержимого и отказа при занятом файле выполняются на тестовых файлах; поведение блокировки с реальными сеансами 1С и на UNC нужно проверить на Windows до эксплуатации. Старые задания без поля `OneCMethod` продолжают использовать выгрузку `.dt`.

## Работа в фоне

«Запустить» включает планировщик самого окна. «Включить фон» запускает отдельный `OneCBackup.Agent.exe` из папки дистрибутива: он выполняет расписание после закрытия окна, от имени текущего пользователя Windows. GUI можно снова открыть для редактирования заданий, просмотра копий, истории и SQL-мониторинга. Задания и источники перечитываются из атомарно сохраняемых файлов.

В разделе «Настройки агента» можно явно включить автозапуск при входе текущего пользователя в Windows. Используется отдельная запись `OneCBackupAgent` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; отключение удаляет только эту запись. После переноса папки программы настройку нужно сохранить заново. Отмена автозапуска не останавливает уже работающий процесс.

«Остановить агент» записывает запрос для конкретного сеанса. Агент отменяет свою текущую операцию, дожидается её завершения и записи истории, затем освобождает общий замок `engine.lock`. Старый запрос не останавливает новый сеанс. Окно, второй агент и ручной мониторинг не могут параллельно владеть исполнением одного рабочего каталога. Не удаляйте `engine.lock`: блокировка снимается закрытием дескриптора или завершением процесса. Окно не помечает работу активного агента прерванной при открытии.

Агент опрашивает включённые SQL-источники независимо от резервного копирования. Интервал каждого источника — от 15 до 86400 секунд, по умолчанию 60; проверка наступления интервала выполняется каждые 10 секунд. Ошибка одного источника не мешает остальным и не останавливает резервное копирование. История опросов — `external-poll-status.json`, наблюдения — `external-backups.json`; повторные наблюдения не добавляются. В автономном режиме это локальная история без API-запросов. Отправка на сервер и управляемое исполнение будут подключены отдельно.

Фоновый агент пока поддерживает только автономный режим. Это **не служба Windows**: работа без входа пользователя, после выхода из сеанса и до входа после перезагрузки ещё не поддерживается. Учётные данные FTP и доступ к SQL / UNC принадлежат текущему пользователю. Перемещение файлов настроек в каталог службы и защищённый IPC остаются отдельным этапом.

Команды самостоятельного агента из распакованной папки:

```powershell
.\OneCBackup.Agent.exe --run
.\OneCBackup.Agent.exe --status
.\OneCBackup.Agent.exe --stop
.\OneCBackup.Agent.exe --run-job <GUID задания>
```

Для другого каталога данных задайте `--data-dir` с полным путём. После обновления программы остановите агент, замените **всю** папку дистрибутива и запустите агент снова. Остановка не завершает окно; закрытие окна не завершает агент.

## Агент: автономный и серверный режимы

Настройка копирования SQL Server и PostgreSQL описана в [sql-backups.md](docs/sql-backups.md). В SQL Server используется Windows-аутентификация, в PostgreSQL — стандартный файл паролей; пароли не сохраняются в заданиях.

В разделе «Режим агента и сервер управления» выбирается режим:

- **Автономный агент** — локальные задания, без сервера и токена. Режим по умолчанию.
- **Управление через сервер** — HTTPS-адрес, идентификатор локальной привязки учётных данных и интервал связи. Используется отдельный набор серверных заданий; локальные задания сохраняются для возврата к автономному режиму. Серверные задания в интерфейсе доступны только для просмотра.

Настройки режима и постоянный ID агента сохраняются в `agent.json` рядом с `jobs.json`; серверный кэш — в `server-jobs.json`. Токен в эти файлы не записывается. При ошибках сети агентский модуль продолжает расписание по последнему принятому кэшу. На первом серверном подключении без кэша заданий нет; локальные задания автоматически не подмешиваются. Смена сервера или ID не активирует чужой кэш.

`BackupAgent.RunAsync` объединяет независимые циклы планировщика и связи; хост передаёт настоящий исполнитель и обработчики результатов. `AgentApiClient` реализует исходящие HTTPS-запросы конфигурации и heartbeat. Проверены сценарии с подменённым HTTP-транспортом, включая остановленный и зависший API; реального сервера пока нет. Очередь отправки результатов после работы без сети будет отдельным этапом.

[Архитектура агента и контракт API v1](docs/agent-api.md) описывают конфигурацию, heartbeat, правила ревизий, режимы работы и следующие части сервера. При внедрении службы WPF-интерфейс будет обращаться к единственному агенту через защищённый локальный канал; общие настройки будут перенесены в `%PROGRAMDATA%\OneCBackup` с миграцией и разграничением доступа.

На сервере запланированы веб-панель мониторинга агентов, история результатов и удалённое создание, изменение, отключение и удаление заданий. Сохранённые настройки и подтверждённая агентом ревизия отображаются отдельно: изменения для отключённого агента ожидают следующей связи. Подробности — в [требованиях к серверному управлению](docs/server-management.md).

## Расписание и количество копий

Для копий, создаваемых внешними заданиями SQL, доступно отдельное окно «Мониторинг копий SQL»: чтение истории SQL Server из `msdb` и импорт отчётов скрипта PostgreSQL. Наблюдения сохраняются локально без повторов; ядро содержит очередь и HTTPS-клиент отправки на сервер. Автоматический опрос выполняет локальный фоновый агент; отправка на сервер пока не подключена. Настройка и ограничения описаны в [руководстве по внешним SQL-копиям](docs/external-backup-monitoring.md).

Для каждого задания доступны «Только вручную», «Ежедневно» и «По выбранным дням недели». Указывается время запуска и часовой пояс; интерфейс показывает следующий запуск по расписанию. Выключенное задание автоматически не запускается. Старые настройки сохраняют ежедневное расписание, время и количество копий.

В автономном режиме нажмите «Запустить» на панели планировщика. Каждые 30 секунд он читает сохранённые задания и запускает включённые ежедневные и недельные задания файловой 1С, SQL Server и PostgreSQL с доставкой на локальный диск, в сетевой каталог или на FTP/FTPS. Приложение должно оставаться открытым; после повторного открытия планировщик нужно включить вручную. Работа без входа пользователя и при закрытом приложении появится со службой Windows.

Ручные и автоматические операции используют общий диспетчер `LocalBackupDispatcher`, исполнитель и постоянную историю. Операции не перекрываются. «Отменить» отменяет текущую операцию, оставляя планировщик включённым. «Остановить» на панели планировщика отменяет его текущую автоматическую операцию и дожидается записи результата; самостоятельная ручная операция этой кнопкой не отменяется. Для закрытия окна сначала остановите планировщик и дождитесь завершения операций. Пока планировщик работает, смена режима агента и окно внешнего SQL-мониторинга недоступны.

Изменение, отключение и удаление заданий считываются при следующем опросе; уже назначенная к исполнению операция использует свой снимок настроек. Локальный диск, сетевой каталог и FTP/FTPS доступны для всех трёх типов базы. Повреждённый файл заданий останавливает планировщик с сообщением об ошибке, без перезаписи файла. Отсутствие учётных данных или отказ FTP завершает соответствующее задание ошибкой; остальные задания продолжают обрабатываться.

`BackupSchedule.NextRun` рассчитывает следующее событие, а `BackupScheduler.RunAsync` передаёт наступившие задания исполнителю. Ошибка задания сохраняется в истории и не запускает немедленный повтор. При задержке опроса выполняется один запуск вместо очереди всех пропущенных событий. После перезапуска отсчёт начинается со следующего события; автоматического восполнения пропущенных за время остановки запусков нет. Остановка и повторное включение планировщика в том же процессе сохраняют сведения об уже обработанных событиях, исключая повтор одного события.

При переходе часов вперёд несуществующее местное время переносится на первую допустимую минуту этого дня. При повторении часа используется только первое вхождение времени. Если полностью пропущена календарная дата, используется следующий подходящий день.

Поле «Сколько успешных копий сохранять» задаёт число N (минимум 1, по умолчанию 7). `BackupCompletion` доставляет и проверяет новую копию, регистрирует её в постоянном JSON-журнале `BackupCatalog` и затем применяет `BackupRetention`. Локальное приложение использует журнал `%LOCALAPPDATA%\OneCBackup\copies.json` для регистрации копий, очистки и просмотра в интерфейсе. Для службы нужны один экземпляр журнала и один координатор завершения, без параллельной записи из других процессов.

Очистка касается только зарегистрированных копий того же задания и текущего хранилища. Новая копия и N−1 последних предыдущих копий сохраняются. Перед очисткой новая копия проверяется повторно; перед удалением старой сверяются её каталог, размер и SHA-256. Чужие файлы, изменённые копии и копии из предыдущего хранилища не удаляются. Если удаление не удалось, запись остаётся в журнале и ошибка возвращается отдельно; фактическое количество копий может временно превышать N. Повреждённый журнал блокирует очистку. Неудачная доставка новой копии не запускает удаление старых.

Лимит относится к конечному хранилищу. Рабочие исходные файлы в отдельном каталоге не входят в этот лимит. Файлы, зарегистрированные непосредственно в конечном каталоге, являются управляемыми копиями и могут удаляться по правилам хранения. Для FTP проверки перед очисткой также требуют обратного скачивания данных.

## Хранилища копий

В настройках задания можно выбрать:

- **Локальный диск** — каталог, например `D:\Backups`.
- **Сетевую папку** — UNC-путь, например `\\server\share\backups`. Для будущей службы Windows нужны права её учётной записи на эту папку; буква подключённого пользователем диска не используется.
- **FTP / FTPS** — сервер, порт и абсолютный каталог, например `/backups`. По умолчанию включён явный FTPS на порту 21 с проверкой сертификата. Обычный FTP включается отдельно; SFTP является другим протоколом и пока не поддерживается.

Ядро содержит общий контракт `IBackupStorage`, адаптеры `FileBackupStorage` и `FtpBackupStorage`, а также `BackupDelivery` для последовательности «готовая копия → ZIP по настройке → хранилище». Локальные и сетевые файлы проверяются по SHA-256 до переименования временного файла. FTP-копия загружается под временным именем, полностью скачивается для проверки SHA-256 и затем переименовывается; сервер должен разрешать загрузку, чтение, переименование и удаление временных файлов. Проверка FTP требует дополнительного трафика и локального места размером с отправленную копию.

Источник сохраняется при любом результате. Проверенные существующие файлы не перезаписываются. FTP не предоставляет универсального атомарного «переименовать, только если назначения нет»: используйте уникальные имена резервных копий и исключите стороннюю запись в их имена. При потере соединения временный файл на FTP может остаться; он имеет суффикс `.tmp` и не считается успешной копией.

В JSON сохраняется только идентификатор учётных данных FTP (`CredentialKey`). В редакторе FTP нажмите «Настроить логин и пароль»: данные сохраняются в диспетчере учётных данных текущего пользователя Windows под именем `OneCBackup/FTP/<CredentialKey>`. Пустой идентификатор заполняется автоматически. После сохранения учётных данных сохраните само задание. Прежний пароль не отображается; при обновлении вводятся логин и новый пароль, пустой пароль сохраняется как пустой.

Несколько заданий с одинаковым идентификатором используют одну запись. Для изменения логина и пароля через интерфейс остановите планировщик. Перед созданием копии проверяется наличие записи, но доступность FTP и правильность пароля проверяются только при доставке. Сохранение данных в Windows не означает успешное подключение к FTP.

Профиль Windows и каталог настроек являются отдельными хранилищами: перенос одного `jobs.json` не переносит пароль. При работе будущей службы от другой учётной записи потребуется настроить её собственный доступ к секретам. Удаление задания не удаляет общую запись учётных данных; её можно удалить в диспетчере учётных данных Windows. Запись и чтение через Windows API, успешный FTPS с доверенным сертификатом и весь интерфейс необходимо проверить на Windows; в облачной среде проверены маршрутизация с подменённым хранилищем и реальный обычный FTP на временном сервере.

Поддержка Яндекс Диска, Облака Mail.ru и S3 запланирована отдельными адаптерами; в интерфейсе они пока не предлагаются как работающие хранилища. Сейчас у задания одно конечное хранилище.

## Архивация копий

В редакторе задания доступен флажок «Архивировать копии в ZIP». Он сохраняется для каждого задания; по умолчанию выключен, в том числе для старых файлов настроек.

В ядре реализован `BackupArchiver.PrepareAsync(job, completedBackupPath)`: для файлового хранилища при включённой архивации готовый файл копии (`.dt`, `.bak`, `.dump` и т. п.) упаковывается в ZIP в каталоге копий. Например, `database.bak` становится `database.bak.zip`; имя файла внутри архива сохраняется. Можно также вызвать `CreateZipAsync` с явным путём архива и уведомлениями о числе обработанных байтов. Для доставки на FTP используется `BackupDelivery`: ZIP создаётся в локальном рабочем каталоге, затем отправляется и удаляется только локальный промежуточный архив. Исходная копия остаётся.

Упаковка выполняется потоково, затем содержимое полностью читается из ZIP и сравнивается с исходными данными по SHA-256. Только после проверки временный файл получает окончательное имя. Исходная копия сохраняется; существующие архивы не перезаписываются. При ошибке или отмене временный архив удаляется. Архивация применяется к завершённой, неизменяемой копии, а не к работающей базе, и не заменяет проверку восстановления базы данных. В ZIP нет шифрования или пароля; уже сжатые копии могут почти не уменьшиться.

Архивация подключена к ручной выгрузке файловой 1С; способ архивации самого `1Cv8.1CD` всегда создаёт ZIP и не упаковывает его повторно. Модуль и последовательность выполнения проверены на тестовых файлах и подменённом процессе платформы; реальную выгрузку и восстановление предстоит проверить на Windows.

## Разработка

Требуется .NET SDK 10.0.401 (версия закреплена в `global.json`). Для запуска интерфейса требуется Windows с .NET Desktop Runtime 10.

Из корня репозитория:

```sh
dotnet restore OneCBackup.slnx
dotnet build OneCBackup.slnx --no-restore
dotnet test tests/OneCBackup.Core.Tests --no-restore
```

Запуск на Windows:

```sh
dotnet run --project src/OneCBackup.Desktop
```

На Linux можно собрать Windows-приложение, выполнить тесты ядра и проверить консольный агент на тестовом файле 1CD; запуск WPF и Windows Credential Manager недоступен.

`python tests/agent_smoke.py` запускает настоящий консольный процесс, проверяет расписание и содержимое ZIP, отказ второго исполнителя и корректную остановку. Ожидание ближайшей минуты занимает до 75 секунд. Windows-интеграционные тесты диспетчера учётных данных явно пропускаются на Linux и выполняются в Windows CI.

FTP-интеграционные тесты в обычном запуске пропускаются явно. Для проверки против временного локального сервера (Python 3.9+):

```sh
python -m pip install -r tests/ftp/requirements.txt
dotnet build OneCBackup.slnx
python tests/ftp/run_integration.py
```

Скрипт запускает сервер только на `127.0.0.1` с тестовыми учётными данными, выполняет FTP-тесты, возвращает код их завершения и удаляет временные файлы сервера. Проверяются передача файла и ZIP, сохранение существующей копии, отказ при неверном пароле, обнаружение повреждения, очистка зарегистрированных старых копий, отказ от удаления изменённой копии и отсутствие перехода на обычный FTP, когда требуется FTPS. Успешная передача по FTPS и доступ к реальной Windows-сетевой папке требуют отдельной проверки в целевой среде.

## Структура

- `src/OneCBackup.Core` — режимы агента, клиент API, кэш, диспетчер расписания, ZIP, хранилища, журнал копий и очистка.
- `src/OneCBackup.Desktop` — приложение Windows с разделами заданий, истории и настроек агента.
- `src/OneCBackup.Agent` — отдельный автономный исполнитель без WPF, расписание и автоматический мониторинг SQL.
- `tests/OneCBackup.Core.Tests` — тесты настроек, архивации, хранилищ и обработки ошибок.
- `tests/ftp` — временный FTP-сервер и запуск интеграционных проверок.
- [План реализации](docs/product-plan.md) — требования, архитектура, способы копирования и интеграционные проверки.
- [Контракт агентского API](docs/agent-api.md) — самостоятельная работа и управление через сервер.
- [Мониторинг и управление](docs/server-management.md) — панель сервера, удалённые настройки и подтверждение их принятия агентами.
